## 1. 为什么需要二项堆

**诉求**：希望**连续插入**有常数摊还时间，同时保持**合并**的对数时间。

回顾已知方案：

| 结构 | 建堆 | 连续 Insert |
|---|---|---|
| 二叉堆 | 一次读入全部元素可在 $O(n)$ 内建堆（Floyd） | **依次调用 Insert 没有 $O(n)$ 保证** |
| 左式堆 / 斜堆 | 可线性建堆（先建完全二叉最小堆，再改指针；完全二叉树满足左偏性质，补算 NPL 也只需线性时间） | 同上，逐个 Insert 是 $O(n\log n)$ |

> [!important] 本讲的目标
> 在元素**逐个到来**时，保证从空堆开始的 $n$ 次 `Insert` 总共只需 $O(n)$ 时间（即**摊还 $O(1)$**），同时保持**合并**为对数时间。

## 2. 二项树与二项堆的定义

### 2.1 二项堆的两条性质

> [!important] 定义（二项堆）
> **1. 结构性质**
> - (a) 二项堆由多棵树构成一个**森林**，每棵树称为**二项树**；
> - (b) 每棵二项树的**高度互不相同**——每个高度至多对应一棵二项树；
> - (c) 高度为 0 的二项树是单结点树；高度为 $k$ 的二项树 $B_k$ 由**把一棵 $B_{k-1}$ 附接到另一棵 $B_{k-1}$ 的根上**构成。
>
> **2. 序性质**：每棵二项树都保持堆序（本节默认最小堆），即根最小、孩子的键不小于父亲的键。

```text
B0        B1        B2              B3
 O        O         O               O
          |        / \            / | \
          O       O   O          O  O  O
                   |            / \    |
                   O           O   O   O
                              ...
每次把两棵同阶树的根相连：结点数加倍，高度加 1。
```

### 2.2 定理：二项树的结点数

> [!important] 定理（二项树的结点数）
> 对任意整数 $k \ge 0$，二项树 $B_k$ 恰好有 $2^k$ 个结点，其中**深度为 $d$ 的结点恰好有 $\binom{k}{d}$ 个**（$0 \le d \le k$）。

**证明**（数学归纳法）：

- 基础：$B_0$ 只有一个根结点，结论成立。
- 归纳：$B_{k+1}$ 由两棵 $B_k$ 连接而成，结点总数为 $2 \cdot 2^k = 2^{k+1}$。连接后，一棵树中各结点的深度**保持不变**，另一棵树中各结点的深度**增加 1**，因此对 $1 \le d \le k$，深度为 $d$ 的结点数为
  $$\binom{k}{d} + \binom{k}{d-1} = \binom{k+1}{d}$$
- 深度为 $0$ 和 $k+1$ 的结点都只有一个，分别等于 $\binom{k+1}{0}$ 与 $\binom{k+1}{k+1}$。∎

> [!tip] 名字的由来
> 各深度的结点数**恰好是二项系数**，这就是「二项树」名字的来源。

**更直观的观察**：$B_k$ 实际上就是「一个根 + 子树 $B_0, B_1, \dots, B_{k-1}$」，且子树**按高度从左到右递增**。

### 2.3 与二进制表示的一一对应

> [!important] 核心对应关系
> 由于每种高度至多出现一次，**含有 $n$ 个结点的二项堆恰好对应 $n$ 的二进制表示**：第 $k$ 位为 1 **当且仅当**堆中含有 $B_k$。
>
> 例：$13 = (1101)_2 = 8+4+1$ ⟹ 堆中有 $B_3, B_2, B_0$，没有 $B_1$。
>
> 推论：**非空堆至多有 $\lfloor \log_2 n \rfloor + 1$ 棵树**。

## 3. 二项堆的操作与分析

### 3.1 FindMin

直接遍历全部 $O(\log n)$ 棵树的**根结点**即可（因为每棵树都满足堆序，全局最小必是某个根）。

- 时间 $O(\log n)$；
- 也可以**专门记录最小根结点**实现 $O(1)$，代价是每次可能改变最小元素的操作后都要维护这个指针。

### 3.2 Merge：二进制加法

> [!important] 核心直觉
> 既然每个二项堆和唯一的二进制数对应，**合并的结果不就正好是二进制加法的结果吗？**
>
> 从**最低阶**的二项树开始（对应最低位）逐位做加法：
> - **无需进位**（$1+0$ 或 $0+1$）⟹ 直接留下作为新堆的一部分；
> - **需要进位**（$1+1$）⟹ 把两棵 $B_i$ 链接成一棵 $B_{i+1}$，与下一位继续做加法；
> - 循环直到最高位完成。

前提：堆按**高度从小到大**存储，因此「逐位处理」可以直接顺序扫描。**时间复杂度显然是 $O(\log n)$**（就是二进制逐位操作）。

### 3.3 Insert

`Insert` 就是**与一棵 $B_0$ 合并**，因此最坏时间 $O(\log n)$。

> [!important] 但从空堆连续插入 $n$ 个元素的总时间是 $O(n)$
> 这与**二进制计数器加一**的问题完全对应：
> - 第 $i$ 位为 1 ⟺ 堆中有一棵 $B_i$；
> - 插入时若**已有同阶树**，就把两棵链接成高一阶的树——对应当前位从 1 变 0 并**向高位进位**；
> - 遇到空位后放入进位树——对应这一位从 0 变 1，**本次插入结束**（插入只加一个结点，所以只要某一位加法无需进位就可以马上停止）。
>
> 每次链接或放入树都只需**常数时间**；由二进制计数器的结论，从 0 开始连续加一 $n$ 次，**总翻转位数不超过 $2n$**，故加上新建结点的常数开销，**连续插入的总时间仍是 $O(n)$**。
>
> **⟹ 每次 Insert 的摊还时间为 $O(1)$。**

### 3.4 DeleteMin

1. 扫描各棵树的根找到最小值，设它是 $B_k$ 的根；
2. 删除它后得到两个二项堆：
   - **原堆移去整棵 $B_k$** 后剩下的森林；
   - **被删根的孩子** $B_0, \dots, B_{k-1}$（它们的高度互不相同，正好构成一个合法二项堆）；
3. 把这两个堆**合并**即可。

总时间仍是 $O(\log n)$。

> [!note] 示例：合并 $6 = (110)_2$ 与 $7 = (111)_2$
> - 第 0 位：留下 13（无需进位）；
> - 第 1 位：把根为 16、14 的两棵树链接，产生一个 $B_2$；
> - 第 2 位：有三棵树，留下刚才的进位树，再把其它两棵输入树链接成 $B_3$。
>
> 结果与 $13 = (1101)_2$ 一致。

### 3.5 DecreaseKey 与 Delete

- **DecreaseKey**：在二项堆中再简单不过——每棵树都是二项树，所以完全类比普通二叉堆：违反序性质时把该记录与父结点的记录**不断交换**（percolate up）直到恢复序性质。时间 $O(\log n)$。
- **Delete（任意结点）**：给目标记录加一个**优先于所有普通键的删除标记**，按 `DecreaseKey` 的方式上滤到根，再调用 `DeleteMin`。时间 $O(\log n)$。

## 4. 二项堆的代码实现

### 4.1 存储结构：左孩子 + 右兄弟

> [!warning] 实现上的关键问题：孩子数量不定
> 二项树的结点可能有**多于 2 个**孩子，因此不能用二叉树的两个指针。改用 **`LeftChild` + `NextSibling`** 的组合。

**副作用（注意）**：这种表示让二项树「**翻转**」了——原先是根的子树**从左到右高度依次增大**，现在变成**依次减小**。

```text
原始二项堆                根数组 + 孩子兄弟表示
      13                   R[3] ──→ 12 ──┬─→ 23 ──→ 24 ──→ 21 ...（降阶排列）
        \                  R[2]         │
         12                R[1] ∅       └─→（NextSibling 串起同层兄弟）
        / | \              R[0] ∅
      23 24 21
```

- **根数组**：用数组存储每棵二项树的根，**数组下标对应二项树的高度**；
- **每条虚线**表示 `NextSibling`，**实线箭头**表示根数组指针或 `LeftChild`。

### 4.2 CombineTrees：合并两棵同阶树

结合堆序性质与 `LeftChild`/`NextSibling` 表示，只需：

> [!important] 算法
> 用**根结点小的**那棵作新根；**根结点大的整棵树**作为 `LeftChild`；再把它原来的 `LeftChild` 挂到自己的 `NextSibling` 上。

```text
CombineTrees(T1, T2):
1:  if T1.Element > T2.Element then return CombineTrees(T2, T1)
2:  T2.NextSibling ← T1.LeftChild
3:  T1.LeftChild ← T2
4:  return T1                       ▷ 键相等时保留 T1 为根
```

### 4.3 Merge：8 种情况

有了 `CombineTrees`，就可以**按二进制加法逐阶合并**两个堆。

```text
Merge(H1, H2):
1:  if H1.CurrentSize + H2.CurrentSize > Capacity then 报告容量不足，两个堆不变
2:  H1.CurrentSize ← H1.CurrentSize + H2.CurrentSize
3:  Carry ← null;  i ← 0;  j ← 1
4:  while j ≤ H1.CurrentSize do
5:      T1 ← H1.TheTrees[i];  T2 ← H2.TheTrees[i]
6:      switch 4*!!Carry + 2*!!T2 + !!T1
7:          case 0, 1: break
8:          case 2: H1.TheTrees[i] ← T2;  H2.TheTrees[i] ← null;  break
9:          case 4: H1.TheTrees[i] ← Carry;  Carry ← null;  break
10:         case 3: Carry ← CombineTrees(T1, T2)
11:                 H1.TheTrees[i] ← null;  H2.TheTrees[i] ← null;  break
12:         case 5: Carry ← CombineTrees(T1, Carry);  H1.TheTrees[i] ← null;  break
13:         case 6: Carry ← CombineTrees(T2, Carry);  H2.TheTrees[i] ← null;  break
14:         case 7: H1.TheTrees[i] ← Carry
15:                 Carry ← CombineTrees(T1, T2);  H2.TheTrees[i] ← null;  break
16:     i ← i + 1;  j ← 2j
17: H2.CurrentSize ← 0;  return H1
```

> [!important] 三位编码的技巧
> 第 $i$ 轮最多处理**三棵树**：$H_1$ 中的 $T_1$、$H_2$ 中的 $T_2$、以及进位树 `Carry`，它们都是 $B_i$。每棵树各有「存在 / 不存在」两种状态 ⟹ 共 $2^3 = 8$ 种组合。
>
> 用 C 语言的双重取非 `!!` 把指针转成 0/1，于是
> $$4 \cdot \texttt{!!Carry} + 2 \cdot \texttt{!!T2} + \texttt{!!T1}$$
> 就把它编码为一个三位二进制数，**从高位到低位依次对应 `Carry`, `T2`, `T1`**。

**8 种情况一览**（整体思路：有零棵或一棵树时无需合并；有两棵就合为一棵 $B_{i+1}$ 向下一阶进位；有三棵就在当前阶留一棵，其余两棵合并后进位）：

| 编码 | Carry, T2, T1 | 处理 |
|:--:|:--:|---|
| 0 | 000 | 三棵树都不存在，当前阶保持为空 |
| 1 | 001 | 只有 $T_1$，已在 $H_1$ 中，**无需修改** |
| 2 | 010 | 只有 $T_2$，移入 `H1.TheTrees[i]`，清空 $H_2$ 对应位置 |
| 3 | 011 | 把 $T_1, T_2$ 合并为**进位树**，清空两堆当前阶 |
| 4 | 100 | 只有 `Carry`，放入 `H1.TheTrees[i]`，清空 `Carry` |
| 5 | 101 | $T_1$ 与 `Carry` 合并为新的进位树，清空 $H_1$ 当前阶 |
| 6 | 110 | $T_2$ 与 `Carry` 合并为新的进位树，清空 $H_2$ 当前阶 |
| 7 | 111 | 原 `Carry` **留在** $H_1$ 当前阶，再把 $T_1, T_2$ 合并为新的进位树，清空 $H_2$ 当前阶 |

## 5. 堆加速 Dijkstra 算法

### 5.1 回顾 Dijkstra

**问题**：边权**非负**的单源最短路径。设图 $G = (V,E)$、源点 $s$，求 $s$ 到各顶点的最短距离（有向图描述；无向图把每条边看成两条反向等权边）。

**算法**：把顶点分成两类——集合 $X$ 中已**确定**最短距离，其余待处理。对每个顶点 $v$ 用 $d[v]$ 记录**暂定距离**（后面可能还会变小），无路径时为 $+\infty$。初始 $d[s] = 0$、其余 $+\infty$、$X = \varnothing$。

每轮：

1. 从 $V \setminus X$ 中选出暂定距离**最小**的顶点 $u$，把 $d[u]$ **确定**为它的最短距离，并将 $u$ 加入 $X$；
2. 检查 $u$ 到各未确定顶点的出边：若 $d[u] + w(u,v) < d[v]$，则更新 $d[v] \leftarrow d[u]+w(u,v)$，并记 $pred[v] = u$——这个尝试改进距离的过程称为**松弛(relaxation)**。

若剩余顶点中最小的暂定距离已是 $+\infty$，则它们都无法从源点到达，算法结束。

> [!note] 示例（讲义图 5.4）
> 从 $s$ 出发得 $d[a] = 10,\ d[b] = 3$，故下一轮选 $b$。经 $b$ 的出边把 $a,c,t$ 的暂定距离更新为 $4,5,12$ ⟹ 下一个确定 $a$。处理 $a$ 时经它到 $c$ 的长度为 6 不能改进已有的 5，但到 $t$ 的长度 11 可以把 12 改小。接着确定 $c$，又把 $d[t]$ 降为 7。最终最短路径为 $s \to b \to c \to t$。

> [!important] 正确性证明
> 证明每轮选出的 $u$ 都满足 $d[u] = \delta(s,u)$（$\delta$ 为真正的最短距离）。
>
> 第一轮选出源点 $s$，结论成立。**归纳假设**：已加入 $X$ 的顶点都满足结论。考虑接下来选出的可达顶点 $u$，取一条 $s$ 到 $u$ 的最短路径，设 $y$ 是这条路径上**第一个不在 $X$ 中**的顶点，$x$ 是它在路径上的**前驱**。
>
> - $x \in X$，故处理 $x$ 时已用**正确**距离 $d[x] = \delta(s,x)$ 松弛过边 $(x,y)$，因而得到 $d[y] = \delta(s,y)$。这里用到**最短路径的前缀仍是最短路径**：若存在更短的前缀，替换后就会得到一条更短的 $s$ 到 $u$ 的路径，与选择矛盾。
> - 因为**边权非负**，从 $y$ 继续走到 $u$ 不会使路径长度减小，所以 $\delta(s,y) \le \delta(s,u)$。
> - 另一方面，算法选出的 $u$ 在所有未确定顶点中暂定距离最小，故 $d[u] \le d[y]$；而暂定距离不小于真正最短距离，即 $\delta(s,u) \le d[u]$。
>
> 串起来：$\delta(s,u) \le d[u] \le d[y] = \delta(s,y) \le \delta(s,u)$，两端相等 ⟹ 中间各项也都相等，特别是 $d[u] = \delta(s,u)$，归纳完成。
>
> 若尚有可达顶点未确定，沿它的一条最短路径同样能找到第一个不在 $X$ 中的顶点 $y$，其前驱已被处理，故 $d[y]$ 必为有限值。因此当所有剩余暂定距离都是 $+\infty$ 时，剩下的顶点确实都不可达。∎

### 5.2 用堆实现未确定顶点集合

> [!important] 堆加速的是**哪一步**
> 每一轮都要从 $V \setminus X$ 中**找暂定距离最小的顶点**，而松弛又会**降低**其中一些顶点的暂定距离。因此：
> - 把所有未确定顶点存入**最小堆**，以 $d[v]$ 为键；
> - 用 **`DeleteMin`** 选出下一轮的顶点；
> - 用 **`DecreaseKey`** 完成距离更新。

```text
Dijkstra(G, s):
1:  对每个 v：d[v] ← +∞;  pred[v] ← null;  done[v] ← false
2:  d[s] ← 0;  建堆 H，每个顶点一条记录 (v, d[v])
3:  while H 非空 do
4:      u ← DeleteMin(H).id
5:      if d[u] = +∞ then break
6:      done[u] ← true
7:      for 每条出边 (u, v) do
8:          if ¬done[v] 且 d[u] + w(u,v) < d[v] then
9:              d[v] ← d[u] + w(u,v);  pred[v] ← u
10:             DecreaseKey(H, v, d[v])
11: return (d, pred)
```

（`done[v]` 表示 $v$ 是否已加入 $X$。）

### 5.3 时间分析

设 $n = |V|$、$m = |E|$。每个顶点**最多取出一次**，每条边**最多检查一次**，每次检查**至多引起一次降键**。记建堆、一次 `DecreaseKey`、一次 `DeleteMin` 的时间分别为 $T_{\text{build}}(n)$、$T_{dk}$、$T_{em}$，则总时间

$$O(n + m) + T_{\text{build}}(n) + O\big(m\,T_{dk} + n\,T_{em}\big)$$

这个式子直接说明了不同数据结构对算法的影响：

| 数据结构 | $T_{dk}$ / $T_{em}$ | 总时间 | 说明 |
|---|---|---|---|
| **数组**存暂定距离 | 更新 $O(1)$，但每轮**扫描** $O(n)$ 找最小 | $O(m + n^2) = O(n^2)$ | 每轮都线性扫全部未确定顶点 |
| **堆**（二叉堆/二项堆等） | 均 $O(\log n)$ | $O((m+n)\log n)$ | 当 $n \ge 2$ 且所有顶点可达时必有 $m \ge n-1$，也可写成 $O(m\log n)$ |
| **斐波那契堆** | $T_{dk}$ 摊还 $O(1)$、$T_{em}$ 摊还 $O(\log n)$ | $O(m + n\log n)$ | 见第 6 节 |

> [!important] 什么时候堆更优
> 对**稀疏图**，具体地当 $m = o(n^2/\log n)$ 时，堆实现的时间界 $o(n^2)$ 优于数组版本的二次上界。现实中的**路网、通信网**等边数通常**远小于顶点数的平方**，因此堆实现的 Dijkstra 在这些场景下更有优势。

> [!tip] 没有 DecreaseKey 怎么办？
> 有些堆只提供 `Insert` 和 `DeleteMin`。这时可以在每次距离变小时**插入一条新记录**，暂时保留旧记录：例如 $d[v]$ 从 12 降为 7 时，向堆中加入 $(7,v)$，原来的 $(12,v)$ 留到以后**取出时再丢弃**（惰性删除）。这是很多实际实现的做法。

## 6. 斐波那契堆

### 6.1 动机

在 Dijkstra 中，`DecreaseKey` 最多执行 $m$ 次、`DeleteMin` 最多执行 $n$ 次。若能把：

- **`DecreaseKey` 的摊还时间降为 $O(1)$**，同时
- **`DeleteMin` 保持对数摊还时间**，

总时间就能从 $O(m\log n)$ 降到

$$\boxed{\ O(m + n\log n)\ }$$

**斐波那契堆正是为此设计的**。

### 6.2 基本结构

斐波那契堆同样是由若干棵满足**最小堆序**的树组成的森林，但相比二项堆**放宽了树形要求**：

- 各棵树**不必是二项树**；
- **允许多个根具有相同的度数**（度数 = 结点的孩子数）。

**链表结构**：

- 所有根用一条**循环双向链表**连接，称为**根链表**；
- 同一个结点的所有孩子也用一条**循环双向链表**连接，称为它的**孩子链表**；
- 链表中的结点**不需要按键值或度数排序**。

堆本身保存：根链表 `H.roots`、最小根指针 `H.min`、结点总数 `H.n`。

**每个结点保存的字段**：

| 字段 | 含义 |
|---|---|
| `key` | 键（比较大小的值）；取出最小值时要返回**整条记录**，才能知道接下来处理哪个顶点 |
| `parent` | 指向父结点 |
| `child` | 指向**任意一个**孩子，没有孩子时为 `null` |
| `degree` | 孩子数 |
| `left`, `right` | 同一条链表中的前驱和后继；**链表只有一个结点时都指向自身** |
| `mark` | 布尔标记：该非根结点**自最近一次成为孩子以来，是否已经失去过一个孩子** |

> [!important] mark 规则（斐波那契堆的灵魂）
> - 结点刚被接到另一个结点下面时，`mark = false`；
> - 它**第一次**失去孩子时，`mark = true`；
> - 它**第二次**失去孩子时，就把它**连同剩余子树一起从父亲处切下，放入根链表**。
>
> 于是：**任何一个仍是非根的结点，自最近一次成为孩子以来至多失去过一个孩子**。约定**根的 `mark` 始终为 `false`**。
>
> 后面将证明，正是这条规则保证了**度数为 $k$ 的结点拥有随 $k$ 指数增长的子树**。

```text
        3 ← H.min
       /|\
      6 8 9
     /  |
    11  20    14*
                \
                 ...
                 
星号 * 表示带标记的结点；虚线示意根链表（省略回环与孩子之间的链表指针）。
```

### 6.3 插入、查找最小值与合并：都是 $O(1)$

**插入**：新建一个没有孩子的根，加入根链表，更新最小根即可。

> [!note] 与二项堆的关键差别
> 二项堆在插入时**需要处理同阶树之间的进位**；斐波那契堆**允许根的度数重复，因而暂时不做合并**。

```text
FibonacciInsert(H, r):
1:  新建结点 x，保存记录 r，x.key ← r.key
2:  x.parent ← null;  x.child ← null;  x.degree ← 0;  x.mark ← false;  将 x 加入 H.roots
3:  if H.min = null 或 x.key < H.min.key then H.min ← x
4:  H.n ← H.n + 1;  return x
```

**FindMin**：直接访问 `H.min`。

**Merge**：拼接根链表，在两个原最小根中选出新的最小根。

```text
FibonacciMerge(H1, H2):
1:  建立空堆 H，将 H1.roots, H2.roots 拼接为 H.roots
2:  H.n ← H1.n + H2.n;  H.min ← H1.min
3:  if H.min = null then H.min ← H2.min
4:  else if H2.min ≠ null 且 H2.min.key < H.min.key then H.min ← H2.min
5:  H1.roots, H1.min, H2.roots, H2.min ← null;  H1.n, H2.n ← 0
6:  return H
```

> [!important] 三个操作都是 $O(1)$，代价是什么
> 这三个操作都只做**常数次比较和链表操作**，实际时间均为 $O(1)$。代价是**根链表可能越来越长**——例如连续插入 $n$ 个元素后，就有 $n$ 棵互不连接的单结点树。这个「债」要在 `DeleteMin` 时一次性偿还（`Consolidate`）。

### 6.4 DeleteMin：合并度数相同的根

**过程**：删除最小根 $z$ 后，它原来的**每个孩子都成为一棵树的根**。把这些孩子加入根链表，重新寻找最小值；**在这次遍历中合并度数相同的根**，让后续操作面对较少的树。

```text
FibonacciDeleteMin(H):
1:  if H.min = null then return "无元素"
2:  z ← H.min;  保存 z 中的记录 r;  从 H.roots 摘下 z;  H.min ← null
3:  while z.child ≠ null do
4:      从 z 的孩子链表摘下一个结点 x;  z.degree ← z.degree - 1
5:      x.parent ← null;  x.mark ← false;  将 x 加入 H.roots
6:  释放结点 z;  H.n ← H.n - 1            ▷ z 的指针失效
7:  Consolidate(H);  return r
```

**`Consolidate`**：用数组 $A$，$A[d]$ 保存一个**已经处理过、度数为 $d$ 的根**。处理当前根 $x$ 时若 $A[d]$ 已被占用，就把**两个根中键较大的接到较小的下面**；新根的度数加 1，继续检查下一个位置直到找到空位。

> [!note] 与二项堆合并的异同
> 这与二项堆合并时的**进位**相同。但这里**必须先遍历无序的根链表**，才能发现哪些度数发生了重复。
>
> **实现细节**：数组 $A$ 的大小无法预先确定，用**动态数组**实现——访问下标超出容量时把容量**不断加倍**。

```text
Consolidate(H):
1:  A ← 容量为 1、初值为 null 的数组;  C ← 1;  D ← -1        ▷ C 为当前容量
2:  while H.roots ≠ null do
3:      从 H.roots 摘下一个根 x;  d ← x.degree
4:      while d ≥ C do 将 A 扩容至 2C（保留原有元素，新增位置置 null）; C ← 2C
5:      while A[d] ≠ null do
6:          y ← A[d];  A[d] ← null
7:          if x.key > y.key then 交换变量 x, y
8:          y.parent ← x;  y.mark ← false;  将 y 加入 x 的孩子链表
9:          x.degree ← x.degree + 1;  d ← x.degree
10:         while d ≥ C do 将 A 扩容至 2C; C ← 2C
11:     A[d] ← x;  D ← max(D, d)
12: H.min ← null
13: for d = 0, 1, …, D do                                ▷ D = -1 时不执行循环
14:     if A[d] ≠ null then
15:         将 A[d] 加入 H.roots;  其 parent ← null、mark ← false
16:         if H.min = null 或 A[d].key < H.min.key then H.min ← A[d]
```

**一次 `DeleteMin` 的实际时间**：设删除前共有 $t$ 棵树、最小根 $z$ 有 $d$ 个孩子。

- 把 $d$ 个孩子逐个移入根链表：$O(d)$；
- 待整理的根共有 $t - 1 + d$ 个，每次合并只需常数时间且使**树的总数减少 1**，故合并次数不超过 $t-1+d$ ⟹ 处理时间 $O(t+d)$；
- 辅助数组 $A$ 的开销 $O(D)$。

$$\Longrightarrow \text{一次 DeleteMin 的实际时间为 } O(t + d + D)$$

> [!warning] 这里的 $t$ 可能很大
> 例如从空堆连续插入 $n$ 个元素后会有 $n$ 棵单结点树，紧接着的一次 `DeleteMin` 就需要处理其余 $n-1$ 个根，花费 $\Theta(n)$ 时间。**但摊还时间是 $O(\log n)$**（见第 7 节）。

### 6.5 DecreaseKey：切断与级联切断

把 $x$ 的键降低为 $k$ 后，$x$ 与**孩子**之间仍满足堆序，**唯一可能违反堆序的是 $x$ 与父结点之间的边**。

- 若 $x$ 已是根，或 $k$ 仍不小于父结点的键 ⟹ **无需改变树形**；
- 否则把 $x$ **连同整棵子树**从父亲处切下，加入根链表，从而去掉违反堆序的那条边。

切下 $x$ 后还要处理**父结点 $y$ 失去孩子**的情况：

1. 若 $y$ 是**根** ⟹ 结束；
2. 若 $y$ **还没有标记** ⟹ 给它加上标记（表示第一次失去孩子）；
3. 若 $y$ **已经有标记** ⟹ **把 $y$ 也切下**；此时 $y$ 的父亲又失去了一个孩子，**继续按同样规则处理**。

> [!important] 这一过程称为**级联切断(cascading cut)**
> 它保证了 6.2 节约定的「失去孩子次数上限」。

```text
Cut(H, x, y):                        ▷ x.parent = y，且 x 确实位于 y 的孩子链表中
1:  从 y 的孩子链表摘下 x;  y.degree ← y.degree - 1
2:  x.parent ← null;  x.mark ← false;  将 x 加入 H.roots
```

```text
FibonacciDecreaseKey(H, x, k):       ▷ k ≤ x.key
1:  x.key ← k;  同步更新记录中的键;  y ← x.parent
2:  if y ≠ null 且 x.key < y.key then
3:      Cut(H, x, y)
4:      while y.parent ≠ null do
5:          if y.mark = false then y.mark ← true;  break
6:          p ← y.parent;  Cut(H, y, p);  y ← p
7:  if x.key < H.min.key then H.min ← x
```

> [!note] 示例（讲义图 5.7）
> 20 和 30 都带有标记。把 40 的键降为 5 后，先将它从 30 处切下；30 **第二次**失去孩子，需要从 20 处切下；接着 20 也第二次失去孩子，需要从 10 处切下。10 是**根**，过程结束。最终得到四个根，标记均被清除。

**时间**：若共切断 $c$ 个结点，则时间为 $O(c+1)$。

> [!tip] 单次降键可能引起很长的级联切断，但……
> 除**第一次**切断外，**每次切断都会清除一个已有标记**。因此直观上摊还分析可以**利用标记数的下降来抵消**这部分成本——这正是势函数取 $\Phi = t + 2m$ 的原因。

### 6.6 删除指定结点

```text
FibonacciDelete(H, x):
1:  保存 x 的原记录副本 r
2:  FibonacciDecreaseKey(H, x, -∞)
3:  FibonacciDeleteMin(H);  return r
```

先把键降到小于所有普通键的 $-∞$，再执行 `DeleteMin`。其摊还成本是这两步摊还成本之和。

### 6.7 度数上界

`DeleteMin` 需要移出最小根的所有孩子、并按度数整理各根，因此**必须控制一个结点最多能有多少孩子**。

> [!important] 定理（斐波那契堆的度数上界）
> 设斐波那契数列满足 $F_0 = 0$、$F_1 = 1$、$F_j = F_{j-1} + F_{j-2}$（$j \ge 2$）。在从空堆按上述操作构造的斐波那契堆中，**度数为 $k$ 的结点，其子树至少有 $F_{k+2}$ 个结点**。
>
> 因此，含 $n \ge 1$ 个结点的堆中，**每个结点的度数至多为 $\lfloor \log_\varphi n \rfloor$**，其中 $\varphi = \dfrac{1+\sqrt 5}{2}$。

**证明**：

1. 设 $x$ 目前有 $k$ 个孩子，按它们**成为 $x$ 的孩子的先后顺序**记为 $y_1,\dots,y_k$。
2. 当 $y_i$ 被接到 $x$ 下方时，$y_1,\dots,y_{i-1}$ **都已经是** $x$ 的孩子，所以**当时 $x$ 的度数至少为 $i-1$**。
3. 由于**只有同度数的根才会合并**，当时 $y_i$ 的度数也**至少为 $i-1$**。
4. 此后 $y_i$ **至多失去一个孩子**（否则它就会被切走）。因此现在各孩子的度数满足
   $$\deg(y_1) \ge 0,\qquad \deg(y_i) \ge i-2 \quad (i \ge 2)$$
5. 令 $\text{size}(x)$ 为以 $x$ 为根的子树结点数（含 $x$），对 $\text{size}(x)$ 作**强归纳**证明度数为 $k$ 时 $\text{size}(x) \ge F_{k+2}$：
   - $k = 0$：子树只有 $x$ 自己，恰好 $1 = F_2$ 个结点；
   - $k \ge 1$：每棵孩子子树都比原树小，可应用归纳假设——$y_1$ 至少有 1 个结点（$F_2 = 1$），而 $y_i$ 的度数至少为 $i-2$，故其子树至少有 $F_i$ 个结点。加上根本身：
   $$\text{size}(x) = 1 + \sum_{i=1}^{k}\text{size}(y_i) \;\ge\; 2 + \sum_{i=2}^{k}F_i \;=\; F_{k+2}$$
   最后一个等式来自 $\sum_{i=0}^{k}F_i = F_{k+2} - 1$（可归纳证明）。∎

## 7. 斐波那契堆的摊还分析

### 7.1 势函数的选取

前面已经找出**两种可能成本很高的操作**：

- `DeleteMin` 可能需要**整理很多根** ⟹ 但合并之后**根数会大幅减少**；
- `DecreaseKey` 可能**连续切断很多结点** ⟹ 但**除第一次外，被切下的结点都带有标记**，切断时这些标记会被清除。

因此自然地：

> [!important] 势函数
> 令 $t(H)$ 为**根数**、$m(H)$ 为**带标记结点的个数**，取
> $$\Phi(H) = t(H) + 2m(H)$$
> **用根数支付整理的费用，用标记数支付级联切断的费用。**

**为什么标记前的系数是 2**：切下一个**带标记**的结点时，**根数增加 1、标记数减少 1**，所以势能净减少 $1$；系数取 2 才能让这次切断**净赚**（$\Delta\Phi = +1 + 2(-1) = -1$）。

（下面的讨论会忽略一些常数项，但不影响最终的界。）

### 7.2 各操作的摊还代价

| 操作 | 实际成本 | $\Delta\Phi$ | 摊还成本 |
|---|---|---|---|
| **Insert** | $O(1)$ | $+1$（新增一个无标记的根） | $O(1) + 1 = O(1)$ |
| **FindMin** | $O(1)$ | $0$（不改变结构） | $O(1)$ |
| **Merge** | $O(1)$ | $0$（两个堆的根数、标记数分别相加，而原堆置空 ⟹ **总势能不变**） | $O(1)$ |

**DecreaseKey**：

- **发生切断的情况**：设一共切下 $c \ge 1$ 个结点。
  - **根数增加 $c$**；
  - 第一次切下的 $x$ 可能没有标记，但其后的 $c-1$ 个结点**在切断前一定带有标记**，切断后标记被清除；过程结束时**至多给一个**原先未标记的祖先加上标记。故
    $$\Delta m \le 1 - (c-1) = 2 - c$$
  - 于是 $\Delta\Phi \le c + 2(2-c) = 4 - c$；
  - $c$ 次切断及其循环判断、收尾工作的实际成本至多为 $c+1$，所以
    $$\hat a = a + \Delta\Phi \le (c+1) + (4-c) = 5 = O(1)$$
- **没有发生切断的情况**：只做常数次比较和赋值，根数与标记数均不变，同样只需 $O(1)$ 摊还时间。

**DeleteMin**：设开始前有 $n \ge 1$ 个结点、$t$ 个根，被删根有 $d$ 个孩子，取 $D = \lfloor \log_\varphi n \rfloor$。

- 由**定理 5.2**，被删根的度数和整理过程中各结点的度数都不超过 $D$；
- 实际成本 $a \le t + d + D$；
- 整理后**各根的度数互不相同**，只可能取 $0,1,\dots,D$，所以**新根数 $t' \le D+1$**；
- 这次操作**只会清除标记、不会增加标记**，故 $\Delta\Phi \le t' - t \le D + 1 - t$；
- 因此
  $$\hat a = a + \Delta\Phi \le (t + d + D) + (D + 1 - t) = d + 2D + 1 = O(\log n)$$

**Delete（任意结点）**：先执行一次 `DecreaseKey`（摊还 $O(1)$），再执行一次 `DeleteMin`（摊还 $O(\log n)$）⟹ 摊还时间也是 $O(\log n)$。

## 8. 各种堆的复杂度对比

令 $n$ 为堆中元素数（合并时取两个输入堆的元素**总数**），$L = \log n$。**带星号的为摊还上界**，其余为最坏情况上界。

| | 二叉堆 | 左式堆 | 斜堆 | 二项堆 | 斐波那契堆 |
|---|---|---|---|---|---|
| **Insert** | $O(L)$ | $O(L)$ | $O(L)^*$ | $O(1)^*$ | $\mathbf{O(1)}$ |
| **Merge** | $O(n)$ | $O(L)$ | $O(L)^*$ | $O(L)$ | $\mathbf{O(1)}$ |
| **DeleteMin** | $O(L)$ | $O(L)$ | $O(L)^*$ | $O(L)$ | $O(L)^*$ |
| **Delete** | $O(L)$ | $O(L)$ | $O(L)^*$ | $O(L)$ | $O(L)^*$ |
| **DecreaseKey** | $O(L)$ | $O(L)$ | $O(L)^*$ | $O(L)$ | $\mathbf{O(1)^*}$ |

> [!tip] 读表要点
> - **二叉堆的 Merge 是 $O(n)$** —— 这就是可合并堆存在的意义；
> - **二项堆**换来的是 `Insert` 摊还 $O(1)$；
> - **斐波那契堆**换来的是 `Merge` 最坏 $O(1)$ + `DecreaseKey` 摊还 $O(1)$，代价是 `DeleteMin` 只到摊还 $O(\log n)$、实现复杂、常数极大（所以实践中二叉堆反而常用）。

## 9. 习题与提示

> [!note] 习题 5.1（Combine 次数）
> 从空堆开始连续插入 $n$ 个元素，总共会执行多少次 `CombineTrees`？给出精确表达式。

**答案**：连续插入 $n$ 个元素共**新建 $n$ 棵单结点树**，而每执行一次 `CombineTrees`，**树的总数就减少 1**。设 $n$ 的二进制表示中有 $\text{popcount}(n)$ 个 1，最终就有这么多棵树，所以合并次数恰好为

$$\boxed{\ n - \text{popcount}(n)\ }$$

> [!note] 习题 5.2（奇偶深度）
> 约定根的深度为 0，记二项堆中深度为偶数、奇数的结点数分别为 $N_0, N_1$。证明 $N_0 - N_1$ 只能等于 0 或 1，并说明这个差值由元素总数的奇偶性如何决定。由此判断：当 $N_0 > N_1$ 时，元素总数是否可能为偶数？

**答案**：先看一棵 $B_k$。由定理 5.1，深度为 $d$ 的结点有 $\binom{k}{d}$ 个，所以当 $k \ge 1$ 时，偶数深度与奇数深度的结点数之差为

$$\sum_{d=0}^{k}(-1)^d\binom{k}{d} = (1-1)^k = 0$$

而 $B_0$ **只有一个深度为 0 的根**，差值为 1。将堆中各棵树的差值相加，结果**只取决于有没有 $B_0$**：

- 元素总数为**偶数** ⟹ 没有 $B_0$ ⟹ $N_0 = N_1$；
- 元素总数为**奇数** ⟹ 有一棵 $B_0$ ⟹ $N_0 = N_1 + 1$；
- 空堆两者都为 0，也满足结论。

**所以当 $N_0 > N_1$ 时，元素总数一定为奇数，不可能为偶数。**

> [!note] 习题 5.3（用合并实现连续插入的问题）
> 为什么直接用通用合并算法实现从空堆开始的连续插入，不能保证常数摊还时间？

**答案**：因为**通用合并算法每一次合并都要扫描所有的树**，并不像连续插入时那样**只扫描到第一次不需要进位就停止**。因此连续 $n$ 次插入的总时间为 $\Theta(n\log n)$。

> [!note] 习题 5.4 / 5.5
> 5.4（设计 2-3-4 堆）与 5.5（堆加速 Prim 算法）讲义留给读者，答案略。5.5 的要点：堆加速的是「从未确定顶点中选出键最小的顶点」这一步，键存**当前到生成树的最小边权**，更新方法是 `DecreaseKey`。

## 10. 考点速查

1. **二项堆的两条性质**：森林中各二项树**高度互不相同** + 每棵树保持堆序。
2. **$B_k$ 有 $2^k$ 个结点，深度 $d$ 的结点有 $\binom{k}{d}$ 个**（证明用帕斯卡恒等式）。
3. **$n$ 的二进制表示 ↔ 堆中的树**：第 $k$ 位为 1 ⟺ 有 $B_k$；非空堆至多 $\lfloor\log_2 n\rfloor + 1$ 棵树。
4. **Merge 就是二进制加法**，逐位进位，$O(\log n)$。
5. **Insert = 与 $B_0$ 合并**，最坏 $O(\log n)$；但**连续 $n$ 次共 $O(n)$（摊还 $O(1)$）**——与二进制计数器加一对应，总翻转位数 $\le 2n$。
6. **DeleteMin**：删最小根后，其余森林 + 该根的孩子森林，**合并**即可，$O(\log n)$。
7. **DecreaseKey** 就是二叉堆的**上滤**，$O(\log n)$；**Delete** = 降到 $-\infty$ + `DeleteMin`，$O(\log n)$。
8. **代码要点**：`LeftChild` + `NextSibling`（孩子可能多于 2 个），**根数组下标 = 高度**；这种表示让子树按**降阶**排列。
9. **Merge 的 8 种情况**用 `4*!!Carry + 2*!!T2 + !!T1` 编码；三位从高到低对应 `Carry, T2, T1`。
10. **Dijkstra 的堆加速**：`DeleteMin` 选顶点 + `DecreaseKey` 更新距离；总时间 $O(n+m) + T_{\text{build}} + O(mT_{dk} + nT_{em})$。
11. **数组 $O(n^2)$、堆 $O(m\log n)$、斐波那契堆 $O(m + n\log n)$**；稀疏图（$m = o(n^2/\log n)$）时堆更优。
12. **没有 DecreaseKey 时**：插入新记录 + 惰性丢弃旧记录。
13. **斐波那契堆的三条链表规则**：根链表、孩子链表都是**循环双向**链表，且**不排序**；允许多个根度数相同。
14. **mark 规则**：成为孩子时 false；第一次失子 true；**第二次失子就级联切断**。
15. **Consolidate**：数组 $A[d]$ 记度数为 $d$ 的根，**度数相同就合并（键大的接到键小的下面）**，动态扩容。
16. **度数上界**：度数 $k$ 的结点子树 $\ge F_{k+2}$ 个结点 ⟹ 度数 $\le \lfloor\log_\varphi n\rfloor$（$\varphi$ 为黄金比）。
17. **摊还分析**：$\Phi = t + 2m$；`Insert`/`Merge`/`FindMin` $O(1)$，`DecreaseKey` 摊还 $O(1)$（$\hat a \le 5$），`DeleteMin` 摊还 $O(\log n)$。
18. **$\Delta\Phi \le 4 - c$ 的推导**是关键：$c$ 次切断中后 $c-1$ 次清除标记（$-2(c-1)$）、根数 $+c$、至多新增一个标记（$+2$）。
