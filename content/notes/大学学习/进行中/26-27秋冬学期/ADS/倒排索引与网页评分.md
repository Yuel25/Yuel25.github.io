## 1. 从逐篇查找到倒排索引

**问题**：给定一批文档，如何高效返回**包含指定词项**的文档集合？

以四篇短文为例，查找同时包含 `silver` 和 `truck` 的文档：

| 文档 | 内容 |
|---|---|
| D1 | gold silver truck |
| D2 | shipment of gold damaged in a fire |
| D3 | delivery of silver arrived in a silver truck |
| D4 | shipment of gold arrived in a truck |

**方案一：逐篇扫描**。检查每篇是否含这两个词 ⟹ 得到 D1、D3。但真实搜索引擎的文档数是千亿级别，且查询量巨大，**逐篇扫描不可行**。

**方案二：词项–文档矩阵**。若词项出现在某文档中就标 1，否则标 0：

| 词项 | D1 | D2 | D3 | D4 |
|---|:--:|:--:|:--:|:--:|
| gold | 1 | 1 | 0 | 1 |
| silver | 1 | 0 | 1 | 0 |
| truck | 1 | 0 | 1 | 1 |
| damaged | 0 | 1 | 0 | 0 |

查询时取出 `silver` 与 `truck` 两行做**逻辑与**，得 `[1,0,1,0]` ⟹ D1、D3。

> [!warning] 矩阵不可行的原因：稀疏
> 设 $V$ 个不同词项、$N$ 篇文档，矩阵共 $VN$ 个位置。当 $V,N$ 都很大时**绝大多数位置是 0**，空间浪费极其严重。所以要换一种「只存 1 的位置」的表示。

### 1.1 定义：倒排索引

> [!important] 定义（倒排索引 inverted index）
> 倒排索引由**词典**与**倒排表**两部分组成。词典把词项 $t$ 映射到它的倒排表 $P(t)$；倒排表**按文档编号递增**保存含有 $t$ 的文档，必要时还保存**词频**与**位置**。

**「倒排」二字的含义**：把「文档 → 其中的词」的索引**反过来**，变成「词 → 含它的文档」的索引。

四篇短文的倒排索引（记法 $\langle \text{文档数};\ \text{文档编号列表}\rangle$）：

| # | 词项 Term | 倒排表 Times; Documents |
|:--:|---|---|
| 1 | a | $\langle 3;\ 2,3,4\rangle$ |
| 2 | arrived | $\langle 2;\ 3,4\rangle$ |
| 3 | damaged | $\langle 1;\ 2\rangle$ |
| 4 | delivery | $\langle 1;\ 3\rangle$ |
| 5 | fire | $\langle 1;\ 2\rangle$ |
| 6 | gold | $\langle 3;\ 1,2,4\rangle$ |
| 7 | of | $\langle 3;\ 2,3,4\rangle$ |
| 8 | in | $\langle 3;\ 2,3,4\rangle$ |
| 9 | shipment | $\langle 2;\ 2,4\rangle$ |
| 10 | silver | $\langle 2;\ 1,3\rangle$ |
| 11 | truck | $\langle 3;\ 1,3,4\rangle$ |

两个核心统计量：

- **文档频率(document frequency)** $\text{df}(t)$：含词项 $t$ 的**文档数**，即分号前的数。例：$\text{df}(\texttt{silver}) = 2$。
- **词频(term frequency)** $\text{tf}(t,d)$：词项 $t$ 在文档 $d$ 中出现的**次数**。例：$\text{tf}(\texttt{silver}, D3) = 2$。

## 2. 用倒排索引回答查询

- **AND 查询**（两个词都出现）⟹ 求两个倒排表的**交集**；
- **OR 查询**（至少一个出现）⟹ 求**并集**。

利用倒排表**按文档编号递增**这一性质，可以用**双指针**在线性时间内完成。

### 2.1 算法：有序倒排链表的交集与并集

```text
IntersectOrUnion(A, B, mode):            ▷ A, B 为编号严格递增的单链表首指针
1:  p ← A;  q ← B;  C ← 空表
2:  while p ≠ null and q ≠ null do
3:      if p.id = q.id then
4:          向 C 表尾追加 p.id;  p ← p.next;  q ← q.next
5:      else if p.id < q.id then
6:          if mode = OR then 向 C 表尾追加 p.id
7:          p ← p.next
8:      else
9:          if mode = OR then 向 C 表尾追加 q.id
10:         q ← q.next
11: while 剩下未走完的链表（仅 OR 模式）: 依次追加到 C
12: return C
```

> [!tip] 为什么可以「直接跳过」
> 链表中的编号**严格递增**。当 $p.id < q.id$ 时，$q$ 当前位置及其后面的所有编号都不小于 $q.id$，因此 $p.id$ **不可能再被匹配**，直接跳过即可。
>
> 例：$\langle 3;1,2,4\rangle$ 与 $\langle 2;3,4\rangle$ 求交——跳过 1、2，跳过对方的 3，最后在 4 上匹配。

### 2.2 用 df 决定求交顺序

> [!important] 先交短表
> 多词 AND 查询可以**按 df 从小到大**依次求交。理由：**求交得到的中间结果不会比参与交集的最短表更长**，先处理短表能更早缩小候选集合，减少后续比较量。

### 2.3 阈值截断

真实搜索中候选文档可能很多，用户不会逐篇阅读。搜索引擎通常按**评分**排序，并按设定的**阈值(threshold)** 只返回前若干篇。

## 3. 位置索引与短语查询

倒排表里再记录**词项在每篇文档中出现的位置**，就得到**位置倒排表**：

| # | 词项 | 位置倒排表（Times; Documents Words） |
|:--:|---|---|
| 6 | gold | $\langle 3;\ (1;1),(2;3),(4;3)\rangle$ |
| 10 | silver | $\langle 2;\ (1;2),(3;3,7)\rangle$ |
| 11 | truck | $\langle 3;\ (1;3),(3;8),(4;7)\rangle$ |

例：`silver` 的 $\langle 2;(1;2),(3;3,7)\rangle$ 表示它在两篇文档中出现——在 D1 的**第 2 个位置**、在 D3 的**第 3 和第 7 个位置**。

两个用途：

1. **返回上下文片段**：搜索引擎展示结果时需要截出包含查询词的语境；
2. **短语查询**：如 `"silver truck"`。只知道两个词都出现过，**无法判断它们是否相邻**，必须靠位置。

> [!important] 停用词与位置索引的关系（易错点）
> `a`、`of` 等停用词几乎出现在所有文档中：为它们建倒排表很占空间，但对查询的区分作用很小，因此可以**在建立索引时略去**。但：
> - 短语查询可能需要它们（`"to be or not to be"` 中每个词都参与匹配）；
> - **即使删掉停用词，也必须保留其余词在原文中的位置**。例如 `silver a truck` 中两者位置是 1 和 3；若删掉 `a` 后重新编号成 1、2，就会**错误地认为原文出现了短语 `silver truck`**。

## 4. 索引的构建与维护

### 4.1 文本处理

**分词(tokenization)**：英文可按空格、标点切分，再按规则处理连字符；中文没有空格分隔，需要借助词典或语言模型判断词界（分词算法本身不在本讲展开）。

其它需要决定的细节：

| 处理 | 做法 | 注意 |
|---|---|---|
| **大小写** | 统一转小写，使 `Truck` 与 `truck` 匹配同一批文档 | **查询时也必须做同样处理**，否则找不到 |
| **词干提取(stemming)** | 按词形规则去词缀，把 process / processing / processed 归到同一词干 | 可能把**含义不同的词**归到一起，返回不相关文档 |
| **词形还原(lemmatization)** | 结合词汇知识与语法信息找原形（says、said → say） | 更准确，但需要词典与词性信息 |
| **停用词(stop words)** | 略去 `a`、`of` 等高频低区分度词 | 见上节的警告：**不要重编位置编号** |

### 4.2 构建索引

**词典的数据结构**：每个词项作键，存指向其倒排表的指针。

| 方案 | 查找 | 备注 |
|---|---|---|
| 平衡搜索树 | $O(\log V)$ 次比较 | 词典巨大，实际常用 **B 树 / B+ 树**（见 [[B树与B+树]]） |
| 哈希表 | 期望 $O(1)$ | 装载率合适时很快，但**不支持高效的范围查询** |

**构建算法**（逐篇读入，边读边追加）：

```text
BuildIndex(文档流):
1:  D ← 空词典
2:  for 每篇文档 (d, text) do
3:      for 按原位置递增得到的词项与位置 (t, p) do
4:          if t 不在 D 中 then 在 D[t] 建立空倒排链表, 首尾指针置 null, df ← 0
5:          if D[t] 的链表为空 or 尾结点的文档编号 ≠ d then
6:              新建文档编号为 d、位置表为空的结点接到表尾;  df 加 1
7:          把 p 追加到 D[t] 尾结点的位置列表
8:  每个结点的 tf 为该结点位置列表的长度
9:  return D
```

> [!note] 为什么这样能保证「按文档编号、位置递增」
> 输入文档流按**递增编号**给出，文档内词项按**原位置递增**给出，只需**追加到表尾**即可自然维持有序，无需排序。

### 4.3 倒排表的压缩

倒排表中编号递增，可存**相邻编号的差值**（$\delta$-gap）：

$$[2,15,47,160] \;\Longrightarrow\; [2,13,32,113]$$

读取时从 0 开始依次累加即可还原。由于差值通常比原编号小得多，**变长编码**（按整数大小用不同字节数）能显著省空间。

> [!warning] 压缩是有代价的
> 查询时需要花时间**解码**。为了能跳过一段较长的倒排表，可以把表**分块**，为每块记录**起始文档编号与存储位置**，使查询能从块边界开始解码。

### 4.4 外存处理

文档很多时完整索引放不进内存，采用**分块建索引 + 归并**：内存中建满一个小索引就写往外存，清空后继续处理后续文档；全部处理完后把所有外存索引**归并**成一个完整索引。

### 4.5 更新与分布式索引

**增量更新**（避免每加一篇文档就重写整个索引）：

| 操作 | 做法 |
|---|---|
| **新增** | 为新文档单独建一个**较小的辅助索引**；查询时同时查主索引与辅助索引并合并结果；辅助索引积累到一定规模后与主索引**归并** |
| **删除** | 把文档编号加入**删除集合**，查询结果中遇到就过滤，等归并时再清除对应倒排表结点 |
| **修改** | 给新版本分配**新编号**，把旧版本标为删除 |

> [!tip] 中心思想
> 所有更新都先做「**小修改**」，把「**整理整个索引**」的工作**推迟到归并阶段**，这与 LSM-Tree 的思路一脉相承。

**分布式索引**的两种划分（仍用四篇短文举例）：

| | **按词项划分** term-partitioned | **按文档划分** document-partitioned |
|---|---|---|
| 划分方式 | 词典中的词项分给不同机器，各存所负责词项的**完整**倒排表 | 文档分给不同机器，各自为自己负责的文档建索引 |
| 例子 | 机器 1 负责 a–s，机器 2 负责 t–z | 机器 1 负责 D1,D2，机器 2 负责 D3,D4 |
| 单词查询 | **只需访问对应的那一台** | 需要发给**所有**机器 |
| 多词查询 | 可能需在机器间**传输倒排表或中间结果**再求交 | **各机器内部本地求交**，结果直接汇总，无需交换完整倒排表 |
| 主要风险 | **热门词**使某台机器承担大量查询 | 查询扇出大（每台机器都要干活） |

实际选择要结合：查询词数、热门词分布、机器间通信开销。

## 5. 搜索结果的评价

### 5.1 数据检索 vs 信息检索

| | **数据检索(data retrieval)** | **信息检索(information retrieval)** |
|---|---|---|
| 条件 | 明确、**可判定**（如「同时包含 silver 与 truck」） | 用户有**信息需求**，查询只能表达其中一部分 |
| 判断 | 满足即返回，结果对错分明 | 需要判断文档与需求的**相关程度**并排序 |
| 评价 | 结果正确性 + 建索引速度、查询延迟、查询语言表达能力 | 见下面的精确率与召回率 |

数据检索的另外三个考察维度：

- **建索引速度**（每小时能索引多少文档）——反映处理新增文档的能力；
- **查询速度**（查询延迟 latency），还要观察**索引增大时延迟如何变化**；
- **查询语言的表达能力**（能否表达「含 silver 和 truck 但不含 damaged」等复杂需求）。

### 5.2 混淆矩阵与两个核心指标

设评测文档集合为 $U$，按相关性标注的相关文档集合为 $R$，系统返回的文档集合为 $S$：

| | 相关 | 不相关 |
|---|---|---|
| **返回** | $\text{TP} = \lvert S \cap R\rvert$ | $\text{FP} = \lvert S \setminus R\rvert$ |
| **未返回** | $\text{FN} = \lvert R \setminus S\rvert$ | $\text{TN} = \lvert U \setminus (R \cup S)\rvert$ |

（T/F = True/False 的首字母，P/N = Positive/Negative 的首字母；即真正例、假正例、假反例、真反例，也称真/假阳性、假/真阴性。）

> [!important] 定义：精确率与召回率
> $$\boxed{\ P = \frac{\text{TP}}{\text{TP} + \text{FP}}\ ,\qquad R = \frac{\text{TP}}{\text{TP} + \text{FN}}\ }$$
> - **精确率 / 查准率(precision)** $P$：返回的文档中**有多少是相关的**；
> - **召回率 / 查全率(recall)** $R$：相关文档中**有多少被找到**。
>
> **边界情况**：若系统没返回任何文档，$P$ 的分母为 0；若评测集中没有相关文档，$R$ 的分母为 0。这两种情况记为「未定义」。

### 5.3 为什么不用准确率

若把「返回相关文档」和「未返回不相关文档」都算判断正确，得到**准确率(accuracy)**：

$$\text{accuracy} = \frac{\text{TP} + \text{TN}}{|U|}$$

> [!warning] 检索任务中准确率会被「不返回」骗过
> 一千篇文档中只有十篇相关，系统**什么都不返回**时准确率仍有 99%，但那十篇相关文档全被漏掉。因此精确率与召回率更能反映搜索结果是否有用。

### 5.4 例题

> [!note] 例
> 评测集 100 篇，相关文档 20 篇；系统返回 15 篇，其中 12 篇相关。
> $$\text{TP} = 12,\ \text{FP} = 3,\ \text{FN} = 8,\ \text{TN} = 77$$
> $$P = \frac{12}{15} = 0.8,\qquad R = \frac{12}{20} = 0.6$$

### 5.5 F1 分数

$$F_1 = \frac{2PR}{P + R} \quad\Longrightarrow\quad F_1 = \frac{2\,\text{TP}}{2\,\text{TP} + \text{FP} + \text{FN}}$$

> [!important] 调和平均的性质
> $F_1$ 是 $P$ 与 $R$ 的**调和平均**：两者相差很大时，$F_1$ 会**偏向较小的那个**。因此想拿高 $F_1$，必须**两个指标都不低**。

### 5.6 返回前 k 篇时 P 与 R 的变化

若系统按评分从高到低返回前 $k$ 篇：

- **召回率不会降低**：增大 $k$ 时，原来找到的相关文档**仍在结果中**；
- **精确率整体趋于降低**：好的评分规则下，越靠前的文档越可能相关。
- 但**可以构造例外**：前三篇依次为「相关、不相关、相关」，返回前两篇时 $P = 1/2$，返回前三篇时反而提高到 $2/3$。

整体而言，**精确率与召回率相互制约**，实际应用需在两者间权衡。

## 6. 网页评分：HITS

用倒排索引找到包含查询词的网页后，还要决定**展示顺序**。一个常用思路是考察网页之间的**链接**：许多网页都链接到的文章可能值得优先阅读；若推荐它的网页本身也很有影响力，这种推荐更有价值。

**建模**：有向图 $G = (V,E)$，$n = |V|$、$m = |E|$，边 $i \to j$ 表示网页 $i$ 链接到 $j$。约定：同一对网页的重复链接**只计一次**，自环略去。

```text
A ──→ B ──→ C        （C 没有出链）
└──────────→ C
```

### 6.1 两种分数：authority 与 hub

HITS（Hyperlink-Induced Topic Search）用两种分数刻画网页的两类作用：

- **authority score** $a_i$：根据**哪些网页链接到** $i$，评价它作为**内容来源**的权威程度；
- **hub score** $h_i$：根据 $i$ **链接到哪些网页**，评价它**推荐内容**的能力。

一个网页可以同时提供内容和推荐他人，因此**每个网页都算两种分数**。

> [!note] 选图：从根集合到基础集合
> 1. 先通过文本检索得到与查询有关的**根集合(root set)** $R_0$；
> 2. 再**双向扩展**：加入这些网页**推荐的**网页，以及**推荐了这些网页的**网页，得到**基础集合(base set)** $B_0$；
> 3. 以 $B_0$ 为顶点集，保留**两端都在其中**的链接，得到用于评分的图。
>
> 找「谁推荐了它」需要事先建立**反向链接索引**。
>
> 本讲的简化取法：根集合至多 $r$ 个网页；对其中每个网页，至多加入 $b$ 个「链接到它的」和 $b$ 个「它链接到的」（超限时按编号从小到大选）⟹ 基础集合至多 $r(1+2b)$ 个顶点。

### 6.2 迭代公式

一个网页得到高 hub 网页的推荐会增加它的 authority；它推荐了高 authority 的网页又会增加自己的 hub：

$$a'_j = \sum_{[本地路径已隐藏], i \to j} h_i, \qquad h'_i = \sum_{[本地路径已隐藏], i \to j} a'_j$$

**归一化**：反复求和会让分数越来越大，而排序只看**相对大小**，因此每轮更新后都把向量除以它的**欧几里得范数** $\|x\|_2 = \sqrt{\sum_i x_i^2}$，使两个向量长度恒为 1。

**矩阵形式**：定义邻接矩阵 $A$（存在边 $i \to j$ 时 $A_{ij} = 1$，否则为 0），分数写成列向量，则第 $t$ 轮为

$$a^{(t)} = \frac{A^{\mathsf T} h^{(t-1)}}{\|A^{\mathsf T} h^{(t-1)}\|_2}, \qquad  h^{(t)} = \frac{A\,a^{(t)}}{\|A\,a^{(t)}\|_2}$$

> [!note] 两个分量正是两次累加
> $(A^{\mathsf T}h)_j = \sum_i A_{ij}h_i$ 恰好累加了**所有链接到 $j$ 的网页**的 hub 分数；
> $(Aa)_i = \sum_j A_{ij}a_j$ 恰好累加了**网页 $i$ 所推荐各网页**的 authority 分数。

**归一化的可行性**：只要图中至少有一条边，且 hub 初值各分量都为正，第一次的 $A^{\mathsf T}h$ 就非零；设 $a = A^{\mathsf T}h/\|A^{\mathsf T}h\|_2$，则 $h^{\mathsf T}Aa = (A^{\mathsf T}h)^{\mathsf T}a = \|A^{\mathsf T}h\|_2 > 0$，所以 $Aa$ 也非零；更新 $h' = Aa/\|Aa\|_2$ 后又有 $a^{\mathsf T}A^{\mathsf T}h' = \|Aa\|_2 > 0$，**以后各轮的归一化都能进行**。

若图中**没有边**，所有贡献为零，算法返回全零分数，并报告「没有链接，无法排序」。

### 6.3 算法与复杂度

```text
HITS(G, K):
1:  if E = ∅ then return 全零分数, 报告"没有链接, 无法进行排名"
2:  h ← (1/√n, …, 1/√n)                     ▷ 所有网页初值相同
3:  for t = 1, …, K do
4:      a ← 0
5:      for 每条边 i → j do  a_j ← a_j + h_i
6:      a ← a / ‖a‖₂
7:      g ← 0
8:      for 每条边 i → j do  g_i ← g_i + a_j
9:      h ← g / ‖g‖₂
10: return (a, h)
```

- **每轮**：两次遍历边 + 一次遍历 $n$ 个分量进行归一化 ⟹ $O(n + m)$；
- **$K$ 轮**：$O(K(n+m))$，另加构建基础集合的时间；
- 若最终要按分数对全部网页排序，再需 $O(n\log n)$。

### 6.4 计算示例（上面的三个网页）

$$A = \begin{pmatrix} 0 & 1 & 1 \\ 0 & 0 & 1 \\ 0 & 0 & 0 \end{pmatrix}$$

**第一轮**：hub 初值相同 ⟹ 每条入链贡献相同 ⟹ 第一次的 authority 与**入度成比例**（C 有 2 条入链、B 有 1 条、A 无）：

$$a^{(1)} = \frac{(0,1,2)^{\mathsf T}}{\sqrt 5}, \qquad h^{(1)} = \frac{(3,2,0)^{\mathsf T}}{\sqrt{13}}$$

**第二轮**：

$$a^{(2)} = \frac{(0,3,5)^{\mathsf T}}{\sqrt{34}}, \qquad h^{(2)} = \frac{(8,5,0)^{\mathsf T}}{\sqrt{89}}$$

> [!note] 可以证明：从相同正初值出发，每轮迭代中 **C 的 authority 始终最高**。

### 6.5 收敛性：幂迭代与谱分析

每轮先算 $A^{\mathsf T}h$ 再左乘 $A$，两次归一化只改变长度。因此做完 $t$ 轮后，**$h^{(t)}$ 的方向与 $Q^t h^{(0)}$ 相同**，其中

$$Q = AA^{\mathsf T}$$

这种「反复乘同一矩阵再归一化」的过程称为**幂迭代(power iteration)**。

> [!important] 定理（HITS 收敛性）
> 若图至少有一条边，且 $Q = AA^{\mathsf T}$ 的**最大特征值单重**（$\lambda_1 > \lambda_2$），则从全正 hub 初值出发，归一化迭代使 hub 与 authority 向量分别收敛到**唯一的非负单位向量**。

**证明要点**：

1. **$Q$ 的性质**：$Q$ 是实对称矩阵，且 $x^{\mathsf T}Qx = \|A^{\mathsf T}x\|_2^2 \ge 0$ ⟹ 全部特征值非负。由谱定理，可选**单位正交**特征向量 $u_1,\dots,u_n$ 作基，特征值排序 $\lambda_1 \ge \cdots \ge \lambda_n \ge 0$。
2. **初值在最大特征方向的分量非零**：对任意单位向量 $u = \sum_i b_iu_i$，$u^{\mathsf T}Qu = \sum_i \lambda_i b_i^2 \le \lambda_1$。取对应 $\lambda_1$ 的单位特征向量、把各分量换成**绝对值**得 $w$；因 $Q$ 元素非负，$w^{\mathsf T}Qw$ 不会减小，而 $w$ 仍是单位向量故 $w^{\mathsf T}Qw \le \lambda_1$，只能取等号 ⟹ 可取**各分量非负**的 $u_1$。它至少有一个正分量，而 $h^{(0)}$ 分量全正，所以 $c_1 = (h^{(0)})^{\mathsf T}u_1 > 0$。
3. **其余方向衰减**：展开 $h^{(0)} = \sum_i c_iu_i$，两边乘 $Q^t$ 除以 $\lambda_1^t$：
   $$\frac{Q^t h^{(0)}}{\lambda_1^t} = c_1u_1 + \sum_{i=2}^{n} c_i\Big(\frac{\lambda_i}{\lambda_1}\Big)^t u_i \;\longrightarrow\; c_1u_1$$
   因为图中至少有一条边 ⟹ $Q$ 至少有一个正特征值 ⟹ $\lambda_1 > 0$；而对 $i \ge 2$ 有 $0 \le \lambda_i/\lambda_1 < 1$，右侧除第一项外都趋于零。归一化后 $h^{(t)} \to u_1$，由「非负且长度 1」知**极限唯一**。
4. **authority 同理**：对 authority 的迭代式取极限得 $a^* = A^{\mathsf T}u_1/\sqrt{\lambda_1}$，它非负、长度为 1，由 $h^*$ 的唯一性随之唯一确定。∎

**本例的谱**：

$$Q = \begin{pmatrix} 2 & 1 & 0 \\ 1 & 1 & 0 \\ 0 & 0 & 0 \end{pmatrix},\qquad \lambda_{1,2} = \frac{3 \pm \sqrt 5}{2},\quad \lambda_3 = 0$$

令 $\varphi = \dfrac{1+\sqrt 5}{2}$，解 $Qh = \lambda_1h$ 得

$$h^* = \frac{(\varphi,\,1,\,0)^{\mathsf T}}{\sqrt{\varphi^2+1}},\qquad a^* = \frac{(0,\,1,\,\varphi)^{\mathsf T}}{\sqrt{\varphi^2+1}}$$

> [!warning] 最大特征值多重时会怎样
> 任意**全正**初值最后都迭代到同一极限（上面的定理）。但若 $\lambda_1$ 对应**多个独立特征方向**，不同初值可能收敛到**不同**的极限向量。本质原因：极限向量是初值在「最大特征值对应的特征子空间」上的**归一化投影**——重数为 1 时该子空间是一维的，投影方向唯一；否则不同初值可能投影到不同方向。

> [!warning] HITS 的实际缺陷（Topic Drift）
> 围绕查询扩展网页集合时，可能加入一批**链接密集但与查询主题无关**的网页。它们之间的链接会在迭代中互相「刷分」，使无关网页排在真正相关的网页之前。人为构造互相推荐的链接也有同样效果。使用 HITS 排序时需要检查：
> - 选入的网页是否**仍围绕查询主题**；
> - 高分是否主要来自**一批无关网页之间的大量相互链接**。

## 7. 网页评分：PageRank

### 7.1 基本思想：随机浏览模型

与 HITS 不同，PageRank 从**浏览网页的过程**定义分数：假设用户当前位于网页 $i$，它有 $d_i$ 条出链，用户**等概率**选一条继续浏览，那么每条出链被选中的概率是 $1/d_i$。PageRank 就用这个随机浏览过程**达到稳定后**用户位于各网页的概率作为评分。

> [!warning] 只沿链接浏览会有两个问题
> 1. **周期**：若图中只有 $A \to B$、$B \to A$，从 $A$ 开始时所在网页在 $A,B$ 之间交替，概率分布在 $(1,0)^{\mathsf T}$ 与 $(0,1)^{\mathsf T}$ 之间摇摆，**无法趋于稳定**；
> 2. **不连通**：图有两个互不连通的部分时，用户永远留在出发时所在的部分，长期访问情况**受起点限制**。

**解决办法：引入随机跳转**。用概率向量 $v$（$v_i \ge 0$、$\sum_i v_i = 1$）表示跳转的选择，最简单取均匀分布 $v_i = 1/n$。

给定 $0 < \alpha < 1$：

- 在**有出链**的网页上：以概率 $\alpha$ 沿一条随机选中的出链浏览，以概率 $1-\alpha$ 按 $v$ 跳转；
- 在**没有出链**的网页（**悬挂结点 dangling node**）上：直接按 $v$ 跳转。

### 7.2 转移矩阵与迭代公式

用列向量 $p^{(t)}$ 表示第 $t$ 步的位置分布（$p_j^{(t)}$ 是位于网页 $j$ 的概率），定义矩阵 $P$：

$$P_{ij} = \begin{cases} 1/d_j, & d_j > 0 \text{ 且 } j \to i \\[2pt] 0, & d_j > 0 \text{ 且无 } j \to i \\[2pt] v_i, & d_j = 0 \end{cases}$$

> [!important] 列的语义
> $P_{ij}$ 是**从 $j$ 到达 $i$** 的概率，所以**出发网页对应列，到达网页对应行**。有出链时 $j$ 的 $d_j$ 个链接目标各得 $1/d_j$；没有出链时整列就是 $v$。因此 $P$ **元素非负、每列之和为 1**，称为**列随机矩阵**。
>
> ⚠️ 注意方向：**行 = 到达，列 = 出发**。这是 PageRank 计算最常搞反的地方。

加入概率 $1-\alpha$ 的随机跳转后：

$$\boxed{\ p^{(t+1)} = \alpha P p^{(t)} + (1-\alpha)v\ }\tag{3.1}$$

> [!important] 定义：PageRank 向量
> $p^*$ 满足
> $$p^* = \alpha Pp^* + (1-\alpha)v,\qquad p_i^* \ge 0,\qquad \sum_i p_i^* = 1 \tag{3.2}$$
> 即「当前分布是 $p^*$ 时，再走一步仍是 $p^*$」的**稳定分布**。

### 7.3 收敛性分析

对向量 $x$ 定义 $\|x\|_1 = \sum_i |x_i|$。因为 $P$ 非负且每列之和为 1：

$$\|Px\|_1 = \sum_i \Big|\sum_j P_{ij}x_j\Big| \le \sum_{i,j} P_{ij}|x_j| = \sum_j |x_j| = \|x\|_1$$

即**左乘 $P$ 后 $L_1$ 范数不会增大**。记一次迭代为 $F(p) = \alpha Pp + (1-\alpha)v$，对两个概率向量 $p,q$ 应用上式得

$$\|F(p) - F(q)\|_1 \le \alpha\|p - q\|_1 \tag{3.3}$$

也就是说迭代是一个**压缩映射**：两个分布各做一次迭代后距离至多变成原来的 $\alpha$ 倍。因为 $\alpha < 1$，反复迭代会不断缩小距离。

> [!important] 定理（PageRank 的存在唯一性与收敛速率）
> 对任意概率向量 $v$ 和任意 $0 < \alpha < 1$，PageRank 向量 $p^*$ **存在且唯一**。从任意概率初值 $p^{(0)}$ 出发按 (3.1) 迭代得到的 $p^{(t)}$ 收敛到 $p^*$，且
> $$\|p^{(t)} - p^*\|_1 \le 2\alpha^{\,t}$$

**证明要点**：

1. **每轮结果仍是概率向量**：$P$ 列随机、$v$ 是概率向量 ⟹ $F(p)$ 分量非负、和为 1。
2. **柯西序列**：记 $\Delta_t = \|p^{(t)} - p^{(t-1)}\|_1$，由 (3.3) 得 $\Delta_{t+1} \le \alpha\Delta_t$。于是对任意 $s > t$：
   $$\|p^{(s)} - p^{(t)}\|_1 \le \sum_{j=t+1}^{s}\Delta_j \le \frac{\alpha^t}{1-\alpha}\Delta_1 \longrightarrow 0$$
   这个上界**与 $s$ 无关**且随 $t$ 趋于零，故各坐标都是实数中的**柯西序列**，分别收敛。坐标只有有限个，极限向量仍然非负、分量之和仍为 1。对 (3.1) 取极限即知它是满足 $p^* = F(p^*)$ 的概率向量。
3. **唯一性**：若另有极限 $q^*$，则 $\|p^* - q^*\|_1 = \|F(p^*) - F(q^*)\|_1 \le \alpha\|p^* - q^*\|_1$；因 $0<\alpha<1$ 只能有 $\|p^*-q^*\|_1 = 0$，即 $p^* = q^*$。
4. **误差界**：反复用 (3.3)，并注意两个概率向量的 $L_1$ 距离至多为 2，得 $\|p^{(t)}-p^*\|_1 \le \alpha^t\|p^{(0)}-p^*\|_1 \le 2\alpha^t$。∎

> [!note] 证明用到的条件与推论
> 证明**只用**了三条：$P$ 是列随机矩阵、$0 < \alpha < 1$、$v$ 是概率向量。因此：
> - 无论原链接图**是否连通**、是否含**悬挂结点**，也无论选哪个 $v$，唯一性与收敛性都成立；
> - 若 $v$ 的每个分量都为正，还可得 $p_i^* \ge (1-\alpha)v_i > 0$，即**每个网页分数都为正**；若 $v$ 中有零分量，某些网页的分数可能为零。

**可检查的停止条件**：实际计算时不知道 $p^*$，但能算出相邻两轮的距离 $\Delta_t$。由 $\Delta_{t+1} \le \alpha\Delta_t$ 可知后续各轮变化之和不超过 $\frac{\alpha}{1-\alpha}\Delta_t$，因此

$$\|p^{(t)} - p^*\|_1 \le \frac{\alpha}{1-\alpha}\Delta_t \quad\Longrightarrow\quad \text{只需 } \Delta_t \le \frac{\varepsilon(1-\alpha)}{\alpha} \text{ 即可保证误差} \le \varepsilon$$

### 7.4 计算示例

仍用 A、B、C 的例子，取 $v = (1/3,1/3,1/3)^{\mathsf T}$、$\alpha = 1/2$。按 $P$ 的定义：从 A 出发等概率到达 B、C；从 B 出发到达 C；C 无出链故该列取 $v$：

$$P = \begin{pmatrix} 0 & 0 & 1/3 \\ 1/2 & 0 & 1/3 \\ 1/2 & 1 & 1/3 \end{pmatrix}$$

设稳定分布为 $(x,y,z)^{\mathsf T}$，从 $p^{(0)} = v$ 出发代入 (3.1)：

$$x = \frac{1}{6} + \frac{z}{6},\qquad y = \frac{1}{6} + \frac{x}{4} + \frac{z}{6},\qquad z = \frac{1}{6} + \frac{x}{4} + \frac{y}{2} + \frac{z}{6}$$

解得

$$p^* = \Big(\tfrac{8}{33},\ \tfrac{10}{33},\ \tfrac{15}{33}\Big)^{\mathsf T}$$

> [!tip] 与 HITS 的关键差别
> 本例中 **A 没有任何入链**，但**随机跳转仍能到达它**，所以 A 也有正分数；而 HITS 的 authority 只累加**入链**贡献，因此 A 的 authority 为 0。

### 7.5 不存矩阵的实现

现实中网页数可能达数十亿，完整存储矩阵 $P$ 不现实。可以直接根据链接计算下一轮分数，只需**邻接表 + 几个长度为 $n$ 的向量**。记当前概率向量为 $p$、下一轮为 $q$，分两步：

1. **先算随机跳转与悬挂结点的贡献**：随机跳转以概率 $1-\alpha$ 发生，跳到网页 $i$ 的概率是 $(1-\alpha)v_i$；再把当前位于**所有悬挂结点**的概率求和记为 $s = \sum_{[本地路径已隐藏],d_j=0} p_j$，这些列在 $P$ 中都等于 $v$，故它们在 $\alpha Pp$ 中跳到 $i$ 的概率合计为 $\alpha s v_i$。两部分相加，先令
   $$q_i = \big((1-\alpha) + \alpha s\big)v_i$$
2. **沿已有链接累加**：网页 $j$ 有 $d_j$ 条出链、当前位于它的概率为 $p_j$，故以概率 $\alpha$ 沿链浏览时，对每条链接 $j \to i$ 只需把 $\frac{\alpha p_j}{d_j}$ 加到 $q_i$ 上。

```text
PageRank(G, v, α, ε, K):
1:  预计算每页出度 d_j;  p ← v
2:  for t = 1, …, K do
3:      s ← Σ_{j: d_j = 0} p_j ;   q ← ((1-α) + αs)·v
4:      for 每条边 j → i do  q_i ← q_i + α·p_j/d_j
5:      Δ ← Σ_i |q_i - p_i| ;  p ← q
6:      if Δ ≤ ε(1-α)/α then return (p, 达到误差要求)
7:  return (p, 达到轮数上限, 误差条件尚未满足)
```

**复杂度**：

- 每轮遍历顶点和边 = $O(n+m)$ ⟹ $K$ 轮共 $O(K(n+m))$；
- 图与工作向量共占 $O(n+m)$ 空间；
- 由误差界 $2\alpha^t \le \varepsilon$ 可知，当 $0 < \varepsilon < 2$ 时，取 $t \ge \left\lceil \dfrac{\log(2/\varepsilon)}{-\log\alpha} \right\rceil$ 轮足以让理论误差达标。

### 7.6 HITS 与 PageRank 对比

| | **HITS** | **PageRank** |
|---|---|---|
| 分数 | authority 与 hub **两种** | **一个**概率分数 |
| 贡献规则 | hub 对每个链接目标贡献**完整**分数 | 按**出度**分配跳转概率 |
| 与查询的关系 | 通常对**查询扩展后的子图**计算 | **固定图与 $v$** 后可**预先计算** |
| 唯一性 | 最大特征值**单重**时，全正初值得到相同极限 | $0 < \alpha < 1$ 时**唯一** |
| 无出链网页 | hub 为零；有入链时 authority 可非零 | 按 $v$ **重新分配**其跳转概率 |

> [!tip] 个性化 PageRank
> 若希望评分**偏向某个主题**，可以让跳转分布 $v$ 给这一主题的网页更高概率——这就是**个性化 PageRank** 的一种做法。

**总体的搜索引擎流水线**：先用倒排索引找到候选网页，再综合**查询词的匹配情况、词项之间的距离、网页评分**进行排序，并通过评测来选择各项因素的组合方式。

## 8. 考点速查

1. **倒排索引 = 词典 + 倒排表**；倒排表按文档编号递增。**「倒排」= 把「文档→词」翻成「词→文档」**。
2. **词项–文档矩阵的问题不是慢而是稀疏**：$VN$ 个位置绝大多数是 0。
3. **df = 含该词的文档数**（分号前那个数）；**tf = 该词在某文档中出现的次数**。
4. **AND 求交、OR 求并**，用**双指针**在 $O(|P(t_1)| + |P(t_2)|)$ 内完成（链表递增是关键）。
5. **多词求交先做短表**（按 df 升序），因为中间结果长度 ≤ 最短参与表。
6. **位置索引**支持短语查询与结果摘要；**删停用词时绝不能重编位置编号**，否则会造出假短语。
7. **词典结构**：平衡树 $O(\log V)$ 或 **B/B+ 树**（词典巨大）；哈希期望 $O(1)$ 但**不支持范围查询**。
8. **倒排表压缩**用 $\delta$-gap（存相邻编号差值）+ 变长编码；代价是解码，可分块记起始位置。
9. **更新策略**：辅助索引 / 删除集合 / 新版本新编号——**先做小修改，把整理推迟到归并阶段**。
10. **分布式**：按词项分（单词查询只打一台，但热门词有热点）vs 按文档分（本地求交、直接汇总，但查询要广播给所有机器）。
11. **数据检索 vs 信息检索**：前者条件可判定，后者要判断**相关程度**。
12. $P = \dfrac{\text{TP}}{\text{TP}+\text{FP}}$，$R = \dfrac{\text{TP}}{\text{TP}+\text{FN}}$，$F_1 = \dfrac{2PR}{P+R} = \dfrac{2\text{TP}}{2\text{TP}+\text{FP}+\text{FN}}$。
13. **不要用 accuracy**：不相关文档占绝大多数时，「什么都不返回」也能有很高准确率。
14. **返回前 $k$ 篇**：$k$ 增大 ⟹ 召回率不降、精确率整体下降（但可构造反例）。
15. **HITS**：$a = A^{\mathsf T}h$、$h = Aa$，每轮归一化 $L_2$；每轮 $O(n+m)$、$K$ 轮 $O(K(n+m))$；收敛到 $Q = AA^{\mathsf T}$ **最大特征向量**，要求该特征值**单重**。
16. **PageRank**：$p^{(t+1)} = \alpha Pp^{(t)} + (1-\alpha)v$；$P$ **列随机**（列 = 出发，行 = 到达）；悬挂结点的整列是 $v$。
17. **PageRank 收敛证明两步**：$\|Px\|_1 \le \|x\|_1$ ⟹ 压缩 $\|F(p)-F(q)\|_1 \le \alpha\|p-q\|_1$ ⟹ 柯西序列 + 唯一性 + 误差界 $2\alpha^t$。
18. **停止条件**：$\Delta_t \le \varepsilon(1-\alpha)/\alpha$ ⟹ 误差不超过 $\varepsilon$；不存矩阵时每轮只需遍历边，$O(K(n+m))$。
19. **HITS 的坑**：Topic Drift（无关但链接密集的网页互相刷分）。
