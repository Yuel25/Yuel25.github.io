# 可合并堆（左式堆 · 斜堆）

> [!abstract] 导览
> 本文讲解两种支持高效**合并**的堆结构：**左式堆（Leftist Heap）** 与 **斜堆（Skew Heap）**。别名提示：左式堆在竞赛圈常叫「**左偏堆 / 左偏树**」，三者指同一个东西。

> 二者的合并策略完全一致——**只沿右路径走**；区别在于左式堆用 `npl`（零路径长）**显式**维持左偏性质，斜堆则每次合并**无条件交换**左右孩子、靠摊还分析保证性能。所有代码均为可编译的完整 C 实现。

## 1. 可合并堆 ADT：普通二叉堆的短板

**可合并堆（mergeable heap）** 要求的操作集合：

| 操作 | 含义 |
|---|---|
| `insert(x)` | 插入元素 |
| `findMin()` | 返回最小元 |
| `deleteMin()` | 删除最小元 |
| **`merge(h1, h2)`** | **把两堆合并成一堆** |

普通二叉堆（数组实现）的 `insert` / `deleteMin` 都是 O(log n)，但 **`merge` 需要 O(n)**：必须把两个数组拼起来再自底向上重建堆（Floyd 建堆）。当算法需要反复合并优先队列时，这是无法接受的。

> [!important] 目标与策略
> 目标：`insert` / `deleteMin` / `merge` **全部 O(log n)**。
>
> 已知结论（可作背景，不是本课重点）：在**只允许比较、不允许位运算**的模型下，三个操作不可能同时做到**最坏** O(log n)（需 Ω(log n) 摊还下界之外的条件限制）。因此实际结构分两条路线：
> - **左式堆**：`merge` 最坏 O(log n)，靠显式维护「左偏」不变式；
> - **斜堆**：`merge` 摊还 O(log n)，不存任何平衡信息，靠自调整 + 势能分析；
> - **二项堆**（lec05）：`merge` 最坏 O(log n)，`insert` 摊还 O(1)，靠树的森林结构。

## 2. 零路径长与左偏性质

### 2.1 零路径长（null path length, npl）

**约定**：`npl(NULL) = -1`；对非空结点

$$\text{npl}(x) = \min\big(\text{npl}(x\to left),\ \text{npl}(x\to right)\big) + 1$$

直观含义：从 x 出发走到一个「**不满结点**」（有两个孩子的结点称为满结点）的**最短**路径长度。叶结点（两个孩子都空）的 npl = 0。

```text
        A          npl(叶) = 0
       / \         npl 从下往上算，取左右中较小者 +1
      B   C        npl(NULL) = -1
     / \
    D   E
```

### 2.2 左偏性质（leftist property）

> [!important] 定义
> 一棵左式堆（leftist heap）是满足**堆序性**（父 ≤ 子）且对**每个结点**都有
> $$\text{npl}(x\to left) \ge \text{npl}(x\to right)$$
> 的二叉树。注意：左偏性质只说 npl，**不要求左右子树结点数相当**，也不要求高度平衡。

**直接推论**：任一站点的**右路径**（从该结点一路沿 right 指针走到底）就是到「不满结点」的最短路。

### 2.3 右路径长度的界（核心定理）

> [!important] 定理
> 若结点 x 的 npl = k，则以 x 为根的子树**至少**有 $2^{k+1} - 1$ 个结点。
>
> **证明思路**（对 k 归纳）：npl(x) = k 意味着从 x 往下的 k+1 层内、沿「每层取 npl 较小的那侧」走 k 步都是满结点，因此以 x 为根的子树包含一棵高度为 k 的**满二叉树**，至少 $2^{k+1}-1$ 个结点。∎

于是：若左式堆的**右路径含 r 个结点**，则 `npl(root) ≥ r - 1`，从而

$$n \ \ge\ 2^{r} - 1 \quad\Longrightarrow\quad r \le \log_2(n+1)$$

**结论：右路径长度是 O(log n)。** 这就是左式堆的整个性能基础——只要一切操作都只碰右路径，就自动是 O(log n)。

## 3. 左式堆的合并算法

### 3.1 算法（递归描述）

```
merge(h1, h2):
    ① 若 h1 为空，返回 h2；若 h2 为空，返回 h1
    ② 保证 h1 的根更小（否则交换 h1、h2）
    ③ h1->right = merge(h1->right, h2)      // 递归合并「h1 的右子树」与 h2
    ④ 若 npl(h1->left) < npl(h1->right)，交换 h1 的左右孩子   // 修复左偏
    ⑤ h1->npl = npl(h1->right) + 1
    ⑥ 返回 h1
```

**为什么正确**：第 ② 步使 h1 的根成为整堆最小元（它必须当根）；剩下的两个堆是「h1 的左右子树」和 h2，它们都比 h1 的根大，可以任意挂到根的子树里。把它们全塞到**右子树**上（第 ③ 步），是为了让递归**只走右路径**；第 ④ 步再把过长的右侧换到左边，恢复左偏。

**为什么是 O(log n)**：每次递归都往 `h1->right` 深入一层，而 h2 一旦挂上就不再参与递归；递归深度 = 两棵堆右路径长度之和 ≤ log₂(n₁+1) + log₂(n₂+1) = O(log n)。

### 3.2 其余操作全部归结为 merge

| 操作 | 实现 |
|---|---|
| `merge(h1, h2)` | 核心原语 |
| `insert(x)` | `merge(h, 单结点堆{x})` |
| `deleteMin()` | 摘掉根，`merge(左子树, 右子树)` |
| `findMin()` | 直接返回 `h->key`，**O(1)** |
| `buildHeap(数组)` | 反复 `insert`，O(n log n)；或把 n 个单结点堆两两合并，同样 O(n log n) |

### 3.3 手算例题

设 M 为「删去最小元」，初始两棵左式堆：

```text
        h1                        h2
         3                         6
        / \                       / \
      10   8                    12   7
      /                         /
    21                        18
```

先把 npl 标出来（NULL 记 −1）：叶结点 21、8、18、7 的 npl = 0；10 的右孩子为空，`npl(10) = npl(NULL)+1 = 0`；12 同理 npl = 0；于是 `npl(3) = min(0, 0)+1 = 1`，`npl(6) = min(0,0)+1 = 1`。两棵树都满足左偏（左 npl ≥ 右 npl）。

```text
merge(3堆, 6堆)
└─ 3 < 6  ⇒ 根取 3，递归 merge(3->right = 「8」, 「6」)
   └─ 6 < 8 ⇒ 交换，根取 6，递归 merge(6->right = 「7」, 「8」)
      └─ 7 < 8 ⇒ 根取 7，递归 merge(7->right = NULL, 「8」) = 「8」
         回溯 7：左 = NULL(npl −1)，右 = 8(npl 0) → −1 < 0 **成立，交换左右**
               → 左 = 8，右 = NULL；npl(7) = npl(NULL) + 1 = 0，返回 7
      回溯 6：左 = 12(npl 0)，右 = 7(npl 0) → 0 < 0 **不成立，不交换**
            npl(6) = npl(7) + 1 = 1，返回 6
   回溯 3：左 = 10(npl 0)，右 = 6(npl 1) → 0 < 1 **成立，交换左右**
         npl(3) = npl(10) + 1 = 1，返回 3
```

最终结果（8 个结点 = 4 + 4，无丢失）：

```text
              3                ← npl = 1
            /   \
           6     10           ← npl(6) = 1, npl(10) = 0
          / \    /
        12   7  21           ← npl(12) = 0, npl(7) = 0, npl(21) = 0
        /     \
       18      8
```

> [!note] 这个例子里的两个「反直觉」点，恰是考点
> 1. **叶结点 7 也发生了交换**：它本来在 h2 里是叶子，被挂上单结点堆「8」之后 `npl(左=NULL) = −1 < npl(右=8) = 0`，需要交换。**不要因为「原来是叶子」就跳过第 ④ 步**。
> 2. **结点 6 没有交换**：它的左右 npl 都是 0，`0 < 0` 不成立，保持原样（左 12、右 7）。左偏条件取的是 `≥`，不是 `>`。
>
> 另外注意：h2 里以 12 为根的子树（`12 ← 18`）**从头到尾没被递归碰过**，它只是被挂在 6 左边跟着走了——合并只走右路径。

> [!tip] 手算口诀
> 沿**右路径**把两棵树「拉链式」合并：每次都让键小的当根、把另一个堆接到它右边，走到某个堆为空为止；然后**回溯时做两件事**——先比较左右 npl 决定要不要交换，再重算 npl。递归只有一条主线，画图时不要分叉。

## 4. 左式堆完整 C 实现

```c
#include <stdio.h>
#include <stdlib.h>

typedef struct LHNode {
    int key;
    int npl;                        /* 零路径长：NULL 为 -1，叶结点为 0 */
    struct LHNode *left, *right;
} LHNode;

#define NPL(n)  ((n) ? (n)->npl : -1)   /* 空结点的 npl 统一按 -1 处理 */

static LHNode* lhNew(int key) {
    LHNode* n = (LHNode*)malloc(sizeof(LHNode));
    n->key = key; n->npl = 0; n->left = n->right = NULL;
    return n;
}

static void lhSwapChildren(LHNode* h) {
    LHNode* t = h->left;
    h->left  = h->right;
    h->right = t;
}

/* ---------- 核心原语：合并。只沿右路径递归，最坏 O(log n) ---------- */
LHNode* lhMerge(LHNode* h1, LHNode* h2) {
    if (!h1) return h2;                              /* ① 空则直接返回另一个 */
    if (!h2) return h1;
    if (h1->key > h2->key) {                         /* ② h1 根更小 */
        LHNode* t = h1; h1 = h2; h2 = t;
    }

    h1->right = lhMerge(h1->right, h2);              /* ③ 递归合并右子树 */

    if (NPL(h1->left) < NPL(h1->right))              /* ④ 左偏被破坏则交换 */
        lhSwapChildren(h1);

    h1->npl = NPL(h1->right) + 1;                    /* ⑤ 更新 npl（右路径变短了） */
    return h1;
}

/* ---------- insert = merge(堆, 单结点堆) ---------- */
LHNode* lhInsert(LHNode* h, int key) {
    return lhMerge(h, lhNew(key));
}

/* ---------- deleteMin = merge(左子树, 右子树) ---------- */
LHNode* lhDeleteMin(LHNode* h) {
    if (!h) return NULL;
    LHNode* l = h->left;
    LHNode* r = h->right;
    free(h);
    return lhMerge(l, r);                            /* 根被摘掉，两棵子树独立合并 */
}

/* 找到最小元（左式堆的根即最小元） */
LHNode* lhFindMin(LHNode* h) { return h; }

/* ---------- 辅助：释放与打印（按 npl 自检左偏性质） ---------- */
void lhFree(LHNode* h) {
    if (!h) return;
    lhFree(h->left);
    lhFree(h->right);
    free(h);
}

/* 前序遍历，顺带检查堆序性与左偏性质 */
int lhCheck(LHNode* h) {
    if (!h) return 1;
    if (h->left  && h->left->key  < h->key) return 0;          /* 堆序 */
    if (h->right && h->right->key < h->key) return 0;
    if (NPL(h->left) < NPL(h->right))       return 0;          /* 左偏 */
    if (h->npl != NPL(h->right) + 1)        return 0;          /* npl 一致 */
    return lhCheck(h->left) && lhCheck(h->right);
}

void lhPreorder(LHNode* h) {
    if (!h) return;
    printf("%d(npl=%d) ", h->key, h->npl);
    lhPreorder(h->left);
    lhPreorder(h->right);
}
```

> [!note] 实现要点
> - **第 ⑤ 步的 npl 公式**：交换之后右孩子是「原来较矮的那侧」，`npl = npl(right) + 1` 只在交换/更新之后算一次，不要写成 `min+1` 重复计算（两者结果相同，但前者更省）。
> - **第 ④ 步的判据是 npl 而不是结点数**：这是左式堆与后面斜堆的唯一区别。`npl(left) < npl(right)` 时交换以后必然满足左偏。
> - **递归深度是安全的**：递归层数 ≤ 右路径长度 ≤ log₂(n+1)，不会爆栈；而且递归写法的「返回新根」天然不需要父指针。
> - **迭代版**：沿右路径下降时用一个**栈**记录路径上每个结点，把 h2 的剩余部分挂到末端；然后弹栈，自底向上做「交换 + 更新 npl」。功能等价，常数更小，适合竞赛里 n 很大的场景。

## 5. 斜堆：丢掉 npl 的自调整版本

> **Sleator 与 Tarjan（1986）** 提出。核心观察：既然「交换左右孩子」这一步已经把左偏修复掉了，那么**判断该不该交换**这件事本身可能就是多余的——干脆**每次无条件交换**。

### 5.1 与左式堆的唯一区别

```text
merge(h1, h2)  —— 斜堆版
    ① 空则返回另一个
    ② 保证 h1 根更小
    ③ h1->right = merge(h1->right, h2)
    ④ **无条件**交换 h1 的左右孩子        ← 左式堆在这里是 if (npl(L) < npl(R))
    ⑤ 不维护任何平衡信息（没有 npl 字段）
```

> [!important] 直观理解
> 斜堆 = 左式堆把「按 npl 判断」换成「一律交换」。交换保证了**最近访问过的路径会变短**，把代价摊到以后的访问上——这正是**自调整**结构（splay 树、并查集路径压缩同源）的共同套路。

### 5.2 斜堆的性质

- **最坏单次操作可以很慢**：可以构造出一次合并走 O(n) 的右路径（例如交替合并大量单结点堆），因为不存 npl 就没有任何"高度上界"约束。
- **摊还 O(log n)**：任意 m 次连续操作的总代价 O(m log n)（见下节）。
- `insert` = `merge(堆, 单结点堆)`；`deleteMin` = `merge(左子树, 右子树)`——与左式堆完全一致。
- 代码更短：省掉 npl 字段（每结点省一个 int）与判断分支。

> [!tip] 什么时候用哪个
> 需要**单次最坏有保证**（实时系统、可持久化结构）→ 左式堆；追求**实现简单 / 常数小 / 空间省**，能接受摊还保证 → 斜堆。

## 6. 斜堆的摊还分析

势能函数法。定义：

- 结点 x **重（heavy）** $\iff |R(x)| > |L(x)|$（右子树结点数严格大于左子树）
- 结点 x **轻（light）** $\iff |R(x)| \le |L(x)|$

**势函数** $\Phi$ = 整棵树中**重结点的个数**。（$\Phi \ge 0$，且空树 $\Phi = 0$。）

> [!important] 引理 1：任一条右路径上至多有 $\log_2(n+1)$ 个轻结点
> 设 x 是右路径上的轻结点，则 $|R(x)| \le |L(x)|$，于是
> $$|\text{subtree}(x)| = |L(x)| + |R(x)| + 1 \ \ge\ 2|R(x)| + 1 \ >\ 2\,|R(x)|$$
> 也就是**沿右孩子走一步，所在子树的规模至少减半**。规模从 n 减半到 1 最多走 $\log_2(n+1)$ 步。∎

> [!important] 引理 2：一次 merge 只改变两条右路径上结点的重/轻状态
> 其余结点的左右子树完全没被碰过，重/轻状态不变。

**交换的效果**（沿右路径在每个结点上做）：

| 交换前 | 交换后 | 势能变化 |
|---|---|---|
| 重（右 > 左） | 新右 = 旧左 < 旧右 = 新左 ⇒ **变轻** | −1 |
| 轻（右 ≤ 左） | 新右 = 旧左 ≥ 旧右 = 新左 ⇒ **变重**（相等时仍为轻） | +1 或 0 |

**摊还计算**：设一次 merge 扫过的两条右路径共 h 个结点，其中轻的 b 个、重的 h−b 个。

- 实际代价 $c = \Theta(h)$（每步只做常数工作）
- 势能变化 $\Delta\Phi \le b - (h-b) = 2b - h$
- 摊还代价 $= c + \Delta\Phi \le \Theta(h) + 2b - h = \Theta(b)$

由引理 1，$b \le \log_2(n_1+1) + \log_2(n_2+1) = O(\log n)$，故

$$\boxed{\text{斜堆 merge 的摊还代价} = O(\log n)}$$

> [!note] 直觉与两条注意
> - **势能替我们付账**：路径上「重」的结点被走过一次之后就变轻了，以后再走它不会再收 O(1) 的账，所以那些代价是一次性的、可以用势能抵扣。
> - **摊还 ≠ 最坏**：单次 merge 仍可能 O(n)（把两个各含 O(log n) 条长右路径的堆反复"攒"起来）。考点常问「斜堆单次最坏是多少」——答案是 O(n)。
> - 交换对 h2 一侧同样成立：递归下去时 h2 的右路径也在被交换，两个堆都要用同一套论证，故 b 是两个堆轻结点数之和。

## 7. 斜堆完整 C 实现

```c
#include <stdio.h>
#include <stdlib.h>

typedef struct SkewNode {
    int key;
    struct SkewNode *left, *right;      /* 没有 npl，没有高度，什么都没有 */
} SkewNode;

static SkewNode* skewNew(int key) {
    SkewNode* n = (SkewNode*)malloc(sizeof(SkewNode));
    n->key = key; n->left = n->right = NULL;
    return n;
}

/* ---------- 核心原语：合并，最坏 O(n) / 摊还 O(log n) ---------- */
SkewNode* skewMerge(SkewNode* h1, SkewNode* h2) {
    SkewNode* tmp;

    if (!h1) return h2;
    if (!h2) return h1;
    if (h1->key > h2->key) {             /* h1 根更小 */
        tmp = h1; h1 = h2; h2 = tmp;
    }

    tmp = skewMerge(h1->right, h2);      /* ① 先递归合并右子树，结果暂存 */

    h1->right = h1->left;                /* ② 无条件交换左右孩子（三步交换） */
    h1->left  = tmp;

    return h1;
}

/* ---------- insert / deleteMin 同样是 merge 的特例 ---------- */
SkewNode* skewInsert(SkewNode* h, int key) {
    return skewMerge(h, skewNew(key));
}

SkewNode* skewDeleteMin(SkewNode* h) {
    if (!h) return NULL;
    SkewNode* l = h->left;
    SkewNode* r = h->right;
    free(h);
    return skewMerge(l, r);
}

SkewNode* skewFindMin(SkewNode* h) { return h; }

void skewFree(SkewNode* h) {
    if (!h) return;
    skewFree(h->left);
    skewFree(h->right);
    free(h);
}

void skewPreorder(SkewNode* h) {
    if (!h) return;
    printf("%d ", h->key);
    skewPreorder(h->left);
    skewPreorder(h->right);
}
```

> [!warning] 顺序不能换
> `tmp = skewMerge(h1->right, h2);` 必须**先**执行，再改写 `h1->right`。若写成「先交换孩子、再递归合并新的右子树」，会因为递归参数已被修改而得到错误的树。这三行的写法是刻意的。

**手算例题**（斜堆，两个堆都满足堆序即可，无需左偏）：

```text
    h1                 h2
     1                  3
    / \                / \
   4   2              7   5
      / \
     8   6
```

```
merge(1堆, 3堆)：1 < 3，根取 1
└─ 递归 merge(1->right = 「2」, 「3」)
   └─ 2 < 3，根取 2
      └─ 递归 merge(2->right = 「6」, 「3」)
         └─ 3 < 6，根取 3
            └─ 递归 merge(3->right = 「5」, 「6」)
               └─ 5 < 6，根取 5
                  └─ merge(5->right = NULL, 「6」) = 「6」
                  └─ 5：交换 → 左 = 6，右 = NULL，返回 5
               └─ 3：交换 → 左 = 「5」, 右 = 「7」，返回 3
         └─ 2：交换 → 左 = 「3」, 右 = 「8」，返回 2
      └─ 1：交换 → 左 = 「2」, 右 = 「4」，返回 1
```

结果（8 个结点 = 5 + 3，一个没丢）：

```text
              1
            /   \
           2     4
          / \
         3   8
        / \
       5   7
      /
     6
```

对照第 3.3 节左式堆的例子可见：**同一组输入，斜堆和左式堆会给出形状不同的树**（斜堆不管 npl，只按"走右路径 + 一路交换"来），但都满足堆序、都是合法结果。这也是常见判断题的坑。

## 8. 对比总结与考点速查

### 8.1 三种可合并堆横向对比

| 维度 | 左式堆 | 斜堆 | 二项堆（lec05） |
|---|---|---|---|
| 平衡信息 | 每结点一个 `npl`（int） | **无** | 结点度数 `degree` |
| 结构形态 | 二叉树 | 二叉树 | 二项树的**森林** |
| 合并策略 | 沿右路径 + 按 npl 交换 | 沿右路径 + **无条件**交换 | 二项树度数相同者「进位」合并 |
| `merge` 最坏 | **O(log n)** | O(n) | O(log n) |
| `merge` 摊还 | O(log n) | **O(log n)** | O(log n) |
| `insert` | O(log n) | O(log n) 摊还 | **O(1) 摊还** |
| `deleteMin` | O(log n) | O(log n) 摊还 | O(log n) |
| `findMin` | O(1) | O(1) | O(1)（维护最小值指针） |
| 附加性质 | 可持久化友好 | 代码最短、最省空间 | 支持 `decreaseKey`/`delete` 任意结点 |
| 典型用途 | 竞赛「可并堆」、k 短路、树上调度 | 自适应优先队列 | Prim/Dijkstra、斐波那契堆的铺垫 |

### 8.2 考试要点速记

1. **npl 定义的两个坑**：`npl(NULL) = -1`（不是 0！），`npl(x) = min(左, 右) + 1`。有些教材把 NULL 记 0，做题时先看题干口径，别混用。
2. **左偏性质是「npl(左) ≥ npl(右)」**，不是「左子树结点数 ≥ 右子树结点数」——后者是斜堆摊还分析里的重/轻结点定义，两回事。
3. **右路径 ≤ log₂(n+1)** 的证明是「npl = k ⇒ 子树 ≥ 2^{k+1} − 1 个结点」的直接推论，常考证明题。
4. **手算合并题**：只走右路径，回溯时按顺序做「比较 npl → 交换 → 重算 npl」。左式堆的交换是**有条件的**，斜堆是**无条件的**——这是二者最容易考的区别。
5. **insert / deleteMin 都是 merge 的特例**，不要另外设计算法。
6. **斜堆摊还分析的三步**：势函数取重结点个数 → 引理「右路径上轻结点 ≤ log n」（轻结点子树规模至少减半）→ 摊还代价 = Θ(轻结点数) = O(log n)。
7. **斜堆单次最坏 O(n)**，左式堆单次最坏 O(log n)，这是问「斜堆为什么不如左式堆」的标准答案；反过来答「斜堆胜在实现简单、每结点省一个字段、不需要维护 npl」。
8. 左式堆的根就是最小元（堆序性），所以 `findMin` 是 O(1)；`deleteMin` 之后要用 merge 把左右子树接起来，不能直接取某一侧作根。
