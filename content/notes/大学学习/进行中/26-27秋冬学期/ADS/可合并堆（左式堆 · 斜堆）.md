# 可合并堆（左式堆 · 斜堆）

> [!abstract] 导览
> 本文讲解两种支持高效**合并**的堆结构：**左式堆（Leftist Heap）** 与 **斜堆（Skew Heap）**。别名提示：左式堆在竞赛圈常叫「**左偏堆 / 左偏树**」，三者指同一个东西。

## 1. 可合并堆 ADT：普通二叉堆的短板

**可合并堆（mergeable heap）** 要求的操作集合：

| 操作 | 含义 |
|---|---|
| `insert(x)` | 插入元素 |
| `findMin()` | 返回最小元 |
| `deleteMin()` | 删除最小元 |
| **`merge(h1, h2)`** | **把两堆合并成一堆** |

普通二叉堆（数组实现）的 `insert` / `deleteMin` 都是 O(log n)，但 **`merge` 需要 O(n)**：必须把两个数组拼起来再自底向上重建堆（Floyd 建堆）。当算法需要反复合并优先队列时，这是无法接受的。

> [!important] 目标与策略
> 目标是让 `insert`、`deleteMin`、`merge` 都获得对数级代价，但**最坏保证与摊还保证要分开说**：
>
> - **左式堆**：`merge` 最坏 $O(\log n)$，靠显式维护左偏不变式；
> - **斜堆**：单次 `merge` 最坏可为 $O(n)$，但摊还 $O(\log n)$，不存平衡信息；
> - **二项堆**（lec05）：`merge` 最坏 $O(\log n)$，专用连续插入过程摊还 $O(1)$，靠二项树森林与二进制进位。
>
> 普通二叉堆数组合并还有一种选择：把较小堆逐项插入较大堆，代价为 $O(\min(n_1,n_2)\log(n_1+n_2+1))$；数组拼接后重建则为 $O(n_1+n_2)$。应根据堆大小选择，而不是只会一种合并方式。

## 2. 零路径长与左偏性质

### 2.1 零路径长（null path length, npl）

**约定**：`npl(NULL) = -1`；对非空结点

$$\text{npl}(x) = \min\big(\text{npl}(x\to left),\ \text{npl}(x\to right)\big) + 1$$

直观含义：从 x 出发走到一个「**不满结点**」（有两个孩子的结点称为满结点）的**最短**路径长度。叶结点（两个孩子都空）的 npl = 0。

```text
        A          npl(叶) = 0
       / \         npl 从下往上算，取左右中较小者 +1
      B   C        npl(NULL) = -1
     / \
    D   E
```

### 2.2 左偏性质（leftist property）

> [!important] 定义
> 一棵左式堆（leftist heap）是满足**堆序性**（父 ≤ 子）且对**每个结点**都有
> $$\text{npl}(x\to left) \ge \text{npl}(x\to right)$$
> 的二叉树。注意：左偏性质只说 npl，**不要求左右子树结点数相当**，也不要求高度平衡。

**直接推论**：任一站点的**右路径**（从该结点一路沿 right 指针走到底）就是到「不满结点」的最短路。

### 2.3 右路径长度的界（核心定理）

> [!important] 定理
> 若结点 x 的 npl = k，则以 x 为根的子树**至少**有 $2^{k+1} - 1$ 个结点。
>
> **证明思路**（对 k 归纳）：npl(x) = k 意味着从 x 往下的 k+1 层内、沿「每层取 npl 较小的那侧」走 k 步都是满结点，因此以 x 为根的子树包含一棵高度为 k 的**满二叉树**，至少 $2^{k+1}-1$ 个结点。∎

于是：若左式堆的**右路径含 $r$ 个结点**，由左偏性质沿右孩子递推可得 **`npl(root) = r - 1`**（这里把右路径一直走到 `NULL`），从而

$$n \ \ge\ 2^{r} - 1 \quad\Longrightarrow\quad r \le \left\lfloor\log_2(n+1)\right\rfloor.$$

**结论：右路径长度是 $O(\log n)$。** 这就是左式堆的性能基础——`merge` 的下降与回溯只访问两条右路径。注意“右路径短”不代表整棵树高度也是 $O(\log n)$：左侧子树可以很深，但核心合并操作不需要沿那条深路径下降。

## 3. 左式堆的合并算法

### 3.1 算法（递归描述）

```
merge(h1, h2):
    ① 若 h1 为空，返回 h2；若 h2 为空，返回 h1
    ② 保证 h1 的根更小（否则交换 h1、h2）
    ③ h1->right = merge(h1->right, h2)      // 递归合并「h1 的右子树」与 h2
    ④ 若 npl(h1->left) < npl(h1->right)，交换 h1 的左右孩子   // 修复左偏
    ⑤ h1->npl = npl(h1->right) + 1
    ⑥ 返回 h1
```

**为什么正确**：第 ② 步使 h1 的根成为整堆最小元（它必须当根）；剩下的两个堆是「h1 的左右子树」和 h2，它们都比 h1 的根大，可以任意挂到根的子树里。把它们全塞到**右子树**上（第 ③ 步），是为了让递归**只走右路径**；第 ④ 步再把过长的右侧换到左边，恢复左偏。

**为什么是 O(log n)**：每次递归都往 `h1->right` 深入一层，而 h2 一旦挂上就不再参与递归；递归深度 = 两棵堆右路径长度之和 ≤ log₂(n₁+1) + log₂(n₂+1) = O(log n)。

### 3.2 其余操作全部归结为 merge

| 操作 | 实现 |
|---|---|
| `merge(h1, h2)` | 核心原语 |
| `insert(x)` | `merge(h, 单结点堆{x})` |
| `deleteMin()` | 摘掉根，`merge(左子树, 右子树)` |
| `findMin()` | 直接返回 `h->key`，**O(1)** |
| `buildHeap(数组)` | 反复 `insert` 为 $O(n\log n)$；讲义另给线性法：先 $O(n)$ 建完全二叉最小堆，再改为指针存储并自底向上补算 `npl`，总计 $O(n)$ |

### 3.3 手算例题

设 M 为「删去最小元」，初始两棵左式堆：

```text
        h1                        h2
         3                         6
        / \                       / \
      10   8                    12   7
      /                         /
    21                        18
```

先把 npl 标出来（NULL 记 −1）：叶结点 21、8、18、7 的 npl = 0；10 的右孩子为空，`npl(10) = npl(NULL)+1 = 0`；12 同理 npl = 0；于是 `npl(3) = min(0, 0)+1 = 1`，`npl(6) = min(0,0)+1 = 1`。两棵树都满足左偏（左 npl ≥ 右 npl）。

```text
merge(3堆, 6堆)
└─ 3 < 6  ⇒ 根取 3，递归 merge(3->right = 「8」, 「6」)
   └─ 6 < 8 ⇒ 交换，根取 6，递归 merge(6->right = 「7」, 「8」)
      └─ 7 < 8 ⇒ 根取 7，递归 merge(7->right = NULL, 「8」) = 「8」
         回溯 7：左 = NULL(npl −1)，右 = 8(npl 0) → −1 < 0 **成立，交换左右**
               → 左 = 8，右 = NULL；npl(7) = npl(NULL) + 1 = 0，返回 7
      回溯 6：左 = 12(npl 0)，右 = 7(npl 0) → 0 < 0 **不成立，不交换**
            npl(6) = npl(7) + 1 = 1，返回 6
   回溯 3：左 = 10(npl 0)，右 = 6(npl 1) → 0 < 1 **成立，交换左右**
         npl(3) = npl(10) + 1 = 1，返回 3
```

最终结果（8 个结点 = 4 + 4，无丢失）：

```text
              3                ← npl = 1
            /   \
           6     10           ← npl(6) = 1, npl(10) = 0
          / \    /
        12   7  21           ← npl(12) = 0, npl(7) = 0, npl(21) = 0
        /     \
       18      8
```

> [!note] 这个例子里的两个「反直觉」点，恰是考点
> 1. **叶结点 7 也发生了交换**：它本来在 h2 里是叶子，被挂上单结点堆「8」之后 `npl(左=NULL) = −1 < npl(右=8) = 0`，需要交换。**不要因为「原来是叶子」就跳过第 ④ 步**。
> 2. **结点 6 没有交换**：它的左右 npl 都是 0，`0 < 0` 不成立，保持原样（左 12、右 7）。左偏条件取的是 `≥`，不是 `>`。
>
> 另外注意：h2 里以 12 为根的子树（`12 ← 18`）**从头到尾没被递归碰过**，它只是被挂在 6 左边跟着走了——合并只走右路径。

> [!tip] 手算口诀
> 沿**右路径**把两棵树「拉链式」合并：每次都让键小的当根、把另一个堆接到它右边，走到某个堆为空为止；然后**回溯时做两件事**——先比较左右 npl 决定要不要交换，再重算 npl。递归只有一条主线，画图时不要分叉。

## 4. 左式堆的任意删除与降键

`deleteMin` 只需合并根的两棵子树；任意 `delete(u)` 与 `decreaseKey(u,k)` 还要先修复被拆空的位置。这里必须能直接定位 $u$，并在实现中维护 `parent` 指针与整堆根指针。**堆序不支持像 BST 那样按键查找**；若只有键而没有结点位置，最坏要先扫描 $O(n)$ 个结点。

### 4.1 拆下子树后的向上修复

设 $u\neq root$，先从 $u.parent$ 摘下以 $u$ 为根的子树。父亲少了一棵子树后，`npl` 可能下降，并继续影响祖先。从 $p=u.parent$ 开始执行：

```text
RepairUp(p):
    while p ≠ null:
        若 npl(p.left) < npl(p.right)，交换 p 的左右孩子
        new = npl(p.right) + 1
        若 new == p.npl：
            停止                    // 更高祖先看到的信息也不再变化
        p.npl = new
        p = p.parent
```

- 交换孩子不会改变子树内的堆序，也不会改变子树大小；它只恢复 `npl(left) ≥ npl(right)`。
- 删除只会使相关位置的 `npl` **下降或不变**，不会凭空增大。
- 若某层的 `npl` 没变，其父亲看到的左右 `npl` 就都没变，因此可以安全提前停止。

### 4.2 Delete 与 DecreaseKey

```text
Delete(u):
    若 u 是根：直接 DeleteMin
    从原堆拆下 u 的子树，并 RepairUp(u.parent)
    去掉 u，把 u.left 与 u.right 合并
    再把合并结果与原堆 Merge

DecreaseKey(u, k):
    若 k > u.key，输入不合法
    若 u 是根或 k ≥ u.parent.key：直接令 u.key = k
    否则：
        从原堆拆下 u 的子树，并 RepairUp(u.parent)
        令 u.key = k
        把这棵仍以 u 为根的左式堆 Merge 回原堆
```

降键不会破坏 $u$ 与孩子之间的堆序，所以拆下的子树仍合法。任意删除则通过“两次合并”恢复：先合并被删结点的两个孩子，再与剩余堆合并。

### 4.3 为什么向上修复也是 $O(\log n)$

设当前父亲为 $p$，刚修复的下层子树为 $C$。若修复还要继续向上：

- $C$ 若本来在右边，交换判断后仍留在右边；
- $C$ 若在左边且其 `npl` 仍不小于右孩子，则 $p.npl$ 不变，算法会停止；
- 因而只有需要交换、并把 $C$ 放到右边时，才可能继续向上。

所以每继续一层，刚修复的子树都落在当前右路径上，修复层数不超过最终右路径长度 $O(\log n)$。再加上常数次左式堆合并，任意 `Delete` / `DecreaseKey` 的总代价仍为 $O(\log n)$（不计按键查找目标的时间）。

> [!warning] 易错点
> 不能只修改被删位置父亲的 `npl` 就结束，也不能无条件下滤被删结点的替代值。左式堆不是完全二叉树，任意删除的核心是“**拆子树 → 向上修左偏 → 合并**”。

## 5. 左式堆核心 C 实现

```c
#include <stdio.h>
#include <stdlib.h>

typedef struct LHNode {
    int key;
    int npl;                        /* 零路径长：NULL 为 -1，叶结点为 0 */
    struct LHNode *left, *right;
} LHNode;

#define NPL(n)  ((n) ? (n)->npl : -1)   /* 空结点的 npl 统一按 -1 处理 */

static LHNode* lhNew(int key) {
    LHNode* n = (LHNode*)malloc(sizeof(LHNode));
    n->key = key; n->npl = 0; n->left = n->right = NULL;
    return n;
}

static void lhSwapChildren(LHNode* h) {
    LHNode* t = h->left;
    h->left  = h->right;
    h->right = t;
}

/* ---------- 核心原语：合并。只沿右路径递归，最坏 O(log n) ---------- */
LHNode* lhMerge(LHNode* h1, LHNode* h2) {
    if (!h1) return h2;                              /* ① 空则直接返回另一个 */
    if (!h2) return h1;
    if (h1->key > h2->key) {                         /* ② h1 根更小 */
        LHNode* t = h1; h1 = h2; h2 = t;
    }

    h1->right = lhMerge(h1->right, h2);              /* ③ 递归合并右子树 */

    if (NPL(h1->left) < NPL(h1->right))              /* ④ 左偏被破坏则交换 */
        lhSwapChildren(h1);

    h1->npl = NPL(h1->right) + 1;                    /* ⑤ 更新 npl（右路径变短了） */
    return h1;
}

/* ---------- insert = merge(堆, 单结点堆) ---------- */
LHNode* lhInsert(LHNode* h, int key) {
    return lhMerge(h, lhNew(key));
}

/* ---------- deleteMin = merge(左子树, 右子树) ---------- */
LHNode* lhDeleteMin(LHNode* h) {
    if (!h) return NULL;
    LHNode* l = h->left;
    LHNode* r = h->right;
    free(h);
    return lhMerge(l, r);                            /* 根被摘掉，两棵子树独立合并 */
}

/* 找到最小元（左式堆的根即最小元） */
LHNode* lhFindMin(LHNode* h) { return h; }

/* ---------- 辅助：释放与打印（按 npl 自检左偏性质） ---------- */
void lhFree(LHNode* h) {
    if (!h) return;
    lhFree(h->left);
    lhFree(h->right);
    free(h);
}

/* 前序遍历，顺带检查堆序性与左偏性质 */
int lhCheck(LHNode* h) {
    if (!h) return 1;
    if (h->left  && h->left->key  < h->key) return 0;          /* 堆序 */
    if (h->right && h->right->key < h->key) return 0;
    if (NPL(h->left) < NPL(h->right))       return 0;          /* 左偏 */
    if (h->npl != NPL(h->right) + 1)        return 0;          /* npl 一致 */
    return lhCheck(h->left) && lhCheck(h->right);
}

void lhPreorder(LHNode* h) {
    if (!h) return;
    printf("%d(npl=%d) ", h->key, h->npl);
    lhPreorder(h->left);
    lhPreorder(h->right);
}
```

> [!note] 实现要点
> - **第 ⑤ 步的 npl 公式**：交换之后右孩子是「原来较矮的那侧」，`npl = npl(right) + 1` 只在交换/更新之后算一次，不要写成 `min+1` 重复计算（两者结果相同，但前者更省）。
> - **第 ④ 步的判据是 `npl` 而不是结点数**：这是左式堆与斜堆的核心差异之一；课程版斜堆另有末端与 base case 约定。`npl(left) < npl(right)` 时交换即可恢复当前结点的左偏性质。
> - **递归深度有对数上界**：合并的递归层数不超过两条右路径的访问量，因而是 $O(\log n)$；递归写法通过“返回新根”链接子树，核心合并不必依赖父指针。对数上界不等于对任意运行环境作“绝不爆栈”的绝对承诺。
> - **迭代版**：沿右路径下降时用一个**栈**记录路径上每个结点，把 h2 的剩余部分挂到末端；然后弹栈，自底向上做「交换 + 更新 npl」。功能等价，常数更小，适合竞赛里 n 很大的场景。

## 6. 斜堆：丢掉 npl 的自调整版本

斜堆由 **Sleator 与 Tarjan（1986）**提出。它不保存 `npl`、高度或其他平衡字段，只保持最小堆序；合并后的自调整代替显式左偏检查。其关系类似 splay 树与 AVL 树：牺牲单次最坏保证，换取更少的元数据与更简单的局部规则。

### 6.1 本课程采用的合并口径

lec04 把过程概括为两步：

1. **归并两条右路径**：按键值从小到大连接，保留路径上每个结点原来的左子树；
2. **自底向上交换孩子**：合并路径上的结点都交换左右孩子，**但路径最后一个（键最大的）结点不交换**。

```text
CourseSkewMerge(H1, H2):
    将 H1、H2 的右路径归并，路径根仍按键值递增
    对合并路径上除末端外的每个结点：
        swap(node.left, node.right)
    返回新根
```

因此合并后，两条原右路径主要转到新树的**左路径**；末端结点原来的左孩子仍保留在左边。交换不改变各子树内部的堆序，新根又是全部根中的最小键，所以结果仍满足堆序。

> [!warning] base case 是讲义特别点名的差异
> 有些资料采用常见递归版：`if (h1 == null) return h2; if (h2 == null) return h1;`，只在非空调用返回时交换。lec04 则要求处理 `H` 与 `null` 连接时，继续检查 $H$ 的右路径，并交换除最大结点外的孩子。两种写法得到的树形可能不同；**本笔记的手算、代码与势能证明均按 lec04**，考试时不要混用口径。

### 6.2 操作、代价与适用范围

- `insert(x)`：与单结点堆合并；`deleteMin()`：删根后合并两棵子树。
- 任意 `delete(u)`：合并 $u$ 的左右子树，用结果替换 $u$，再按斜堆规则处理；任意降键可直接删除旧结点，再以新键插入（这是讲义给出的一种直接实现）。
- **单次最坏 $O(n)$**：没有 `npl` 限制右路径，一次合并可访问线性数量的结点。
- **摊还 $O(\log n)$**：一系列 `insert` / `deleteMin` / `merge` 的总代价可由下一节的势能法控制。
- 每个结点省去 `npl` 字段，也不需要计算左偏条件；但递归实现仍可能因单次长路径而产生深递归。

> [!tip] 什么时候用哪个
> 需要单次最坏保证时选左式堆；能接受摊还保证、重视少元数据和自调整时考虑斜堆。不要把“斜堆摊还对数”写成“每次合并必然对数”。

## 7. 斜堆的轻重边摊还分析

### 7.1 重结点、轻结点与势函数

记 $L(x),R(x)$ 分别为 $x$ 的左、右子树的**结点数**，$s(x)=1+|L(x)|+|R(x)|$ 为以 $x$ 为根的子树大小。lec04 定义：若右子树结点数至少为 $s(x)/2$，则 $x$ 为重结点，否则为轻结点。它等价于：

- **重（heavy）**：$|R(x)|>|L(x)|$；
- **轻（light）**：$|R(x)|\le |L(x)|$。

等价性由 $2|R|\ge 1+|L|+|R|\iff |R|\ge |L|+1$ 得到。相等情形 $|L|=|R|$ 属于**轻**结点。讲义按“结点”计数；有些讲解把相应右孩子边称为重边/轻边，术语外观不同，证明用的仍是上述子树大小关系。

对多个堆组成的森林，取

$$\Phi=\text{所有堆中的重结点总数}.$$

空堆 $\Phi=0$，且始终 $\Phi\ge 0$，满足势函数要求。

### 7.2 引理：右路径上的轻结点只有对数个

若 $x$ 是轻结点，则 $|L(x)|\ge |R(x)|$，所以

$$s(x)=1+|L(x)|+|R(x)|\ge 1+2|R(x)|=1+2\big(s(x.right)-1\big)>2s(x.right).$$

因此，沿右路径每遇到一个轻结点，子树规模就至少缩小到原来的一半以下。更精细地归纳可得：若右路径有 $\ell$ 个轻结点，则整棵树至少有 $2^\ell-1$ 个结点，故

$$\ell\le \left\lfloor\log_2(n+1)\right\rfloor=O(\log n).$$

重结点没有这种规模收缩保证，一条右路径可以含 $O(n)$ 个重结点；这正是单次操作可能线性的原因。

### 7.3 合并前后势能怎样变化

设两个输入堆为 $H_1,H_2$，总结点数 $n=n_1+n_2$。在第 $i$ 条右路径上：

- $\ell_i$ 为轻结点数；
- $h_i$ 为重结点数；
- 另用 $h$ 表示**不在两条右路径上**的重结点总数。

课程版合并的真实成本按“每个右路径结点常数工作”归一化为

$$c=\ell_1+\ell_2+h_1+h_2.$$

有两个关键观察：

1. **路径外结点不改变轻重**：它们的整棵子树未被改动，因此合并前的 $h$ 个路径外重结点在合并后仍为重结点。
2. **原右路径上的重结点全部变轻**：除末端外交换左右孩子，使新右子树为旧左子树，由 $|L|<|R|$ 变为新 $|R'|<|L'|$；末端没有右孩子，本来就满足 $|R|=0\le |L|$，也是轻结点。

原右路径上的轻结点交换后**可能**变重，也可能仍为轻，所以新重结点最多有 $\ell_1+\ell_2+h$ 个：

$$\Phi(H_3)\le \ell_1+\ell_2+h,\qquad \Phi(H_1)+\Phi(H_2)=h_1+h_2+h.$$

于是

$$\Delta\Phi\le (\ell_1+\ell_2+h)-(h_1+h_2+h)
=\ell_1+\ell_2-h_1-h_2.$$

摊还代价满足

$$\hat c=c+\Delta\Phi
\le (\ell_1+\ell_2+h_1+h_2)+(\ell_1+\ell_2-h_1-h_2)
=2(\ell_1+\ell_2).$$

再由轻结点引理：

$$\ell_1+\ell_2=O(\log n_1+\log n_2)=O(\log(n_1+n_2))=O(\log n),$$

故课程版斜堆 `merge` 的摊还代价为 $O(\log n)$。若把每个结点的实际工作写成 $\alpha c$，可把势函数同乘相应常数，结论不变。

> [!note] 手算势能变化
> 假设两条右路径分别有 $(\ell_1,h_1)=(2,3)$、$(\ell_2,h_2)=(1,3)$，路径外重结点数 $h=7$。则实际归一化成本 $c=2+1+3+3=9$，合并前 $\Phi=3+3+7=13$，合并后 $\Phi\le 2+1+7=10$，所以 $\hat c\le 9+10-13=6=2(\ell_1+\ell_2)$。长路径上的 6 个重结点变轻，正好抵消主要成本。

### 7.4 为什么不能随便拿“右孩子总数”当势函数

合并确实会把许多结点从右路径转到左路径，但“右孩子总数”在一次线性成本的合并中**可以不下降**：讲义习题通过两条交错右路径构造了这种例子，旧左叶子在交换后又成为右孩子。因此它无法稳定支付长路径成本。有效的势函数必须利用**子树大小**区分轻重，而不是只数指针方向。

> [!warning] 摊还不是单次保证
> 一次合并仍可能实际花费 $\Theta(n)$；势能下降只是把成本推迟到“过去积累的重结点”上结账。写证明时还要同时计算两棵输入堆的轻、重结点，不能只分析其中一边。

## 8. 斜堆的 course 版实现与手算

```c
#include <stdio.h>
#include <stdlib.h>

typedef struct SkewNode {
    int key;
    struct SkewNode *left, *right;      /* 没有 npl，没有高度，什么都没有 */
} SkewNode;

static SkewNode* skewNew(int key) {
    SkewNode* n = (SkewNode*)malloc(sizeof(SkewNode));
    n->key = key; n->left = n->right = NULL;
    return n;
}

/* lec04 base case：继续处理剩余右路径，末端（没有右孩子）不交换 */
static SkewNode* skewFlipTail(SkewNode* h) {
    if (!h || !h->right) return h;       /* 空路径或合并路径末端 */
    SkewNode* mergedTail = skewFlipTail(h->right);
    h->right = h->left;
    h->left = mergedTail;
    return h;
}

/* ---------- 核心原语：合并，最坏 O(n) / 摊还 O(log n) ---------- */
SkewNode* skewMerge(SkewNode* h1, SkewNode* h2) {
    SkewNode* tmp;

    if (!h1) return skewFlipTail(h2);    /* 不是简单 return h2：采用讲义口径 */
    if (!h2) return skewFlipTail(h1);
    if (h1->key > h2->key) {             /* h1 根更小 */
        tmp = h1; h1 = h2; h2 = tmp;
    }

    tmp = skewMerge(h1->right, h2);      /* 先递归合并右子树，结果暂存 */

    h1->right = h1->left;                /* 非末端结点交换左右孩子 */
    h1->left  = tmp;

    return h1;
}

/* ---------- insert / deleteMin 同样是 merge 的特例 ---------- */
SkewNode* skewInsert(SkewNode* h, int key) {
    return skewMerge(h, skewNew(key));
}

SkewNode* skewDeleteMin(SkewNode* h) {
    if (!h) return NULL;
    SkewNode* l = h->left;
    SkewNode* r = h->right;
    free(h);
    return skewMerge(l, r);
}

SkewNode* skewFindMin(SkewNode* h) { return h; }

void skewFree(SkewNode* h) {
    if (!h) return;
    skewFree(h->left);
    skewFree(h->right);
    free(h);
}

void skewPreorder(SkewNode* h) {
    if (!h) return;
    printf("%d ", h->key);
    skewPreorder(h->left);
    skewPreorder(h->right);
}
```

> [!warning] 顺序不能换
> `tmp = skewMerge(h1->right, h2);` 必须**先**执行，再改写 `h1->right`。若写成「先交换孩子、再递归合并新的右子树」，会因为递归参数已被修改而得到错误的树。这三行的写法是刻意的。

**手算例题**（斜堆，两个堆都满足堆序即可，无需左偏）：

```text
    h1                 h2
     1                  3
    / \                / \
   4   2              7   5
      / \
     8   6
```

```
merge(1堆, 3堆)：1 < 3，根取 1
└─ 递归 merge(1->right = 「2」, 「3」)
   └─ 2 < 3，根取 2
      └─ 递归 merge(2->right = 「6」, 「3」)
         └─ 3 < 6，根取 3
            └─ 递归 merge(3->right = 「5」, 「6」)
               └─ 5 < 6，根取 5
                  └─ merge(5->right = NULL, 「6」) = 「6」
                  └─ 5：交换 → 左 = 6，右 = NULL，返回 5
               └─ 3：交换 → 左 = 「5」, 右 = 「7」，返回 3
         └─ 2：交换 → 左 = 「3」, 右 = 「8」，返回 2
      └─ 1：交换 → 左 = 「2」, 右 = 「4」，返回 1
```

结果（8 个结点 = 5 + 3，一个没丢）：

```text
              1
            /   \
           2     4
          / \
         3   8
        / \
       5   7
      /
     6
```

对照第 3.3 节左式堆的例子可见：**同一组输入，斜堆和左式堆会给出形状不同的树**（斜堆不管 `npl`，按课程规则交换合并路径上的孩子），但都满足堆序、都是合法结果。这也是常见判断题的坑。

### 8.1 base case 小手算：为什么不能直接返回长右路径

合并单结点堆 `1` 与右链 `2 → 3 → 4`（每个结点只有右孩子）：

```text
输入：  1        2
                  \
                   3
                    \
                     4

归并路径：1, 2, 3, 4
课程规则：交换 1、2、3 的孩子，末端 4 不交换
结果：    1
         /
        2
       /
      3
     /
    4
```

若 base case 遇到 `null` 就直接返回 `2 → 3 → 4`，那么 2、3 不会被交换，得到的是另一种树形。这就是本课程口径与部分常见递归代码的差别。

## 9. 我的理解与思考

> [!note] 个人归纳
> 本节是我对讲义证明和结构选择的整理，不是讲义原文。

### 9.1 左式堆维护的是“工作路径短”，不是“整棵树平衡”

搜索树希望每次查找都走短路径，所以要控制整体高度；堆只需要在根取最小值，合并又可以设计在右路径上，因此左式堆只约束 `npl(左) ≥ npl(右)`。左子树即使很深，也不会拖慢这次合并。这让我意识到：**不变式应该围绕操作真正访问的部分设计**，而不是笼统追求“越平衡越好”。

### 9.2 `npl` 是把指数规模下界写进每个结点

`npl = k` 不只是路径标记，它还承诺子树至少有 $2^{k+1}-1$ 个结点。于是每向右边前进一步，剩余问题的规模受到指数级约束。合并返回时交换孩子，相当于用常数工作恢复这份“规模证书”。任意删除后的向上修复也依赖同一证书，而不是另起一套平衡理论。

### 9.3 斜堆把显式证书换成跨操作的信用

斜堆不存 `npl`，单次操作缺少即时的右路径界。重结点却像已经储蓄的信用：长右路径上若重结点很多，课程版合并会把它们变轻，重结点数下降，势能替本次长路径买单。若路径上轻结点多，则轻结点本身就迫使子树规模快速缩小，路径不可能太长。

因此证明的两半缺一不可：**轻结点给出对数上界，重结点提供可释放的势能**。只背 $\Phi=\#heavy$ 而不说明这两点，就没有真正理解摊还分析。

### 9.4 三种堆是在“立即维护”与“延迟结账”之间取舍

左式堆每次合并立即修复结构，获得最坏对数；斜堆每次做简单自调整，用势能跨操作结账；二项堆则把结构组织成二进制计数器。我的理解是，复杂度表只是结果，真正值得掌握的是每种结构把成本放在哪里、用什么不变式或势能证明这笔账始终付得起。

## 10. 对比总结与考点速查

### 10.1 三种可合并堆横向对比

| 维度 | 左式堆 | 斜堆 | 二项堆（lec05） |
|---|---|---|---|
| 平衡信息 | 每结点一个 `npl`（int） | **无** | 结点度数 `degree` |
| 结构形态 | 二叉树 | 二叉树 | 二项树的**森林** |
| 合并策略 | 沿右路径 + 按 `npl` 判断交换 | 归并右路径 + 交换除末端外的孩子（lec04 口径） | 同阶二项树链接并「进位」 |
| `merge` 最坏 | **O(log n)** | O(n) | O(log n) |
| `merge` 摊还 | O(log n) | **O(log n)** | O(log n) |
| `insert` | O(log n) | O(log n) 摊还 | **O(1) 摊还** |
| `deleteMin` | O(log n) | O(log n) 摊还 | O(log n) |
| `findMin` | O(1) | O(1) | O(1)（维护最小值指针） |
| 附加性质 | 可持久化友好 | 代码最短、最省空间 | 支持 `decreaseKey`/`delete` 任意结点 |
| 典型用途 | 竞赛「可并堆」、k 短路、树上调度 | 自适应优先队列 | Prim/Dijkstra、斐波那契堆的铺垫 |

### 10.2 考试要点速记

1. **`npl` 定义的两个坑**：`npl(NULL) = -1`（不是 0），`npl(x)=min(npl(left),npl(right))+1`。不同教材若采用其他约定，必须先读题干，不能混用公式。
2. **左偏性质是 `npl(left) ≥ npl(right)`**，不是左子树结点数更多；后者属于斜堆轻重分析的另一套概念。
3. **右路径定理**：非空左式堆根的 `npl` 等于右路径边数；若右路径有 $r$ 个结点，则 $n\ge 2^r-1$，所以 $r\le\lfloor\log_2(n+1)\rfloor$。
4. **左式堆手算**：只沿右路径递归，回溯时依次“比较 `npl` → 必要时交换 → 更新 `npl`”。相等时不交换，因为条件是 `≥`。
5. **操作归并**：`insert` 与 `deleteMin` 都是 `merge` 的特例；任意删除/降键则先拆子树并向上修复，再合并。只给键而没有结点位置时，查找目标本身可能花费 $O(n)$。
6. **斜堆按讲义口径**：归并右路径后，交换除末端外的孩子；某些递归资料 base case 不同，手算不能混用。
7. **斜堆摊还证明链**：轻重定义 $\Rightarrow$ 右路径轻结点 $O(\log n)$ $\Rightarrow$ 路径外轻重不变、路径上重结点变轻 $\Rightarrow$ $\Delta\Phi\le \ell_1+\ell_2-h_1-h_2$ $\Rightarrow$ $\hat c\le2(\ell_1+\ell_2)=O(\log n)$。
8. **摊还不是最坏**：斜堆单次 `merge` 可为 $O(n)$，左式堆最坏 $O(\log n)$；不要把摊还上界写成每次操作都必然成立，也不要把上界证明误写成精确成本 $\Theta(\ell_1+\ell_2)$。
9. **建堆**：反复插入是 $O(n\log n)$；讲义给出的左式堆线性建堆法是先建完全二叉最小堆，再指针化并补算 `npl`。
