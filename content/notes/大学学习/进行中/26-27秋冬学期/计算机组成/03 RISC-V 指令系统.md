## 1. 机器语言、存储程序与设计原则
### 1.1 三层语言与两次翻译
同一个交换相邻数组元素的过程，可以有三种外观：
- **高级语言**：用变量、表达式和控制结构描述算法，例如 `temp = v[k]; v[k] = v[k+1];`。
- **汇编语言**：用 `ld`、`sd`、`add` 等符号表示机器操作，并显式选择寄存器和地址。
- **机器语言**：指令最终是二进制位模式；处理器读取这些位，而不是直接理解 C 或汇编助记符。
基本翻译关系是：

```text
C 源程序 --compiler--> 汇编程序 --assembler--> 机器语言目标模块
```

高级语言让程序员更接近问题本身，也提高可移植性；汇编则把 ISA 提供的实际能力暴露出来。学习汇编不是为了让所有程序都手写汇编，而是为了看清**软件语义最终受什么硬件契约支撑**。
### 1.2 存储程序原理
本章反复强调两个关键点：
1. **指令用数表示**：操作码、寄存器编号、立即数都编码为二进制位。
2. **程序像数据一样存放在内存中**：可以被读取，也可由装载器写入；编译器、汇编器、链接器正是“处理程序的程序”。
这带来两个重要结果：
- 取指与读取数据都在访问内存中的位，但二者按不同语义解释；同样的位模式本身没有天生的“指令”或“数据”标签。
- **标准化 ISA 支持二进制兼容**：只要实现遵守同一架构约定，已编译程序可在不同微架构上运行，而不必因流水线深度、缓存大小改变而重写。
### 1.3 四条设计原则

> [!note] 设计原则不是口号，要能在具体编码中找到证据
>
> | 原则 | 本章对应例子 | 为什么有用 |
> |---|---|---|
> | **Simplicity favors regularity**（简单源于规整） | 常见算术指令三个操作数；少数字段位置固定；load/store 与运算分开 | 译码、数据通路和编译器生成都更规则 |
> | **Smaller is faster**（越小越快） | 只设 32 个通用整数寄存器，而不是把所有变量都放内存 | 寄存器堆更小、更快，5 位即可编号 |
> | **Make the common case fast**（加快常见情况） | 立即数指令、`x0` 恒零、短偏移分支、压缩指令扩展 | 高频操作少访存、少指令或省代码空间 |
> | **Good design demands good compromises**（好设计需要好折中） | 固定 32 位基础编码与有限立即数；为保持寄存器字段位置而拆散立即数 | 在代码密度、译码复杂度、表达能力之间折中 |

“简单”不等于“功能弱”。复杂 C 表达式可由多条简单指令组合；编译器通常很擅长这种组合。相反，一条很强的复杂指令可能让最慢路径决定整个处理器的时钟周期。

## 2. 寄存器、ABI 与算术运算
### 2.1 32 个整数寄存器
RV64 有 `x0`–`x31` 共 32 个通用整数寄存器，每个 64 位；64 位数据称 **doubleword**，32 位数据称 **word**。寄存器用于频繁访问的数据，而大数组、结构体、堆对象通常放在内存。
- 寄存器编号需要 5 位，因为 $2^5=32$。
- `x0` 永远读出 0，向其写入会被丢弃；它不是“初始值为 0、以后可改”的普通寄存器。
- `pc` 是程序计数器，不属于这 32 个通用寄存器，不能当作 `x32` 使用。
- 寄存器比内存快，因此编译器会进行寄存器分配；寄存器不够时，把较不常用的值 **spill** 到栈等内存区域。

### 2.2 ABI 名称与调用保存责任
**ISA** 规定 `add`、`ld` 等指令怎样执行；**ABI（Application Binary Interface）**进一步约定寄存器在函数接口中的用途。下表的“保存责任”指一次普通过程调用前后的可见值，而不是说硬件会自动压栈。

| 寄存器 | ABI 名 | 通常用途 | 调用性质与保存责任 |
|---|---|---|---|
| `x0` | `zero` | 常量 0 | 不可改，无保存问题 |
| `x1` | `ra` | 返回地址 | call-clobbered；非叶过程若还要调用别人，通常自行保存 |
| `x2` | `sp` | 栈指针 | 调用前后必须恢复；callee 释放自己的栈帧 |
| `x3` | `gp` | 全局指针 | 特定运行环境保留，不应当作普通临时寄存器 |
| `x4` | `tp` | 线程指针 | 线程环境保留，不应当作普通临时寄存器 |
| `x5`–`x7` | `t0`–`t2` | 临时值 | caller-saved / call-clobbered |
| `x8` | `s0` / `fp` | 保留寄存器，可选帧指针 | callee-saved；若使用则保存并恢复 |
| `x9` | `s1` | 保留寄存器 | callee-saved |
| `x10`–`x17` | `a0`–`a7` | 前 8 个整数参数及返回值 | call-clobbered；需要跨调用保留时由 caller 处理 |
| `x18`–`x27` | `s2`–`s11` | 保留寄存器 | callee-saved；只保存实际使用的那些 |
| `x28`–`x31` | `t3`–`t6` | 临时值 | caller-saved / call-clobbered |

> [!warning] “caller 保存”与“callee 保存”不是无条件全保存
> - caller 只有在**某个 call-clobbered 寄存器里的值跨调用后仍要使用**时，才需要保存它。
> - callee 只有在**自己要改写某个 callee-saved 寄存器**时，才需要保存旧值，并在返回前恢复。
> - `ra` 被 `jal` / `jalr` 直接写入；`a0` 还常承载返回值。二者都不能被误认为跨调用天然不变。
前 8 个整数参数通常放入 `a0`–`a7`，普通整数返回值放入 `a0`（需要时 ABI 也使用后续返回寄存器）。更多参数按 ABI 放入调用者的传出参数栈区；**不能脱离具体帧布局，死记“第 9 个参数一定在 `fp+8`”**。
标准 RISC-V psABI 通常要求 `sp` 保持 16 字节对齐。讲义用 24 字节保存 3 个 doubleword 是为了直观看保存/恢复；实际编译器可能把帧大小向上取整到 32 字节。
### 2.3 算术指令：三操作数与立即数
最常见的寄存器算术形式为：

```asm
add rd, rs1, rs2    # rd = rs1 + rs2
sub rd, rs1, rs2    # rd = rs1 - rs2
addi rd, rs1, imm   # rd = rs1 + sext(imm)，imm 为 12 位有符号数
```

C 语句：

```c
f = (g + h) - (i + j);
```

若 `f, g, h, i, j` 分别在 `s0, s1, s2, s3, s4`，可译为：

```asm
add t0, s1, s2      # t0 = g + h
add t1, s3, s4      # t1 = i + j
sub s0, t0, t1      # f = t0 - t1
```

这里需要两条 `add` 和一条 `sub`，因为一条基础算术指令只完成一个二元运算。规整的三操作数格式避免额外的累加器约定，也让目的操作数不覆盖任一源操作数。
立即数把常见小常数直接放进指令：

```asm
addi x22, x22, 4    # 不必先把常量 4 从内存 load 到寄存器
addi t0, a0, -1     # 12 位立即数可以为负
```

这就是 *make the common case fast*：省去一次访存，也少用一个寄存器。`addi` 的立即数范围是 **−2048～2047**；超出范围时由多条指令或伪指令 `li` 构造。
RV64I 还提供 `addw`、`subw`、`addiw` 等 32 位运算形式，其低 32 位结果会符号扩展到 64 位。`mul` 等整数乘除指令属于 **M 扩展**，不要混入“RV64I 基础指令”的清单。

## 3. 逻辑运算与移位
### 3.1 位运算

| 运算 | RISC-V 指令示例 | 用途 |
|---|---|---|
| AND | `and x9, x10, x11` / `andi` | 用掩码保留某些位，其余清 0 |
| OR | `or x9, x10, x11` / `ori` | 把掩码为 1 的位设为 1 |
| XOR | `xor x9, x10, x11` / `xori` | 比较位差异、翻转指定位 |
| NOT | `xori x9, x10, -1` | 与全 1 异或，逐位取反 |

例如只保留低 8 位：

```asm
andi t0, a0, 0xff       # 掩码 0x00...00ff
```

`and` 的寄存器形式必须有三个寄存器操作数，不能写成讲义汇总表中偶见的 `and x5, x6, 3`；常数形式应写 `andi`。
### 3.2 逻辑移位与算术移位

| 指令 | 操作 | 空出位如何填 |
|---|---|---|
| `sll` / `slli` | 左移 | 右侧补 0 |
| `srl` / `srli` | 逻辑右移 | 左侧补 0 |
| `sra` / `srai` | 算术右移 | 左侧复制原符号位 |

- 左移 $i$ 位，在无溢出的合适解释下相当于乘 $2^i$。
- 逻辑右移 $i$ 位相当于**无符号数**除以 $2^i$ 并向下取整。
- 算术右移保留负数的符号，不能把逻辑右移笼统用于有符号负数除法。

```asm
slli t0, a0, 3          # 地址计算常见：下标乘 8
srli t1, a0, 3          # 把 a0 当无符号位串，高位补 0
srai t2, a0, 3          # 把 a0 当有符号数，高位补符号位
```

RV64 的立即数移位量需要 6 位，以覆盖 0～63。`slli` / `srli` / `srai` 使用特殊 I 型布局：高位是 `funct6`，低 6 位是 `shamt`，并不是普通的 12 位算术立即数。

## 4. 内存、小端与对齐
### 4.1 字节编址与 load/store
RISC-V 使用**字节编址**：一个地址标识一个 8 位字节，而不是一个 64 位 doubleword。因此：
- 相邻 doubleword 的地址相差 8。
- 相邻 32 位 word 的地址相差 4。
- 64 位地址理论上可表示 $2^{64}$ 个字节地址，即 $2^{61}$ 个 doubleword 的位置；这只是地址空间上界，不表示机器真的装了这么多内存。
RISC-V 是 load/store 架构：算术逻辑指令的操作数来自寄存器，内存数据必须先 load，结果需要写回时再 store。

```asm
ld t0, 0(a0)            # t0 = Memory[a0 + 0]
add t0, t0, a1
sd t0, 0(a0)            # Memory[a0 + 0] = t0
```

### 4.2 小端字节序
RISC-V 采用 **little endian**：多字节对象的**最低有效字节放在最低地址**。若从地址 `A` 存入 32 位数 `0x12345678`：

| 地址 | 字节值 |
|---|---|
| `A + 0` | `0x78` |
| `A + 1` | `0x56` |
| `A + 2` | `0x34` |
| `A + 3` | `0x12` |

所以按地址递增观察字节是 `78 56 34 12`。大端则按地址递增看到 `12 34 56 78`。字节序讨论的是**字节在内存中的排列**，不会把每个字节内部的位也倒过来。
### 4.3 对齐与结构体填充
自然对齐通常要求对象的地址是其对齐要求的整数倍，例如 8 字节 doubleword 常放在 8 的倍数地址。原因是一个跨缓存行、内存字或页边界的数据可能需要多次访问和额外拼接。
讲义结构体例子中，`char` 成员之后插入未使用字节，是为了让后面的 `float e` 落在合适边界：
![[co-ch3-LrRHT6l4.png]]

> [!warning] 不要把“ISA 不强制自然对齐”误读为“未对齐访问总没代价”
> 讲义指出 RISC-V 不像某些 ISA 那样一律要求字对齐。具体到 RISC-V 执行环境，未对齐 load/store 可能由硬件或软件透明处理，也可能产生异常；即使能完成，也可能更慢。编译器仍会通过自然对齐和结构体 padding 避免跨行访问。
### 4.4 有符号与无符号只是解释约定
同一组位没有内在数值含义。$n$ 位无符号数范围是 $0$ 到 $2^n-1$；二进制补码有符号数范围是 $-2^{n-1}$ 到 $2^{n-1}-1$。
- 全 0 表示 0，全 1 在补码中表示 −1。
- 最高位为 1 时，补码解释是负数，无符号解释则是一个很大的正数。
- 补码取负：按位取反再加 1；最小负数的正数无法在同位宽中表示。
- 这解释了为什么 `blt` 与 `bltu` 面对完全相同的寄存器位模式，可能作出不同判断。

## 5. 寻址方式与数组访问
### 5.1 本章四种核心寻址方式

| 寻址方式 | 操作数或目标怎样得到 | 例子 |
|---|---|---|
| 立即数寻址 | 常数直接编码在指令中 | `addi x5, x6, 10` |
| 寄存器寻址 | 操作数在寄存器中 | `add x5, x6, x7` |
| 基址加偏移寻址 | 有效地址 `EA = rs1 + sext(offset)` | `ld x5, 100(x6)` |
| PC 相对寻址 | 目标 `= 当前指令 PC + sext(offset)` | `beq x5, x6, L1` |

![[co-ch3-cKPQXFYu.png]]
`jalr` 还提供寄存器间接跳转：目标主要来自 `rs1 + imm`，适用于返回、间接函数调用和跳转表。`auipc` 则把 PC 与高位立即数相加，为位置无关的地址构造服务。
### 5.2 数组下标为什么先乘元素大小
若 `A` 是 doubleword 数组，基址在 `s2`，`h` 在 `s1`：

```c
A[12] = h + A[8];
```

对应：

```asm
ld   t0, 64(s2)         # A[8]：8 × 8 = 64 字节
add  t0, s1, t0
sd   t0, 96(s2)         # A[12]：12 × 8 = 96 字节
```

若下标在运行时变化，不能由汇编器预先算成一个固定 offset，需要先计算地址：

```asm
slli t0, a1, 3          # t0 = i * sizeof(doubleword) = i * 8
add  t0, a0, t0         # t0 = &A[i]
ld   t1, 0(t0)
```

这里 `slli` 是“乘法的强度削减”：对 2 的幂，用移位替代更一般的乘法。
### 5.3 `swap`：完整的 C / 汇编对照

```c
void swap(long long v[], size_t k) {
    long long temp = v[k];
    v[k] = v[k + 1];
    v[k + 1] = temp;
}
```

`v` 在 `a0`，`k` 在 `a1`。这是不调用其他过程的**叶过程**，只用临时寄存器即可：

```asm
swap:
    slli t1, a1, 3       # t1 = 8 * k
    add  t1, a0, t1      # t1 = &v[k]
    ld   t0, 0(t1)       # temp = v[k]
    ld   t2, 8(t1)       # t2 = v[k+1]
    sd   t2, 0(t1)       # v[k] = v[k+1]
    sd   t0, 8(t1)       # v[k+1] = temp
    jalr zero, 0(ra)     # return
```

它没有修改 `s0`–`s11`，也没有嵌套调用覆盖自己的 `ra`，所以不必为了“函数看起来完整”而机械压栈。

## 6. R-I-S-B-U-J 指令格式
### 6.1 公共字段
课程 RV64I 基础指令使用 32 位编码。常见字段为：
- `opcode`：主操作码，位于 `inst[6:0]`。
- `rd`：目的寄存器编号，通常位于 `inst[11:7]`。
- `funct3`：3 位附加功能码，位于 `inst[14:12]`。
- `rs1`：第一源寄存器或基址寄存器，位于 `inst[19:15]`。
- `rs2`：第二源寄存器或待存储数据寄存器，位于 `inst[24:20]`。
- `funct7` / `funct6`：进一步区分 `add/sub`、`srl/sra` 等。
- `imm`：分散在各格式中的立即数位，需按格式重排并扩展。
![[co-ch3-KcGbrnLp.png]]
### 6.2 六种布局总表
下表把每行字段按 **31 位到 0 位**排列；逗号只是字段分隔，不表示机器码里存在标点。

| 格式 | 高位到低位字段布局 | 主要用途 |
|---|---|---|
| R | `funct7[31:25], rs2[24:20], rs1[19:15], funct3[14:12], rd[11:7], opcode[6:0]` | 寄存器算术、逻辑、比较 |
| I | `imm[11:0][31:20], rs1[19:15], funct3[14:12], rd[11:7], opcode[6:0]` | 立即数运算、load、`jalr` |
| S | `imm[11:5][31:25], rs2[24:20], rs1[19:15], funct3[14:12], imm[4:0][11:7], opcode[6:0]` | store |
| B | `imm[12][31], imm[10:5][30:25], rs2, rs1, funct3, imm[4:1][11:8], imm[11][7], opcode` | 条件分支 |
| U | `imm[31:12][31:12], rd[11:7], opcode[6:0]` | `lui`、`auipc` |
| J | `imm[20][31], imm[10:1][30:21], imm[11][20], imm[19:12][19:12], rd, opcode` | `jal` |

> [!note] 旧称对照
> 讲义也把 B 型称为 **SB 型**，把 J 型称为 **UJ 型**。含义相同；本篇统一用更常见的 R/I/S/B/U/J。
### 6.3 R 型：寄存器间运算

```text
 31       25 24  20 19  15 14 12 11   7 6      0
+-----------+------+------+-----+------+--------+
|  funct7   | rs2  | rs1  |fnc3 |  rd  | opcode |
+-----------+------+------+-----+------+--------+
```

语义常为 `rd = rs1 op rs2`。`add` 与 `sub` 的 `opcode`、`funct3` 相同，靠 `funct7` 区分；`srl` 与 `sra` 也采用类似办法。
### 6.4 I 型与 S 型：为什么立即数拆法不同
I 型保留完整的 `rd`，12 位立即数连续放在最高位，适合 `addi`、load 和 `jalr`：

```text
I: | imm[11:0]       | rs1 | funct3 | rd        | opcode |
S: | imm[11:5] | rs2 | rs1 | funct3 | imm[4:0]  | opcode |
```

S 型没有目的寄存器，却需要两个寄存器字段：`rs1` 提供基址，`rs2` 提供写入内存的数据。把立即数拆到 `31:25` 和 `11:7`，就能让 `rs1`、`rs2` 与 R 型保持原位。
这种“立即数不连续”不是随意增加难度，而是为了**寄存器字段规整**。硬件可在操作细节尚未完全译出时，就从固定位置读取寄存器编号。
### 6.5 B 型与 J 型：偏移最低位不编码
B/J 立即数表示**相对当前指令地址的字节偏移**。由于指令至少按 2 字节对齐，合法目标偏移的 `imm[0]` 恒为 0，所以编码省略这一位，解码时补 0。

> [!important] 必须纠正的说法
> 不能说“B/J 立即数是以 2 字节为单位的数，因此目标 = PC + 字段值 × 2”。字段中那些分散的位要拼成一个带符号的**字节偏移**，末尾再补已被省略的 0。比如字节偏移 +12 的 `imm[4:1]` 确实是 6，但完整立即数是 12，不是“先得到 6 再乘 2”的机器字段整体值。
在课程无 RVC 的 32 位指令序列里，实际目标还通常相隔 4 字节的倍数；但格式仍只强制省略 `imm[0]`，不能把 `imm[1]` 也擅自省掉。
### 6.6 U 型：高 20 位与低 12 位补零
`lui` 将 20 位立即数放到位 `31:12`，低 12 位补 0；RV64 中结果按 32 位有符号值扩展到 64 位。`auipc` 则把这个值与当前 `pc` 相加：

```asm
lui   t0, 0x12345       # t0 的低 32 位为 0x12345000
auipc t0, 0x1           # t0 = pc + 0x1000（再按 RV64 规则扩展）
```

### 6.7 常用 opcode / funct 速查

| 指令组 | `opcode` | `funct3` 或其他识别信息 |
|---|---|---|
| R 型整数运算 | `0110011` | `add/sub 000`，`sll 001`，`slt 010`，`sltu 011`，`xor 100`，`srl/sra 101`，`or 110`，`and 111` |
| I 型整数运算 | `0010011` | `addi 000`，`slti 010`，`sltiu 011`，`xori 100`，`ori 110`，`andi 111` |
| Load | `0000011` | `lb 000`，`lh 001`，`lw 010`，`ld 011`，`lbu 100`，`lhu 101`，`lwu 110` |
| Store | `0100011` | `sb 000`，`sh 001`，`sw 010`，`sd 011` |
| Branch | `1100011` | `beq 000`，`bne 001`，`blt 100`，`bge 101`，`bltu 110`，`bgeu 111` |
| `jal` | `1101111` | J 型，无 `funct3` |
| `jalr` | `1100111` | I 型，`funct3 = 000` |
| `lui` | `0110111` | U 型 |
| `auipc` | `0010111` | U 型 |

R 型中 `sub`、`sra` 的 `funct7 = 0100000`，其余表中常见 `add`、`srl` 等为 `0000000`。注意 Branch 的 opcode 是 `1100011`，而 `jalr` 才是 `1100111`。

## 7. 立即数拼接与机器编码例题
### 7.1 通用读法
以下 `{...}` 表示位拼接，`sext(...)` 表示把拼接结果符号扩展到 RV64 的 64 位；`inst[i]` 指机器指令的第 `i` 位。

```text
I: sext({inst[31:20]})
S: sext({inst[31:25], inst[11:7]})
B: sext({inst[31], inst[7], inst[30:25], inst[11:8], 1'b0})
U: sext({inst[31:12], 12'b0})
J: sext({inst[31], inst[19:12], inst[20], inst[30:21], 1'b0})
```

展开为重复符号位的写法：

| 类型 | 拼接后的原始位数 | 64 位立即数 |
|---|---:|---|
| I | 12 | `{{52{inst[31]}}, inst[31:20]}` |
| S | 12 | `{{52{inst[31]}}, inst[31:25], inst[11:7]}` |
| B | 13 | `{{51{inst[31]}}, inst[31], inst[7], inst[30:25], inst[11:8], 1'b0}` |
| U | 32 | `{{32{inst[31]}}, inst[31:12], 12'b0}` |
| J | 21 | `{{43{inst[31]}}, inst[31], inst[19:12], inst[20], inst[30:21], 1'b0}` |

符号位统一取 `inst[31]`，也是编码规整的体现。U 型不是简单“20 位零扩展”：它先形成低 12 位为 0 的 32 位值，在 RV64 再按位 31 符号扩展。
### 7.2 范围与偏移单位

| 类型 | 可表达的关键范围 | 说明 |
|---|---|---|
| I/S | −2048～2047 | 12 位有符号字节偏移或常数 |
| B | −4096～+4094 字节，步长 2 | 13 位有符号字节偏移，最低位不存 |
| J | −1,048,576～+1,048,574 字节，步长 2 | 21 位有符号字节偏移，最低位不存 |
| U | 20 位字段驱动位 31:12 | 低 12 位补 0，不应当作普通 20 位整数范围背诵 |

B/J 的目标基准是**当前这条分支或跳转指令的 PC**，不是 `PC + 4`；`PC + 4` 是 `jal` / `jalr` 写入 `rd` 的返回地址。
### 7.3 例 1：完整编码 `add x9, x20, x21`
已知 `add` 的 `opcode = 0110011`、`funct3 = 000`、`funct7 = 0000000`。

| 字段 | 十进制 | 二进制 |
|---|---:|---|
| `funct7` | 0 | `0000000` |
| `rs2 = x21` | 21 | `10101` |
| `rs1 = x20` | 20 | `10100` |
| `funct3` | 0 | `000` |
| `rd = x9` | 9 | `01001` |
| `opcode` | 51 | `0110011` |

按字段从高到低拼接：

```text
0000000 10101 10100 000 01001 0110011
= 0000 0001 0101 1010 0000 0100 1011 0011
= 015A 04B3（十六进制）
```

所以机器码是 **`0x015A04B3`**。四位二进制对应一位十六进制，分组必须从最低位开始每四位一组，不能改变字段次序。
### 7.4 例 2：拼接 B 型立即数并验证机器码
设 `bne s1, s8, Exit` 位于地址 **80012**，`Exit` 位于 **80024**，其中 `s1 = x9`，`s8 = x24`。
第一步，直接按**字节地址**求差：
$$\text{offset}=80024-80012=12$$
第二步，把 12 写成 13 位二进制 `0 0000 0000 1100`，取各段：

| 立即数字段 | 值 | 来源 |
|---|---|---|
| `imm[12]` | `0` | 非负数，符号位为 0 |
| `imm[11]` | `0` | 12 的第 11 位 |
| `imm[10:5]` | `000000` | 高段均为 0 |
| `imm[4:1]` | `0110` | $12/2=6$，只是这四个位的数值 |

第三步，连同 `rs2 = 24 = 11000`、`rs1 = 9 = 01001`、`bne` 的 `funct3 = 001` 填入：

```text
imm[12|10:5]  rs2    rs1    f3   imm[4:1|11]  opcode
0000000       11000  01001  001  01100         1100011
```

得到：

```text
0000000 11000 01001 001 01100 1100011
= 0000 0001 1000 0100 1001 0110 0110 0011
= 0x01849663
```

解码时按 `inst[31], inst[7], inst[30:25], inst[11:8], 0` 重排，就恢复 **+12 字节**。这道例题也说明：看见字段值 `0110` 不能直接说“汇编器写入的立即数是 6”；必须区分**完整字节偏移**与**编码字段切片**。
### 7.5 例 3：由机器码反汇编 `0x00578833`
先按 R 型字段切开：

```text
0x00578833
= 0000000 00101 01111 000 10000 0110011
```

- `opcode = 0110011`，说明是 R 型整数运算。
- `funct7 = 0000000` 且 `funct3 = 000`，说明是 `add`。
- `rs2 = 00101 = 5`，即 `t0`。
- `rs1 = 01111 = 15`，即 `a5`。
- `rd = 10000 = 16`，即 **`a6`**。
因此反汇编为：

```asm
add a6, a5, t0
```

讲义该页文字把 `x16` 对应成 `a7`，这是 ABI 编号笔误；`x16 = a6`，`x17 = a7`。

## 8. 条件分支、循环与间接跳转
### 8.1 相等、大小与有符号性

| 指令 | 条件成立时跳转 | 比较解释 |
|---|---|---|
| `beq rs1, rs2, L` | `rs1 == rs2` | 位模式相等 |
| `bne rs1, rs2, L` | `rs1 != rs2` | 位模式不等 |
| `blt rs1, rs2, L` | `rs1 < rs2` | 有符号 |
| `bge rs1, rs2, L` | `rs1 >= rs2` | 有符号 |
| `bltu rs1, rs2, L` | `rs1 < rs2` | 无符号 |
| `bgeu rs1, rs2, L` | `rs1 >= rs2` | 无符号 |

例如 `x22` 为全 1、`x23` 为 1：
- 有符号解释：−1 < +1，所以 `blt x22, x23, L` 会跳。
- 无符号解释：很大的正数 > 1，所以 `bltu x22, x23, L` 不会跳。
RISC-V 没有单独的 `bgt` / `ble` 真实指令，它们由汇编器交换操作数后展开为 `blt` / `bge`。
### 8.2 `slt`：把比较结果写成 0 或 1

```asm
slt  t0, s0, s1         # 有符号：t0 = (a < b) ? 1 : 0
sltu t0, s0, s1         # 无符号版本
bne  t0, zero, Less     # 若 a < b，跳到 Less
```

`slti` / `sltiu` 则让寄存器与立即数比较。`slt` 配合 `beq` / `bne` 可构造其他条件；不过常见 `a < b` 直接用 `blt` 更短。
### 8.3 if / else 与循环
C 代码：

```c
if (i == j)
    f = g + h;
else
    f = g - h;
```

一种汇编结构：

```asm
    bne  s3, s4, Else   # i != j 时走 else
    add  s0, s1, s2     # then：f = g + h
    jal  zero, Exit     # 跳过 else
Else:
    sub  s0, s1, s2     # else：f = g - h
Exit:
```

`while (save[i] == k) i = i + 1;` 的骨架则是：

```asm
Loop:
    slli t0, s6, 3       # i * 8
    add  t0, t0, s9      # &save[i]
    ld   t1, 0(t0)
    bne  t1, s8, Exit    # 条件不满足就退出
    addi s6, s6, 1
    jal  zero, Loop
Exit:
```

![[co-ch3-cPr6MSEe.png]]
![[co-ch3-jjYmiuAy.png]]
若把第一条指令放在 80000，则六条 32 位指令地址依次为 80000、80004、80008、80012、80016、80020，`Exit` 为 80024：
- `bne` 在 80012，向前到 `Exit` 的偏移是 +12，即上一节编码例。
- 最后的无条件跳转在 80020，回 `Loop` 的偏移是 $80000-80020=-20$。
- 两条偏移都相对**各自当前指令地址**，不能统一相对循环首地址计算。
### 8.4 目标太远：反转条件加无条件跳转
B 型范围有限。原来的：

```asm
    beq a0, zero, Far
```

若 `Far` 超出分支范围，可改为：

```asm
    bne a0, zero, Skip  # 反转条件，决定是否跳过 jal
    jal zero, Far
Skip:
```

![[co-ch3-bUcump8l.png]]
若连 `jal` 也不够，则用 `lui` / `auipc` 配合 `jalr` 构造更远目标。汇编器和链接器通常负责这些细节，但手算时必须知道范围限制。
### 8.5 `jal`、`jalr` 与跳转表

```asm
jal  ra, Procedure      # ra = pc + 4；pc = pc + offset
jalr zero, 0(ra)        # 返回：pc = (ra + 0) & ~1
jalr ra, 0(t0)          # 间接调用：目标在 t0
```

`jalr` 的目标计算后会把最低位清 0；若没有启用 RVC，目标仍须满足 4 字节指令对齐，否则可能产生指令地址未对齐异常。
`switch` 可先边界检查，再以 `k` 索引存放代码地址的跳转表，最后用 `jalr` 间接跳转：
![[co-ch3-cYBpIP5o.png]]
### 8.6 基本块
**基本块（basic block）**是一段指令序列：
- 除末尾外没有分支或跳转；
- 除开头外没有分支目标标签；
- 因而从入口进入后，会顺序执行到出口，没有中间旁路。
编译器识别基本块后可做局部优化与调度，处理器也可利用这种顺序性加速执行。

## 9. 过程调用、栈与递归
### 9.1 一次过程调用的六个阶段
1. caller 把参数放到约定位置，通常是 `a0`–`a7`。
2. caller 用 `jal ra, callee` 转移控制，并把返回地址写入 `ra`。
3. callee 获取所需存储资源：分配栈帧、保存它必须保护的寄存器。
4. callee 执行过程体；若再调用其他过程，同样遵守约定。
5. callee 把结果放入约定返回寄存器，恢复保存寄存器和 `sp`。
6. callee 用 `jalr zero, 0(ra)` 返回，caller 从 `jal` 的下一条指令继续。
硬件只完成跳转和链接；“参数在哪、谁保存谁、栈怎样恢复”主要由 ABI 和代码共同保证。
### 9.2 栈向下增长与正确的 push / pop
栈通常从高地址向低地址增长。压入一个 doubleword 时，先让 `sp` 减 8，再把数据写到**新的 `sp` 指向的位置**：

```asm
# 概念上的 push：保存一个 doubleword
addi sp, sp, -8
sd   t0, 0(sp)          # 正确：写入新栈顶，不是 8(sp)
# 概念上的 pop：与上面配对
ld   t0, 0(sp)
addi sp, sp, 8
```

> [!warning] 旧示例纠错
> `addi sp, sp, -8; sd t0, 8(sp)` 会把数据写回新栈帧之外，既不是这次 push 的新栈顶，也与 `ld t0, 0(sp)` 不配对。若减 8 后使用 `8(sp)`，那指的是**原来的** `sp` 位置。
![[co-ch3-sFba4Dmg.png]]
真实函数往往一次性分配整个帧，而不是每个值都单独 push/pop：

```asm
    addi sp, sp, -32     # 例如保存 3 个 doubleword，并维持 16 字节对齐
    sd   ra, 24(sp)
    sd   s0, 16(sp)
    sd   s1, 8(sp)
    # ...函数体...
    ld   s1, 8(sp)
    ld   s0, 16(sp)
    ld   ra, 24(sp)
    addi sp, sp, 32
    jalr zero, 0(ra)
```

保存与恢复顺序可以相反，但地址必须与保存时一一对应；返回前 `sp` 必须回到入口值。
### 9.3 谁需要保存：叶过程与非叶过程
讲义的 `leaf_example` 先保存 `x5`、`x6`、`x20`，再计算 `(g+h)-(i+j)`，适合展示栈操作；但按 ABI 优化时：
- `x5 = t0`、`x6 = t1` 是 call-clobbered，叶过程可以直接使用，不必为 caller 保存。
- `x20 = s0` 是 callee-saved，只有本函数使用它时才保存并恢复。
- 若过程不调用别人，自己的 `ra` 不会被嵌套 `jal` 覆盖，通常不必保存 `ra`。
因此“每条函数都保存所有寄存器”既错误又低效；保存集合取决于寄存器类别、实际使用和是否嵌套调用。
### 9.4 栈帧、局部数据与帧指针
过程帧（activation record）包含该过程的保存寄存器、局部数组或结构体、可能的溢出参数等。C 的 automatic 局部变量常位于栈上，static 变量则位于静态数据区。
![[co-ch3-ut3O9gGP.png]]
- `sp` 指向当前栈顶，分配和释放帧时改变。
- `fp` 是 `s0` 的可选用途；若使用，可在一个帧内保持固定，用固定偏移访问局部数据。
- 使用 `fp` 本身也要遵守 `s0` 的 callee-saved 约定。
- 简单函数或 `sp` 已足够定位所有数据的函数，可以省略 `fp`。

> [!warning] 悬空指针
> 过程返回后，它的栈帧可能被后续调用覆盖。把指向 automatic 局部变量的指针返回给 caller，会形成无效或不可依赖的指针；这不是 load/store 指令出错，而是对象生命周期已结束。
### 9.5 递归阶乘：为什么要同时保存 `ra` 与 `n`
C 代码：

```c
long long fact(long long n) {
    if (n < 1)
        return 1;
    return n * fact(n - 1);
}
```

下面是按讲义结构整理的教学版。`mul` 属于 M 扩展；每一层使用 16 字节栈帧：

```asm
fact:
    addi sp, sp, -16
    sd   ra, 8(sp)        # 保存“回到上一层”的地址
    sd   a0, 0(sp)        # 保存本层的 n
    addi t0, a0, -1
    bge  t0, zero, Recur  # 若 n - 1 >= 0，即 n >= 1
    addi a0, zero, 1      # 基本情况：返回 1
    addi sp, sp, 16       # 本层没有使用保存值，可直接释放帧
    jalr zero, 0(ra)
Recur:
    addi a0, a0, -1       # 参数 n - 1
    jal  ra, fact         # 下层的 ra 会覆盖本层 ra
    mv   t1, a0           # 暂存 fact(n-1)
    ld   a0, 0(sp)        # 取回本层 n
    ld   ra, 8(sp)        # 取回本层返回地址
    addi sp, sp, 16
    mul  a0, a0, t1       # a0 = n * fact(n-1)
    jalr zero, 0(ra)
```

![[co-ch3-XYw3FYUD.png]]
保存理由：
- **`ra` 必须保存**：本层执行 `jal ra, fact` 后，`ra` 变为本层递归调用的下一条地址；若不保存，最初 caller 的返回地址就丢了。
- **`n` 必须保存**：`a0` 既要传给下一层，又承载下一层返回值，原 `n` 会被覆盖；回来后还要用它做乘法。
- **基本情况可直接释放帧**：该路径没有再次改写 `ra`，也不再需要旧 `n`，所以无需先 load 再丢弃。

> [!note] ABI 严谨性补充
> 上面的教学版与讲义一致，用 `t1` 跨“恢复本层数据”的若干指令保存子调用结果，返回前不再调用其他函数，因此没有新的调用会覆盖它。若乘法前还要调用别的函数，就不能假设 `t1` 会保留，应使用已保存的 `s*` 或栈槽。
### 9.6 非叶排序过程中的保存集合
讲义 `sort` 调用 `swap`，并使用 `s0`（`i`）、`s1`（`j`）、`s2`、`s3` 等保留寄存器，因此 prologue 保存：
- `ra`：因为 `sort` 自己还要返回，而调用 `swap` 会写 `ra`；
- 实际使用的 `s*`：因为 caller 期望这些寄存器调用前后不变；
- 必要时 caller 还需保存自己跨调用使用的 `a*` / `t*`，或先把长期值放进已保存的 `s*`。
这体现了三步翻译方法：**分配变量到寄存器 → 生成过程体 → 按调用约定保护寄存器**。

## 10. 字符、字符串与宽位访问
### 10.1 字符编码与字节访问
讲义区分：
- ASCII：基础字符集，用单字节编码常见英文字母、数字和控制字符。
- Latin-1：8 位编码，在 ASCII 基础上增加西欧字符。
- Unicode：为字符分配码点；UTF-8、UTF-16 是可变长度编码方案，不应把“Unicode 字符”简单等同为固定的 32 位内存单元。
字符数组通常按字节处理，所以字符串循环中的地址增量是 1，而不是 4 或 8。
### 10.2 Load 的扩展规则
RV64 从内存读入较窄数据时，要明确怎样填满 64 位目的寄存器：

| 指令 | 读取宽度 | 扩展到 64 位的方式 |
|---|---:|---|
| `lb` | 8 位 | 符号扩展 |
| `lh` | 16 位 | 符号扩展 |
| `lw` | 32 位 | 符号扩展 |
| `ld` | 64 位 | 无需扩展 |
| `lbu` | 8 位 | 零扩展 |
| `lhu` | 16 位 | 零扩展 |
| `lwu` | 32 位 | 零扩展 |

例如内存字节 `0xFF`：`lb` 得到 −1（64 位全 1），`lbu` 得到 +255。处理 ASCII 字节常用 `lbu`，处理有符号 8 位整数则用 `lb`。
### 10.3 Store 保存低位

| 指令 | 写入内存的内容 |
|---|---|
| `sb rs2, off(rs1)` | `rs2` 最低 8 位 |
| `sh rs2, off(rs1)` | 最低 16 位 |
| `sw rs2, off(rs1)` | 最低 32 位 |
| `sd rs2, off(rs1)` | 整个 64 位 |

store 不需要“符号扩展版本”，因为它只截取寄存器右端若干位，不产生更宽的结果。
### 10.4 字符串复制：逐字节拷贝并检查 `'\0'`

```c
void strcpy(char x[], char y[]) {
    size_t i = 0;
    while ((x[i] = y[i]) != '\0')
        i += 1;
}
```

`x`、`y` 的基址分别在 `a0`、`a1`，若用 `s3` 保存 `i`：

```asm
strcpy:
    addi sp, sp, -16      # 教学版额外保留 ABI 栈对齐
    sd   s3, 0(sp)        # s3 是 callee-saved
    add  s3, zero, zero   # i = 0
L1:
    add  t0, s3, a1       # &y[i]
    lbu  t1, 0(t0)        # 读一个字节并零扩展
    add  t2, s3, a0       # &x[i]
    sb   t1, 0(t2)        # 先完成拷贝
    beq  t1, zero, L2     # 拷到 NUL 就结束
    addi s3, s3, 1
    jal  zero, L1
L2:
    ld   s3, 0(sp)
    addi sp, sp, 16
    jalr zero, 0(ra)
```

![[co-ch3-607BHJlv.png]]
这是叶过程，若编译器把 `i` 分到未使用的 `t3`，就可以省去保存 `s3` 的栈操作。优化原则是先利用临时寄存器，再承担保存/恢复保留寄存器的成本。

## 11. 32 位常数与地址
### 11.1 为什么需要两条指令
I 型立即数只有 12 位，而 U 型可设置高 20 位。常见的 32 位常数构造是：

```asm
lui  rd, upper20
addi rd, rd, lower12_signed
```

`addi` 会把低 12 位看作**有符号数**。因此若目标低 12 位在 `0x800`–`0xFFF`，直接把它当正数写不合法，且其符号扩展会从高位“借 1”；高位字段要预先加 1。
### 11.2 例：构造十进制 4,000,000
目标：
$$4{,}000{,}000=976\times4096+2304=\mathtt{0x003D0900}$$
低 12 位是 `0x900 = 2304`，其最高位为 1，作为 I 型有符号立即数应解释为：
$$2304-4096=-1792$$
所以正确写法是：

```asm
lui  s3, 977            # 977 = 0x3D1；先得到 0x003D1000
addi s3, s3, -1792      # 0x003D1000 - 0x700 = 0x003D0900
```

若写成 `lui s3, 976; addi s3, s3, 2304`，`2304` 已超出 `addi` 的正数范围。讲义该页在十进制立即数展示上容易造成误解，以上使用可由 12 位字段合法编码的 −1792。
同理，构造 `0x12345FFF` 可写：

```asm
lui  t0, 0x12346
addi t0, t0, -1         # 结果为 0x12345FFF
```

### 11.3 地址构造与 `auipc`
- **绝对地址思路**：`lui` 形成地址高位，`jalr` 加低 12 位并跳转；低 12 位同样要处理符号调整。
- **PC 相对思路**：`auipc` 形成离当前 PC 的高位地址，再由 `addi`、`ld` 或 `jalr` 加低位，常用于位置无关代码。
概念示例：

```asm
.L0:
    auipc t0, %pcrel_hi(symbol)
    addi  t0, t0, %pcrel_lo(.L0)  # 关联到上面的 auipc 标签
```

实际 `%hi/%lo`、`%pcrel_hi/%pcrel_lo` 等表达式由汇编器和链接器结合重定位信息计算，程序员不必手工把每一次地址修补写成固定常数。

## 12. 同步：LR-SC 与锁
### 12.1 数据竞争与原子性
若两个处理器共享内存，P1 写、P2 读，而没有同步，最终结果可能依赖访问交错顺序，这就是数据竞争。实现锁或原子交换需要一种机制，让“读出旧值—判断—写入新值”不会被别的写操作悄悄插入。
RISC-V A 扩展提供保留加载和条件存储：

```asm
lr.d rd, (rs1)          # rd = Memory[rs1]，并建立 reservation
sc.d rd, rs2, (rs1)     # 若 reservation 仍有效则 Memory[rs1] = rs2
                        # 成功时 rd = 0；失败时 rd 非 0，内存不完成该次写入
```

`sc.d` 失败必须重试。把“reservation 失效”简单理解为地址被改写有助于入门；真实实现还可能因其他架构允许的事件而失败，所以软件不能只重试一次或假定必然成功。
### 12.2 原子交换

```asm
# a0 指向锁变量，a1 是希望写入的新值
again:
    lr.d t0, (a0)        # 读旧值
    sc.d t1, a1, (a0)    # 尝试写新值
    bne  t1, zero, again # 条件存储失败则重来
    mv   a1, t0          # 取回旧值
```

从软件效果看，旧值读取与新值写入构成一个原子交换，而不是两条可任意交错且仍保证正确的普通 load/store。
### 12.3 用 LR/SC 获取和释放锁

```asm
# a0 指向 lock：0 表示空闲，1 表示已占用
    addi t0, zero, 1
acquire:
    lr.d t1, (a0)
    bne  t1, zero, acquire  # 已被占用，继续检查
    sc.d t2, t0, (a0)
    bne  t2, zero, acquire  # 抢到一半失败，重试
    # critical section：获得锁后的临界区
    sd   zero, 0(a0)        # release：写回 0
```

讲义用此例说明原子指令怎样支撑互斥。工程实现还要考虑内存顺序、公平性和忙等待开销，常使用带 acquire/release 语义的原子指令或 fence；不能把这段教学代码当作所有平台上的高性能锁实现。

## 13. 从 C 到执行：编译、汇编、链接、装载
### 13.1 工具链全景

```text
C 源文件
   │  compiler
   ▼
汇编文件
   │  assembler
   ▼
机器语言目标模块 ──┐
                  ├─ linker ─→ 可执行文件 ─ loader ─→ 内存中的进程
库目标模块 ────────┘
```

- **编译器**：完成语义分析、优化、寄存器分配，并生成汇编或目标代码。
- **汇编器**：把助记符和伪指令翻译成机器指令，处理局部标签，生成目标模块。
- **链接器**：合并多个目标模块和库，确定符号地址，修补引用。
- **装载器**：把可执行映像需要的代码、数据带入虚拟地址空间，做好初始状态并转入启动代码。
### 13.2 目标模块包含什么
一个目标文件不仅是连续的 0 和 1，通常还含：

| 组成 | 作用 |
|---|---|
| Header | 描述目标模块内容、各段大小等 |
| Text segment | 翻译后的指令 |
| Static data segment | 生命周期覆盖程序运行期的已初始化静态数据 |
| Relocation information | 哪些字段依赖最终地址、需要怎样重定位 |
| Symbol table | 本模块定义的全局符号与需要外部解析的引用 |
| Debug information | 把机器代码与源代码位置关联，便于调试 |

例如模块内 `ld a0, 0(gp)` 依赖数据符号 `X`，`jal ra, B` 依赖外部过程 `B`。若地址尚未确定，汇编器记录重定位项，而不是编造一个最终地址。
### 13.3 链接的三个核心动作
1. 把各模块的代码和数据安排到输出映像中。
2. 确定全局数据与指令标签的地址，解析外部符号。
3. 根据重定位信息修补内部和外部引用，如调用目标、全局数据地址。
**静态链接**在生成可执行文件时纳入所需库代码；**动态链接**把部分库解析推迟到装载时或调用时，可减小映像、共享库代码并更新库版本，但要求代码可重定位，并引入运行时解析成本。
### 13.4 装载器怎样启动程序
讲义的装载步骤可整理为：
1. 读取可执行文件头，确定代码段和数据段大小。
2. 创建虚拟地址空间。
3. 复制 text 与已初始化数据到内存，或建立页表项，等缺页时再调入。
4. 在栈上准备命令行参数等启动信息。
5. 初始化寄存器，包括合适的 `sp`，并由运行环境设置其他必要状态。
6. 跳到启动例程；启动代码准备参数并调用 `main`，`main` 返回后执行退出系统调用。
常见进程内存布局是：

```text
高地址  栈：过程帧、automatic 局部数据，通常向低地址增长
        动态数据：堆，由 malloc / new 等管理
        静态数据：全局与 static 对象、常量数据等
低地址  代码 text 与保留区域
```

`gp` 可被运行环境初始化到静态数据附近，以支持带小偏移的全局访问；具体布局由 ABI、操作系统和链接脚本共同决定，不是所有 RISC-V 程序都只有同一张固定地址图。
![[co-ch3-HgSNu9rL.png]]
### 13.5 Java 的另一种执行路径
讲义还以 JVM 为例：字节码提供可移植指令集，虚拟机可解释执行，并把“热点”方法 JIT 编译为宿主机器码。它并不改变本章主线——无论直接编译 C 还是即时编译字节码，最终仍要落到某种机器指令与执行约定上。

## 14. 伪指令与真实指令
### 14.1 为什么要区分
**真实指令**有架构规定的操作码和机器编码；**伪指令**是汇编器提供的便捷写法，会被展开成一条或多条真实指令。伪指令让汇编更易读写，但不代表硬件新增了一个操作。

| 伪指令 | 常见展开 | 说明 |
|---|---|---|
| `nop` | `addi x0, x0, 0` | 结果写 `x0`，无架构状态变化 |
| `mv rd, rs` | `addi rd, rs, 0` | 寄存器复制 |
| `not rd, rs` | `xori rd, rs, -1` | 与全 1 异或 |
| `neg rd, rs` | `sub rd, x0, rs` | 0 减源寄存器 |
| `li rd, small` | `addi rd, x0, small` | 仅限能直接编码的小立即数情形 |
| `li rd, large` | `lui` + `addi` 等 | 具体序列由常数大小和汇编器决定 |
| `j label` | `jal x0, label` | 不保存返回地址 |
| `jr rs` | `jalr x0, 0(rs)` | 寄存器间接跳转 |
| `ret` | `jalr x0, 0(ra)` | 过程返回 |
| `beqz rs, label` | `beq rs, x0, label` | 与 0 比较 |
| `bnez rs, label` | `bne rs, x0, label` | 与 0 不等 |
| `bgt rs, rt, label` | `blt rt, rs, label` | 交换操作数，有符号 |
| `ble rs, rt, label` | `bge rt, rs, label` | 交换操作数，有符号 |
| `la rd, symbol` | 常为 `auipc` + `addi` 等 | 依地址模型、重定位与是否 PIC 而定 |

![[co-ch3-ABLaJ0cn.png]]
注意两种“不是新硬件指令”的情况：
- `j` 是伪指令，但展开后的 `jal x0, label` 是真实 J 型指令。
- `beq x0, x0, label` 本身就是真实 B 型指令，也能无条件跳转；不要为了统一而把两种写法混为一谈。
反汇编器可能把真实机器码显示成伪指令，以便阅读。因此看到 `ret`，仍应知道机器里执行的是 `jalr x0, 0(x1)`。

## 15. 我的理解与思考

> [!note] 个人归纳
> 本节是我对本章的整理与推演，不是讲义原文。核心观点是：**ISA 是硬件与软件之间的契约，编码是契约的位级形式，ABI 则是软件模块之间的契约。**
### 15.1 ISA 契约：稳定的是语义，不是某一种实现
我把 ISA 看成一道边界：
- 对硬件实现者，它规定指令结果、寄存器行为、异常与地址语义等必须遵守的可见效果。
- 对编译器和汇编程序员，它提供可以依赖的能力，却不承诺某颗芯片有几级流水线、多大缓存。
- 对工具链，它提供稳定的机器码目标，使同一套二进制兼容性可以跨不同微架构延续。
所以“某指令几条周期完成”通常不是本章 ISA 语义本身，而是微架构问题。把二者分开，才能理解为什么 RISC-V 可以保持软件兼容，同时允许不同性能和成本的实现。
### 15.2 编码规整为什么服务流水线
初看 B/J 立即数排列很“反人类”，但站在硬件角度，我认为它是在优化**每条的共同工作**：
1. `opcode` 固定在低位，取指后可立即开始主译码。
2. `rs1`、`rs2` 在 R/I/S/B 中尽量保持同位段，寄存器堆读地址可更早形成，甚至与进一步译码并行。
3. 各立即数最高符号位都来自 `inst[31]`，符号扩展不必等待完全不同的格式判断。
4. 基础指令定长，让下一条顺序指令地址容易计算，取指与 PC 更新更规则。
5. B/J 复用本来会被其他格式用于寄存器的位段来容纳偏移，是在 32 位总预算内做折中。
因此“字段整齐”不是为了让背诵容易，而是减少译码扇出、数据通路选择和关键路径依赖。C 扩展提高代码密度，也说明定长 32 位不是 RISC 的唯一可能；架构会在取指复杂度与代码体积之间继续折中。
### 15.3 为什么 load/store 分离也关乎简单实现
`add t0, t1, t2` 只需要寄存器与 ALU；`ld` 则需要有效地址和内存系统。若允许每条算术指令都随意带内存源操作数，内存延迟会渗入更多指令的执行路径，流水线调度与异常处理也更复杂。
load/store 分离把“算”与“搬”显式化：
- 硬件可为不同指令建立更规则的数据通路。
- 编译器看清哪些值值得留在寄存器，何时必须 spill。
- 程序员能从指令序列中直接看到访存次数，而不是被一条复杂指令掩盖。
### 15.4 ABI 是软件契约：寄存器用途不是硬件自动管理
硬件不会因为寄存器叫 `s0` 就自动保存它，也不知道 C 语言“函数”的边界。`a0`、`ra`、`sp` 的名字只有配合约定才有意义。
我认为 ABI 的价值体现在三件具体事情上：
- **分别编译**： caller 与 callee 不必知道对方全部内部实现，只要共同遵守参数、返回和保存规则。
- **库与递归**：只要每层恢复该恢复的状态，多层调用就能像协议一样叠加。
- **优化空间**：叶过程少保存、只保存实际使用的 `s*`、把短生命周期值放 `t*`，都是利用契约减少成本，而不是违反契约。
递归阶乘最能说明这一点：`jal` 只给了一个 `ra`，并没有给整个调用历史。多层返回地址必须由软件借栈保存。栈不是某种神秘硬件队列，而是内存加 `sp` 加约定共同构成的数据结构。
### 15.5 立即数设计体现“常见情况优先”
小常数直接编码，避免一次 load；大常数用 U 型与 I 型组合；短分支用 PC 相对偏移，远跳再付出额外指令。我的理解是，ISA 不追求“一种写法覆盖所有长度”，而是让**短情况短、长情况可构造**。
PC 相对偏移还减少对绝对地址的依赖，与重定位、位置无关代码自然相连。`auipc` 的存在尤其说明：地址构造不仅是“常数太大怎么办”，也关系到程序能否被放到不同地址运行。
### 15.6 手写汇编不等于高性能
讲义最后提醒：复杂指令不必然更快，手写汇编也不必然优于编译器。现代编译器能做寄存器分配、强度削减、循环优化；程序员手写更多指令，反而可能增加错误。
数组清零例中，指针版避免每次重新计算 `base + 8*i`，但编译器也可通过归纳变量优化把清晰的数组写法改成类似形式。因此我更喜欢先写语义清楚的代码，再根据测量和反汇编处理真正的热点。

## 16. 考点速查
### 16.1 必背概念与数字
1. **存储程序**：指令是数，程序像数据一样放内存；ISA 标准支持二进制兼容。
2. **四原则**：简单源于规整；越小越快；常见情况优先；好设计需要好折中。
3. **课程编码范围**：RV64I 基础指令 32 位；RISC-V 还有 RVC 16 位编码，不能说整个 ISA 全部 32 位。
4. **寄存器**：`x0` 恒零；`x1=ra`，`x2=sp`，`x10–x17=a0–a7`；`t*` call-clobbered，`s*` callee-saved。
5. **保存责任**：caller 保存自己仍需使用的临时/参数值；callee 只保存并恢复自己改写的 `s*`；非叶过程通常保存 `ra`。
6. **栈**：向低地址增长；`addi sp,sp,-8` 后保存到 `0(sp)`；返回前恢复 `sp`，实际 ABI 注意 16 字节对齐。
7. **内存**：字节编址；doubleword 相邻地址差 8；word 差 4；小端是最低有效字节在最低地址。
8. **扩展**：`lb/lh/lw` 符号扩展，`lbu/lhu/lwu` 零扩展；`sb/sh/sw` 只存最低 8/16/32 位。
9. **六种格式**：R/I/S/B/U/J 字段布局必须会画；`rs1` 在 19:15，`rs2` 在 24:20，`rd` 常在 11:7。
10. **Branch 与 `jalr` opcode 不同**：Branch `1100011`，`jalr 1100111`；`sd` 的 `funct3 = 011`。
### 16.2 必会计算
1. **有效地址**：`ld rd, off(rs1)` 使用 `EA = rs1 + sext(off)`；数组偏移是下标乘元素字节数。
2. **R 型编码**：依次拼 `funct7 | rs2 | rs1 | funct3 | rd | opcode`，再每 4 位转十六进制。
3. **I/S 立即数**：12 位有符号，范围 −2048～2047；S 型把位 `11:5` 与 `4:0` 分放两处。
4. **B/J 立即数**：是**字节偏移**；编码省略恒为 0 的 `imm[0]`，解码重排后补 0，不是笼统计作“2 字节单位”。
5. **分支目标**：`target = 当前分支指令 PC + offset`；`jal` 写回 `pc+4`，但目标同样相对当前 `pc`。
6. **范围**：B 为 −4096～+4094 字节，J 为 −1,048,576～+1,048,574 字节，均按 2 字节步进。
7. **大常数**：`lui + addi`；低 12 位 ≥ `0x800` 时高位字段加 1，低位写成对应负有符号立即数。
8. **反汇编**：先看 opcode 定格式，再看 funct 定操作，最后把寄存器编号映射到 ABI 名；`x16=a6`，不是 `a7`。
### 16.3 必会编程与解释
1. 能把 `if/else`、循环、数组下标、`swap`、字符串复制翻成汇编。
2. 能解释 `blt/bge` 与 `bltu/bgeu` 的差异；`bgt/ble` 是交换操作数的伪指令。
3. 能写出 `jal ra, fact` 与 `jalr zero, 0(ra)` 的调用/返回配对，并解释递归为何保存 `ra` 和原参数。
4. 能识别 `mv`、`li`、`j`、`ret`、`beqz` 等伪指令的真实展开。
5. 目标太远时，用**反转条件分支 + `jal`**扩展距离。
6. `lr.d/sc.d` 属于 A 扩展；`sc.d` 成功写 0，失败写非 0，失败必须重试。
7. 工具链顺序：compiler → assembler → linker → loader；目标文件的重定位表和符号表分别解决“怎样改地址”和“符号在哪里/需要谁”。
8. **常见陷阱**：返回局部 automatic 变量指针会悬空；复杂指令和手写汇编都不必然带来高性能。
