## 1. 从 ISA 到处理器实现

### 1.1 CPU 的两个核心部分

CPU 可先从功能上分成：

- **数据通路（datapath）**：真正加工数据与地址的部件，包括 PC、寄存器堆、ALU、存储器、加法器与多路选择器等。
- **控制单元（control unit）**：依据指令产生控制信号，决定 ALU 做什么、MUX 选哪一路、寄存器或存储器是否写入。

![[co-ch4-8m8KK7Ar.png]]

同一套数据通路要支持不同指令，不能把多个数据来源直接接在一起；必须使用 MUX，并由控制单元决定选择信号。

### 1.2 本讲实现的 RISC-V 子集

讲义的基本实现覆盖：

| 类别 | 指令 | 所需核心动作 |
|---|---|---|
| R 型 | `add, sub, and, or` | 读两个寄存器，ALU 运算，写 `rd` |
| 访存 | `ld, sd` | 基址加偏移；`ld` 读内存并写回，`sd` 写内存 |
| 条件分支 | `beq` | 比较两个寄存器，选择 `PC+4` 或分支目标 |
| 实验扩展 | `xor, slt, srl`；`addi` 等 I 型；`sw`；`jal` | 扩展 ALU 译码、立即数生成与跳转写回 |

ISA 是硬件与软件之间的约定：它规定寄存器、指令语义、编码与寻址方式；数据通路和控制则给出一种具体实现。相同 ISA 可以对应单周期、流水线、顺序多发射或乱序处理器。

### 1.3 指令执行概况

每条指令开头都做两类工作：

1. 按 PC 从指令存储器取指；
2. 译码并读取寄存器操作数。

后续动作由指令类别决定：ALU 可能计算算术结果、访存地址或分支比较；load/store 访问数据存储器；PC 最终选择顺序地址或控制转移目标。

> [!warning] “五阶段”不是“每条指令都做五件事”
> IF、ID 是共同步骤；只有 load/store 真正访问数据存储器，只有需要写寄存器的指令才执行有效 WB。`sd` 没有寄存器写回，R 型没有数据访存，`beq` 通常既不写数据寄存器也不访问数据内存。把它们画成经过五级，是为了统一流水线路径与时序，而不是说每级都有有效副作用。

### 1.4 性能三要素

程序在 CPU 上的执行时间为

$$\text{CPU Time}=IC\times CPI\times T_c=\frac{IC\times CPI}{f}. \tag{4.1}$$

- **指令数 $IC$**：主要受 ISA、编译器和程序本身影响。
- **平均每条指令周期数 $CPI$**：受数据通路、冒险、停顿与多发射影响。
- **时钟周期 $T_c$**：由关键路径、流水线划分、硬件工艺等决定。

ISA 与编译器也会影响实现难度，所以三项并非完全独立；优化时不能假设改变其中一项，其余两项必然不变。

## 2. 逻辑设计约定与单周期数据通路

### 2.1 组合逻辑与状态单元

**组合元件**的输出是当前输入的函数，例如：

- 与门：$Y=A\mathbin{\&}B$；
- 加法器：$Y=A+B$；
- ALU：$Y=F(A,B)$；
- MUX：$Y=S?I_1:I_0$。

**状态（时序）元件**保存信息，例如寄存器、PC 与存储器。带写控制的寄存器只在时钟边沿且写使能有效时更新。

本讲采用边沿触发：在一个时钟周期内，状态单元输出经组合逻辑变换，再在下一有效边沿写回状态单元。**两个边沿之间最长组合延迟决定最小时钟周期。**

### 2.2 取指通路

取指需要三个基本元素：

```text
PC ──→ 指令存储器 ──→ Instruction
 │                         │
 └──→ 加法器：PC + 4 ──────┴──→ 下一 PC 的候选
```

PC 保存当前指令地址；指令存储器按地址输出指令；独立加法器计算 `PC+4`。本讲基础 RISC-V 指令均为 32 位，所以顺序地址每次加 4。

### 2.3 寄存器堆与立即数生成

RISC-V 有 `x0`–`x31` 共 32 个整数寄存器，`x0` 恒为 0。算术逻辑指令的操作数先放入寄存器；存储器只由数据传输指令访问。

寄存器堆的基本端口为：

- 两个读寄存器编号 `rs1, rs2`；
- 两路读数据 `Read data 1, Read data 2`；
- 写寄存器编号 `rd`、写数据 `Write data`；
- 写使能 `RegWrite`。

Imm Gen 从指令中抽取并重排立即数字段，再扩展成机器字长。不同格式不能只记成统一的 `inst[31:20]`：

| 格式 | 立即数的拼接要点 | 用途 |
|---|---|---|
| I 型 | 符号扩展 `inst[31:20]` | `ld`、`addi` 等 |
| S 型 | 拼接 `inst[31:25]` 与 `inst[11:7]` | `sd`、`sw` |
| B 型 | 重排符号位及分散字段，末位补 0 | `beq` 等 PC 相对分支 |
| J 型 | 重排 20 位立即数字段，末位补 0 | `jal` |

分支与跳转位移按半字为单位编码，因此生成字节地址偏移时隐含左移一位。实际硬件是对编码字段重排并补 `imm[0]=0`，不是把已经生成的完整字长数再任意移一次。

### 2.4 从局部通路到完整通路

完整单周期数据通路通过 MUX 支持多类指令：

- ALU 第二操作数选 `Read data 2` 或立即数；
- 寄存器写回数据选 ALU 结果、内存读数或 `PC+4`；
- 下一 PC 选 `PC+4`、分支目标或跳转目标；
- 存储器读、写和寄存器写分别由控制信号门控。

![[co-ch4-nfSQAg0L.png]]

![[co-ch4-w8O0EH27.png]]

一个数据通路元件在一个时刻只能承担规定的一项功能。单周期中指令存储器访问与数据存储器访问可能同时出现在同一条 `ld/sd` 的路径上，因此使用分离的指令、数据存储器。

## 3. 各类指令的数据通路

### 3.1 R 型：寄存器—ALU—寄存器

以 `add x9,x20,x21` 为例：

1. IF：取指，计算 `PC+4`。
2. ID：读 `rs1=x20`、`rs2=x21`，主控制器识别 R 型。
3. EX：ALU 两个输入都来自寄存器堆，按 `funct3/funct7` 执行加法。
4. WB：`RegWrite=1`，把 ALU 结果写入 `rd=x9`。
5. PC：没有分支或跳转，采用 `PC+4`。

有效通路为

```text
IM → 译码/寄存器堆读 → ALU → 写回 MUX → 寄存器堆写
```

这类指令不读 Imm Gen 作为 ALU 第二输入，不访问数据存储器。

### 3.2 I 型算术：第二操作数换成立即数

以 `addi x1,x2,4` 为例，路径与 R 型相似，但：

- 只读取一个源寄存器 `x2`；
- Imm Gen 符号扩展 12 位立即数 `4`；
- `ALUSrc=1`，ALU 第二输入选立即数；
- 运算结果写回 `x1`。

所以 I 型不是“必定 load”，load 只是 I 型编码的一种用途。

### 3.3 Load：完整使用五段功能

以 `ld x1,200(x2)` 为例：

1. 取指并准备 `PC+4`。
2. 读基址寄存器 `x2`，生成立即数 `200`。
3. ALU 加法得到有效地址 $x2+200$。
4. 数据存储器按该地址读出一个双字。
5. 写回 MUX 选择内存读数，写入 `x1`。

关键控制为 `ALUSrc=1`、`MemRead=1`、`RegWrite=1`、`MemtoReg` 选择内存、`MemWrite=0`。

![[co-ch4-amfocLym.png]]

Load 同时包含地址计算、数据访存和寄存器写回，因此是本讲单周期模型中最长路径。

### 3.4 Store：有访存，无寄存器写回

以 `sd x1,200(x2)` 为例：

1. 读基址 `x2` 与待存数据 `x1`；
2. ALU 计算 $x2+200$；
3. 数据存储器的地址来自 ALU，写数据来自第二个寄存器读端口；
4. `MemWrite=1`，在时钟控制下写内存；
5. `RegWrite=0`，没有 WB 副作用，PC 顺序前进。

Store 的 `rs2` 字段是数据来源，不是目标寄存器；S 型立即数又占用了 R 型的 `rd` 位置，不能误把它当成写回编号。

### 3.5 BEQ：比较与目标地址并行准备

以 `beq x1,x2,offset` 为例：

- 主 ALU 做 $x1-x2$，用 Zero 判断两个操作数是否相等；
- 另一条加法通路计算 $PC+\text{sign-extended offset}$；
- 若 Branch 有效且满足相等条件，下一 PC 选目标地址，否则选 `PC+4`；
- 不写通用寄存器，也不访问数据存储器。

可将选择逻辑概括为

$$PC_{\text{next}}=
\begin{cases}
PC+\text{offset}, & \text{Branch}\land\text{condition true},\\
PC+4, & \text{otherwise}.
\end{cases} \tag{4.2}$$

更一般的 `bne/blt/bge` 不能只靠同一个 Zero 位，需要相应的比较条件；本讲简化通路重点展示 `beq`。

### 3.6 JAL：同时写返回地址与改变 PC

`jal x1,procedure` 做两件事：

1. 将 `PC+4` 写入 `rd=x1`，保存返回地址；
2. 将 PC 更新为 $PC+\text{J 型偏移}$。

因此需要额外的写回选择 `PC+4` 和 Jump 控制。若写 `jal x0,label`，仍发生跳转，但 `x0` 不保存返回地址。

## 4. 主控制与 ALU 控制

### 4.1 为什么采用二级译码

32 位指令同时提供 opcode、寄存器编号、funct 字段和立即数。控制器的职责包括：

- 决定 ALU 的基本用途；
- 控制寄存器与存储器读写；
- 控制 MUX 的数据来源；
- 根据分支、跳转语义选择下一 PC。

讲义把译码分成两层：

```text
opcode ─→ 主控制器 ─→ ALUSrc、MemtoReg、RegWrite、MemRead、
                       MemWrite、Branch、Jump、ALUOp
                              │
funct3 + funct7 ──────────────┴─→ ALU 控制器 ─→ ALU 具体操作
```

主控制器看“指令属于哪一类”，ALU 控制器进一步看“这一类中的哪一种运算”。

### 4.2 主要控制信号

| 信号 | 无效或基本含义 | 有效时的作用 |
|---|---|---|
| `RegWrite` | 不写寄存器 | 将写回数据写入 `rd` |
| `ALUSrc` | ALU 第二输入来自 `Read data 2` | 来自 Imm Gen |
| `MemRead` | 不读数据存储器 | 读取有效地址处的数据 |
| `MemWrite` | 不写数据存储器 | 将第二个寄存器读数写入有效地址 |
| `MemtoReg` | 选择 ALU 结果 | load 选择内存读数；扩展实现还可选 `PC+4` |
| `Branch` | 非条件分支 | 与条件判断共同决定是否选分支目标 |
| `Jump` | 不执行无条件跳转 | 选择跳转目标 |
| `ALUOp` | 编码指令类别 | 与 funct 字段共同确定 ALU 控制 |

原笔记中的扩展 `MemtoReg` 编码为：`00` 选 ALU 结果、`01` 选数据内存、`10` 选 `PC+4`。`PCSrc` 是下一 PC 选择的逻辑结果，由 Branch 与条件成立共同产生，不应简单理解为“Branch=1 就必定跳转”。

### 4.3 典型指令控制方向

下表用“动作”而非某个实验工程的固定二进制编码总结，避免不同端口定义造成混淆：

| 指令 | ALU 第二输入 | ALU 动作 | 数据内存 | 寄存器写回 | 下一 PC |
|---|---|---|---|---|---|
| R 型 | `rs2` | funct 决定 | 不访问 | ALU 结果 → `rd` | `PC+4` |
| I 型算术 | 立即数 | funct 决定 | 不访问 | ALU 结果 → `rd` | `PC+4` |
| `ld` | 立即数 | 加 | 读 | 内存数据 → `rd` | `PC+4` |
| `sd` | 立即数 | 加 | 写 | 无 | `PC+4` |
| `beq` | `rs2` | 减并比较 | 不访问 | 无 | 条件决定 |
| `jal` | 不必使用主 ALU | — | 不访问 | `PC+4` → `rd` | 跳转目标 |

> [!warning] 默认控制值要能安全失效
> 未识别指令或插入气泡时，不应让 `RegWrite/MemWrite` 随意有效。将控制信号清零的目的，是使后续阶段等价于 nop，不产生体系结构状态改变。

### 4.4 ALU 控制表

讲义的基础控制编码示例为：

| ALU 控制线 | 操作 |
|---|---|
| `0000` | AND |
| `0001` | OR |
| `0010` | add |
| `0110` | subtract |

load/store 一律需要地址加法；`beq` 需要减法比较；R 型则由 `ALUOp` 结合 `funct3/funct7` 进一步选择。扩展到 AND、OR、加减之外的 XOR、SLT、SRL 时，控制码位数与真值表可随具体实现扩展，不能把另一张图的 3 位码与本表机械混用。

## 5. 单周期关键路径与性能

### 5.1 为什么 CPI=1 仍可能很慢

单周期实现中，每条指令都在一个周期内完成，所以理想 $CPI=1$。但所有指令使用同一个周期长度，它必须容纳**最慢指令的最长数据通路**，快指令也只能等待本周期结束。

这违背“让常见情况更快”的直觉：即使程序中 load 并不多，周期也得按 load 设计。不能简单地给不同指令分配不同长度的同一时钟周期。

### 5.2 讲义延迟模型

忽略其他延迟，设：

- 指令或数据存储器：200 ps；
- ALU 与加法器：200 ps；
- 寄存器堆读或写：100 ps。

| 指令 | 主要路径 | 总延迟 |
|---|---|---:|
| `ld` | IM → RF 读 → ALU → DM → RF 写 | $200+100+200+200+100=800$ ps |
| `sd` | IM → RF 读 → ALU → DM | $700$ ps |
| R 型 | IM → RF 读 → ALU → RF 写 | $600$ ps |
| `beq` | IM → RF 读 → ALU 比较 | $500$ ps |

![[co-ch4-NwWf9hns.png]]

因此 $T_c=800$ ps。这里的路径求和针对题目给定的简化模型；目标地址加法器等若能与主路径并行，不应无依据地重复串接。

### 5.3 数值例：不能只比 CPI

> [!note] 例 4.A：单周期与五级流水线的总时间
> 某程序有 $IC=10^6$ 条指令。单周期实现 $T_c=800$ ps、$CPI=1$；流水线实现最慢级为 200 ps，因停顿与预测错误，实际 $CPI=1.25$。忽略其他差异，比较运行时间与加速比。

单周期：

$$T_{\text{single}}=10^6\times1\times800\text{ ps}=0.8\text{ ms}.$$

流水线：

$$T_{\text{pipe}}=10^6\times1.25\times200\text{ ps}=0.25\text{ ms}.$$

所以

$$S=\frac{0.8}{0.25}=3.2.$$

流水线并没有达到理想的 $800/200=4$ 倍，因为实际 CPI 从 1 上升到 1.25。反过来，也不能因流水线 CPI 较大就说它更慢；周期缩短必须一并考虑。

### 5.4 平均 CPI 的计算

若指令分若干类，第 $i$ 类在动态指令流中占 $p_i$、平均 CPI 为 $CPI_i$，则

$$CPI_{\text{avg}}=\sum_i p_iCPI_i. \tag{4.3}$$

停顿、flush 与未利用的发射槽都可折算为额外周期。使用“静态指令条数”还是“动态执行条数”必须分清：性能公式中的 IC 是实际执行的动态指令数。

## 6. 五级流水线与流水线寄存器

### 6.1 五级的职责

| 阶段 | 名称 | 基本工作 |
|---|---|---|
| IF | Instruction Fetch | 从指令存储器取指，计算下一 PC 候选 |
| ID | Instruction Decode / Register Read | 译码、读寄存器、生成立即数 |
| EX | Execute / Address Calculation | ALU 运算或地址计算；具体实现也可做分支判断 |
| MEM | Memory Access | load 读、store 写数据存储器 |
| WB | Write Back | 将结果写入寄存器堆 |

稳定后，理想单发射五级流水线每周期可开始一条新指令，也可完成一条旧指令。五阶段是指令在数据通路中的位置；无有效 MEM/WB 工作的指令仍然向前流动，只是对应控制位无效。

### 6.2 为什么需要级间寄存器

如果直接把五级组合电路连起来，不同指令的信息会混杂。必须在级间保存上一周期产生的数据和控制：

```text
IF → IF/ID → ID → ID/EX → EX → EX/MEM → MEM → MEM/WB → WB
```

| 流水线寄存器 | 典型保存内容 |
|---|---|
| IF/ID | 取出的指令、当前 PC 等 |
| ID/EX | PC、两个寄存器读数、立即数、`rs1/rs2/rd`、EX/MEM/WB 控制 |
| EX/MEM | ALU 结果、Zero 或分支信息、store 写数据、目标、控制 |
| MEM/WB | 内存读数、ALU 结果、`rd`、WB 控制 |

**不仅要传数据，还要传使用时机较晚的信息。**例如 load 的 `rd` 必须一路传到 MEM/WB，否则 WB 时可能错误地使用当前下游指令的字段；讲义特别用“Wrong register number”与修正后的 load 数据通路说明这一点。

### 6.3 控制信号随指令前进

![[co-ch4-NIrsoPGm.png]]

控制信号仍在 ID 阶段译出，但不再直接控制整条单周期通路，而是随对应指令逐级传递：

- EX 阶段使用 `ALUSrc/ALUOp`；
- MEM 阶段使用 `Branch/MemRead/MemWrite`；
- WB 阶段使用 `RegWrite/MemtoReg`。

已经用过的信号不必继续传；尚未到使用阶段的信号必须保留在相应流水线寄存器中。

### 6.4 完整流水线数据通路

![[co-ch4-MN5uM6ID.png]]

两类“从右向左”的信息流值得特别注意：

- WB 把结果写回较左侧的寄存器堆；
- 分支结果可能回送并修改 PC。

它们反映了先前指令影响后续指令的途径，也是数据冒险与控制冒险的硬件背景。但不能把所有右到左连线都笼统称为冒险：前递连线本身正是解决数据冒险的手段。

## 7. 时空图、理想加速比与 ISA 权衡

### 7.1 两种流水线图

- **多周期时空图**：横轴为周期、纵轴为指令或资源，用格子表示每条指令在各周期处于哪个阶段，适合数停顿与气泡。
- **单周期流水线图**：固定某一个周期，在五级数据通路上标出此刻每条指令使用的资源，适合分析级间寄存器和结构冲突。

读图先看格子属于“哪条指令、哪个周期”，不要把一条指令的总延迟误认为每级都在同一周期完成。

### 7.2 逐周期例：五条指令的理想流动

> [!note] 例 4.B：由时空图数周期
> 五条无冒险指令依次进入理想五级单发射流水线，求第一条和最后一条完成周期。

| 指令 \ 周期 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 |
|---|:-:|:-:|:-:|:-:|:-:|:-:|:-:|:-:|:-:|
| $I_1$ | IF | ID | EX | MEM | WB |  |  |  |  |
| $I_2$ |  | IF | ID | EX | MEM | WB |  |  |  |
| $I_3$ |  |  | IF | ID | EX | MEM | WB |  |  |
| $I_4$ |  |  |  | IF | ID | EX | MEM | WB |  |
| $I_5$ |  |  |  |  | IF | ID | EX | MEM | WB |

第一条在第 5 周期完成，第五条在第 9 周期完成。一般地，$n$ 条指令的理想周期数为

$$C=n+(5-1)=n+4. \tag{4.4}$$

前 4 个周期是填充成本；稳定后每周期完成一条。$n$ 很小时不能忽略填充，$n$ 很大时平均 CPI 才趋近 1。

### 7.3 洗衣房类比与理想加速比

![[co-ch4-gXlLw0vr.png]]

把洗衣、烘干、折叠等步骤分给不同设备，一批衣物可在不同阶段同时处理。流水线的收益是**吞吐率提高**，不是每件衣物从开始到结束的时间缩短。

讲义洗衣例子中，4 批任务的加速比为 $8/3.5\approx2.3$；持续处理时

$$S(n)=\frac{2n}{0.5n+1.5}\approx4,$$

趋近阶段数。对理想、均衡的 $k$ 级流水线，指令完成间隔约缩短到非流水线的 $1/k$；若级间不平衡，周期由最慢级决定，实际加速低于 $k$。

### 7.4 单条延迟并未降低

以上述延迟模型，load 单周期路径为 800 ps；理想五级流水线周期为 200 ps，一条 load 从取指到写回仍需 $5\times200=1000$ ps。加入流水线寄存器后还可能更大。

因此：

- 单条指令延迟：未减少，甚至增加；
- 稳态吞吐率：理想约提高 5 倍；
- 程序总时间：由 IC、实际 CPI、周期三者共同决定。

### 7.5 ISA 如何帮助或阻碍流水线

RISC-V 适合基础流水线的原因：

1. **本讲 RV64I 基础子集采用定长 32 位指令**：取指、对齐和 `PC+4` 简单；x86 指令可为 1–17 字节，取指与译码更复杂。
2. **格式少且规整**：寄存器字段位置较固定，可在译码同时读寄存器。
3. **load/store 架构**：只有 load/store 访问数据存储器，EX 算地址、MEM 访存的职责自然分开。

复杂 ISA 的复合寻址、隐式寄存器更新、内存间接访问等会增加阶段工作与控制难度。IA-32 可在内部翻译为较简单的微操作，再由复杂流水线执行，但这同样需要额外硬件。

> [!important] ISA 与实现是相互影响，而非单向决定
> ISA 决定数据通路要支持什么；数据通路、工艺和流水线成本也会反过来影响 ISA 设计。谓词指令、延迟分支等方案都必须结合当时的流水线深度与硬件成本理解，不能把某一种微架构当成 ISA 的永恒属性。

## 8. 结构冒险与数据冒险

### 8.1 三类冒险总览

**冒险**是阻止下一条指令按计划在下一周期开始执行的情况。

| 类型 | 原因 | 典型例子 | 基本对策 |
|---|---|---|---|
| 结构冒险 | 所需硬件资源正被占用 | IF 与 MEM 同时争用一个存储器端口 | 复制/拆分资源，或暂停 |
| 数据冒险 | 后指令需要前指令尚未提供的数据 | `add` 结果立刻被下一条使用 | 前递、暂停、调度 |
| 控制冒险 | 下一 PC 依赖尚未确定的控制流 | 分支方向或目标尚未确定 | 早判决、预测、flush |

它们可能组合出现；停顿能提高正确性，却会增加 CPI。

### 8.2 结构冒险：分离指令与数据存储器

若指令和数据共用一个单端口存储器，某条 load/store 在 MEM 访问数据时，另一条指令的 IF 也要取指，二者无法同周期完成，只能插入气泡。

基础流水线使用分离的指令存储器与数据存储器，或分离的 I-cache/D-cache，从而消除这一特定冲突。寄存器堆在同一周期 WB 写、ID 读，可通过约定前半周期写、后半周期读，使同周期读取得到新值。

### 8.3 前递的基本思想

考察：

```asm
sub x2, x1, x3
and x12, x2, x5
or  x13, x6, x2
add x14, x2, x2
sd  x15, 100(x2)
```

第一条 `sub` 在 EX 末已得到 `x2`，若等 WB 后再让 `and` 读取，会产生不必要停顿。前递（forwarding / bypassing）把 EX/MEM 或 MEM/WB 中已保存的结果直接送到当前 EX 的 ALU 输入 MUX。

![[co-ch4-RK45A20K.png]]

> [!important] 前递改变的是“数据可用时间”
> 结果仍由生产者计算，消费者仍按语义读取同一个值；只是不必等体系结构寄存器写回后再从寄存器堆取得。前递不能产生尚不存在的数据，也不能让时间倒流。

### 8.4 前递检测的完整条件

当前指令在 EX，两个源寄存器编号为 `ID/EX.RegisterRs1/Rs2`。需要检查前两条指令的目的寄存器：

- EX 冒险：`EX/MEM.RegisterRd` 与当前 `Rs1` 或 `Rs2` 相等；
- MEM 冒险：`MEM/WB.RegisterRd` 与当前 `Rs1` 或 `Rs2` 相等。

但**编号相等并不充分**，还必须：

1. 生产者的 `RegWrite` 有效；
2. 生产者的 `RegisterRd != 0`，因为 `x0` 恒为 0；
3. 当前字段确实是该指令使用的源寄存器。

最后一点在简化讲义条件中常被省略：例如 store 的某些字段与立即数字段复用，不能无条件把指令位 `[24:20]` 当成需要前递的 ALU 源。

![[co-ch4-mDBaG3zn.png]]

### 8.5 ForwardA / ForwardB 的选择

| 选择信号 | 编码 | ALU 输入来源 |
|---|---|---|
| `ForwardA/B=00` | 寄存器路径 | ID/EX 保存的寄存器读数 |
| `ForwardA/B=10` | EX/MEM | 上一条指令的 ALU 结果 |
| `ForwardA/B=01` | MEM/WB | 更早指令的内存读数或 ALU 结果 |

![[co-ch4-er4z1aL3.png]]

`ForwardA` 控制第一个 ALU 操作数，`ForwardB` 控制第二个；若第二输入最终来自立即数，仍需结合 `ALUSrc`，不能把所有 B 输入都无条件下一步送进 ALU。

### 8.6 双重数据冒险与优先级

```asm
add x1, x1, x2    # I1
add x1, x1, x3    # I2
add x1, x1, x4    # I3
```

当 I3 在 EX 时，I1 的 MEM/WB 与 I2 的 EX/MEM 都可能匹配 `x1`。程序语义要求使用**最近的 I2**，所以 EX/MEM 优先于 MEM/WB。

```text
EX hazard on rs1:
if EX/MEM.RegWrite
   and EX/MEM.RegisterRd != 0
   and EX/MEM.RegisterRd == ID/EX.RegisterRs1
then ForwardA = 10

MEM hazard on rs1（仅在对应 EX hazard 不成立时）:
if MEM/WB.RegWrite
   and MEM/WB.RegisterRd != 0
   and not (EX/MEM.RegWrite
            and EX/MEM.RegisterRd != 0
            and EX/MEM.RegisterRd == ID/EX.RegisterRs1)
   and MEM/WB.RegisterRd == ID/EX.RegisterRs1
then ForwardA = 01

否则 ForwardA = 00；ForwardB 对 Rs2 使用完全对称的条件。
```

![[co-ch4-A1p7bxI7.png]]

![[co-ch4-jtKJEetu.png]]

> [!warning] “当前 EX 只与前两条有关”需要时序前提
> 本讲约定 WB 与较后指令的 ID 可在同一周期完成先写后读，因此普通 ALU 结果主要检查 EX/MEM 和 MEM/WB 两个来源。若寄存器堆读写时序不同、流水线更深或存在更长延迟部件，就不能照搬“只看前两条”。

## 9. Load-Use 冒险、暂停与指令调度

### 9.1 为什么前递不够

紧邻序列：

```asm
ld  x1, 0(x2)
add x3, x1, x4
```

按周期观察：

| 周期 | `ld` | `add` | 数据是否可用 |
|---:|---|---|---|
| 1 | IF |  |  |
| 2 | ID | IF |  |
| 3 | EX | ID | load 正在算地址，尚未读数据 |
| 4 | MEM | 本应 EX | `add` 在周期初需要 `x1`，load 到 MEM 末才读出 |
| 5 | WB | — | 等 WB 已失去前递的意义 |

`add` 的需求时刻早于 load 数据产生时刻，所以 **forwarding 不能单独解决紧邻 load-use，必须 stall 一个周期**。暂停后，load 完成 MEM，使用者再在下一周期 EX，通过 MEM/WB 前递获得数据。

![[co-ch4-ubBcnr9y.png]]

### 9.2 冒险检测条件

load 已进入 EX，使用它的指令正在 ID，因此比较 `ID/EX` 中的 load 目标与 `IF/ID` 中的使用者源寄存器：

$$\begin{aligned}
&\text{ID/EX.MemRead}\\
\land\;&(\text{ID/EX.RegisterRd}=\text{IF/ID.RegisterRs1}\\
\lor\;&\text{ID/EX.RegisterRd}=\text{IF/ID.RegisterRs2}).
\end{aligned} \tag{4.5}$$

这里 `MemRead` 用来识别 EX 中确实是 load。严谨实现还需排除不写寄存器的情况、排除 `x0`，并只对当前指令真正使用的源字段检测，避免把立即数或目标字段误判为源操作数。

### 9.3 Stall 的两组硬件动作必须区分

检测到 load-use 后，不是简单地“把当前指令变成 nop”一句话带过，而是同时做：

1. **冻结前部**：禁止 PC 更新，禁止 IF/ID 流水线寄存器更新。
   - 使用者的指令仍留在 IF/ID，下一周期重新译码；
   - 更后面的下一条指令仍由 IF 重取，PC 不会丢失。
2. **在后部插入气泡**：把 ID/EX 寄存器中的 EX/MEM/WB **控制值清零**。
   - 本周期原本要进入 EX 的使用者不被放行；
   - 气泡流过时没有寄存器写、内存写或分支等副作用；
   - load 本身继续向 MEM 前进，不受影响。

> [!important] 被重复译码与变成气泡的不是同一个动作
> IF/ID 中保留的是**使用者指令**，等待下一周期再次执行 ID；ID/EX 中被清零的是本周期的控制信息，制造一个 nop 气泡。若只清 ID/EX 而 PC、IF/ID 照常前进，就会丢失使用者；若只冻结 PC/IF/ID 而 ID/EX 照常接收，就可能把使用者提前执行一次。

### 9.4 加入一个气泡后的逐周期图

| 周期 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---:|---|---|---|---|---|---|---|---|
| `ld x1,0(x2)` | IF | ID | EX | MEM | WB |  |  |  |
| `add x3,x1,x4` |  | IF | ID | **stall** | EX | MEM | WB |  |
| `sub x5,x6,x7` |  |  | IF | **stall** | ID | EX | MEM | WB |
| 级间动作 |  |  |  | 清 ID/EX 控制；保持 PC、IF/ID | 使用者重新进入 EX，可前递 |  |  |  |

这里 stall 行表示该指令没有推进，不是多执行一次 EX。三条指令无冒险时需 $3+4=7$ 周期，插入一次停顿后需 8 周期。

![[co-ch4-msWVpgrK.png]]

### 9.5 编译器指令调度

在不改变数据依赖和内存语义的前提下，把无关指令移到 load 与使用者之间，可用真实工作填补延迟槽。

讲义例子计算 `a=b+e; c=b+f`，原始顺序为：

```asm
ld  x1, 0(x0)
ld  x2, 8(x0)
add x3, x1, x2
sd  x3, 24(x0)
ld  x4, 16(x0)
add x5, x1, x4
sd  x5, 32(x0)
```

重排为：

```asm
ld  x1, 0(x0)
ld  x2, 8(x0)
ld  x4, 16(x0)
add x3, x1, x2
sd  x3, 24(x0)
add x5, x1, x4
sd  x5, 32(x0)
```

第三条 load（`ld x4,16(x0)`）被移到第一条 `add x3,x1,x2` 前，为第二条 load（`ld x2,8(x0)`）与使用 `x2` 的 `add` 之间提供一条独立指令；`sd` 又隔在这条 `ld x4` 与使用 `x4` 的 `add x5,x1,x4` 之间。讲义的简化时空图显示，该例由 13 周期降至 11 周期，减少两次停顿。

![[co-ch4-juukFftc.png]]

> [!tip] 调度必须懂目标流水线
> 哪些指令能移动、需要隔多远，取决于部件延迟、前递路径和存储依赖。编译器优化不是任意“换顺序”；尤其不能跨越可能有别名关系的 load/store 随意重排。

## 10. 控制冒险、分支预测与流水线清空

### 10.1 控制冒险从何而来

条件分支需要决定方向和目标。分支尚未判决时，若硬件仍按固定顺序取指，可能已经把错误路径上的指令送入流水线。

简单方案是等分支结果出来再取指，但每遇到分支都停顿成本很高。也可把比较器与目标地址加法器前移：讲义简化实现把结果从 MEM 提前到 ID，以减少分支延迟。

### 10.2 分支判决位置决定惩罚

假设预测顺序执行，而实际分支 taken，在分支后已有若干条年轻指令被取入：

| 分支在何处作出决定 | 典型需清除的已取年轻指令数 | 本讲简化理解 |
|---|---:|---|
| MEM | 3 | IF、ID、EX 中的三条错误路径指令 |
| EX | 2 | IF、ID 中的两条 |
| ID | 1 | IF 中的一条 |

这些是特定五级图下“预测不跳转、实际跳转”的典型惩罚，不是所有处理器的固定常数。分支开销还取决于目标是否已计算、预测器何时提供目标、是否有 delay slot 等。

### 10.3 Flush 不是普通 Stall

- **Stall**：让某些指令原地不动，稍后再继续；目的通常是等待数据或资源。
- **Flush**：把错误路径上年轻指令的控制状态清为无效，使其永远不能产生体系结构副作用；同时把 PC 改到正确路径。

在讲义 taken 分支图中，应 flush 已经取入的后续顺序指令，而不是等待它们正常完成。被清除的是错误路径指令，分支本身和更老指令继续执行。

![[co-ch4-lcqgxCgf.png]]

### 10.4 静态与动态预测

**静态预测**不根据运行时历史逐条调整，例如：

- 总是预测 not taken，直接顺序取指；
- 根据典型行为，向后分支预测 taken（常为循环），向前分支预测 not taken。

**动态预测**由硬件记录分支历史，并假设近期趋势会延续：

1. 用分支指令地址的若干位索引分支预测缓冲 / 分支历史表；
2. 读取预测方向，从 fall-through 或预测目标继续取指；
3. 分支真正判决后，若预测错误则 flush 并更新历史。

预测只在正确时避免等待；它不改变程序语义，也不会消除真实分支依赖。

### 10.5 1 位与 2 位预测器

**1 位预测器**记录上次方向，并直接预测相同方向。嵌套循环的内层分支可能每次外层循环错两次：

- 内层最后一次退出循环，历史仍是 taken，错一次；
- 下次进入内层，历史已是 not taken，第一次迭代又错一次。

**2 位饱和计数器**有四个状态，通常只有连续两次误判才从强 taken 转向预测 not taken，或反向翻转。一次反常退出不会立刻完全改变长期方向，因此更适合循环。

### 10.6 方向预测正确仍可能有目标惩罚

即使知道分支会 taken，仍须知道**跳到哪里**。若目标地址尚未算出，taken 分支仍可能停顿一个周期。

**分支目标缓冲（BTB）**在取指时按 PC 索引并缓存目标地址；命中且预测 taken 时，可较早从目标地址取指。方向预测与目标预测是两项不同工作。

### 10.7 数值例：把分支损失折算成 CPI

> [!note] 例 4.C：预测错误对性能的影响
> 某五级流水线的理想 CPI 为 1。动态执行指令中条件分支占 $20\%$，预测准确率为 $90\%$，每次误判损失 3 个周期。另有 $5\%$ 的 load 造成一次无法被调度消除的 load-use 停顿。求实际 CPI；若 $T_c=500$ ps、$IC=2\times10^8$，求 CPU 时间。

每条分支的期望额外周期为 $0.10\times3=0.3$，所以分支带来的平均增量为

$$\Delta CPI_{\text{branch}}=0.20\times0.10\times3=0.06.$$

load-use 带来的平均增量为

$$\Delta CPI_{\text{load}}=0.05\times1=0.05.$$

于是

$$CPI_{\text{actual}}=1+0.06+0.05=1.11,$$

$$T=2\times10^8\times1.11\times500\text{ ps}=0.111\text{ s}.$$

若只计算理想 CPI=1，会得到 0.100 s；约 11% 的额外周期来自两类冒险。该例假设两类损失独立且可直接相加，若题目说明停顿重叠，应按具体时空图计数。

## 11. 多发射、动态调度与推测执行

### 11.1 从更深流水到多发射

提高指令级并行（ILP）有两条路线：

- **加深流水线**：每级做更少工作，缩短时钟周期；
- **多发射（multiple issue）**：复制功能部件和通路，每周期开始多条指令。

多发射时 $CPI$ 可小于 1，因此常用 $IPC=1/CPI$。例如 4 GHz、4 发射处理器的峰值为

$$4\times10^9\times4=16\times10^9\text{ instructions/s},$$

即 16 BIPS，峰值 $IPC=4$、$CPI=0.25$。真实相关性与资源冲突会使它低于峰值。

### 11.2 静态多发射与动态多发射

| 特性 | 静态多发射 | 动态多发射 |
|---|---|---|
| 谁选择同周期指令 | 编译器 | CPU 硬件 |
| 组织形式 | 指令打包到 issue slots / packets | 每周期检查指令流并选择发射 0、1、2…条 |
| 冒险处理 | 编译器尽量避免，必要时填 nop | 硬件运行时检测并解决 |
| 编译器作用 | 必须了解具体流水线规则 | 仍可重排帮助硬件，但不承担全部正确性 |
| 代表概念 | VLIW、静态双发射 | 超标量、动态调度 |

静态发射包可看作一条包含多个并行操作的超长指令。包内通常不能有不能被硬件及时满足的依赖；不同 ISA 对包间依赖的约束也可能不同。

### 11.3 静态双发射 RISC-V

讲义的示例每周期有两个槽：

- 一个 ALU/branch 指令；
- 一个 load/store 指令；
- 两条按 64 位对齐组成发射包；
- 空槽填 nop。

更多并行也带来新限制：

- 单发射中靠 EX 前递可消除的部分冒险，在同一发射包内不一定来得及前递；
- `add x10,x0,x1` 与同包 `ld x2,0(x10)` 不能直接用新 ALU 结果算地址，须拆到不同包；
- load-use 仍有一个周期的使用延迟，但现在会影响同包和后续两条指令，需要更积极调度。

### 11.4 静态调度与循环展开例

原循环体为：

```asm
Loop: ld   x31, 0(x20)
      add  x31, x31, x21
      sd   x31, 0(x20)
      addi x20, x20, -8
      blt  x22, x20, Loop
```

讲义的双发射调度为：

| 周期 | ALU/branch 槽 | load/store 槽 |
|---:|---|---|
| 1 | `nop` | `ld x31,0(x20)` |
| 2 | `addi x20,x20,-8` | `nop` |
| 3 | `add x31,x31,x21` | `nop` |
| 4 | `blt x22,x20,Loop` | `sd x31,8(x20)` |

实际 5 条指令用 4 周期，$IPC=5/4=1.25$，低于峰值 2。`sd` 地址使用 `8(x20)`，是为了抵消此前 `addi` 已将指针减 8 的影响。

**循环展开**复制多个迭代体、减少循环控制，并给不同复制体使用不同寄存器，以暴露更多 ILP。讲义展开后 14 条实际指令用 8 周期：

$$IPC=\frac{14}{8}=1.75.$$

代价是更多寄存器和更大代码体积；编译器中的“寄存器重命名”在此指给复制体换用不同寄存器名，消除由复用名字造成的假相关。

### 11.5 动态多发射与乱序执行

动态多发射处理器称**超标量（superscalar）**，由 CPU 每周期决定可发射多少条，并在运行时避免结构与数据冒险。编译器调度仍有帮助，但硬件负责维持 ISA 语义。

动态调度允许指令**乱序开始/完成执行**，以避免无关指令被一条停顿阻塞：

```asm
ld   x31, 20(x21)
add  x1, x31, x2    # 等待 load
sub  x23, x23, x3   # 与上面无关，可以先执行
andi x5, x23, 20
```

但“乱序执行”不等于可以任意改变程序可见状态。讲义强调结果对寄存器的**提交仍按序进行**，以便维护依赖、异常与精确状态。

### 11.6 保留站、ROB 与寄存器重命名

动态调度数据通路中的主要结构：

- **保留站（reservation stations）**：保存待执行操作及其操作数；操作数未就绪时等待功能单元广播。
- **重排序缓冲（reorder buffer, ROB）**：按程序顺序记录未完成指令及其结果，提供操作数并最终按序提交。
- **功能单元与结果总线**：执行操作，并把结果送给等待它的保留站及 ROB。

寄存器重命名的核心是把“体系结构寄存器名”映射到具体物理值或 ROB/保留站项：

- 若源操作数已在寄存器堆或 ROB 可用，发射时复制到保留站；
- 若尚未产生，保留站记录生产者，等待功能单元提供；
- 后续指令写同一个体系结构寄存器，不会覆盖旧消费者已经保存或已绑定的值。

这样可消除因寄存器名复用产生的**反相关与输出相关（名字相关）**，但不能消除程序真正传递值的数据相关。

### 11.7 推测执行

推测是“先猜、尽早执行、再验证”：

- 分支结果未知时预测方向并继续取指、发射；
- 对 load 推测有效地址、值，或在前序 store 尚未完全确定时提前加载，并处理 store-to-load 前递；
- 若猜测正确，保留结果并继续；
- 若猜测错误，丢弃缓冲中的错误路径结果，回滚到正确状态。

静态多发射也可由编译器移动指令并加入修复代码；动态多发射通常由硬件缓冲结果，在推测尚未确认前**不提交**。

> [!important] 乱序、重命名、推测不是同义词
> 乱序允许无关指令绕过停顿；重命名消除寄存器名字造成的假相关；推测在未知条件下先执行。现代高性能处理器常组合使用三者，但每一项解决的问题不同。

### 11.8 为什么不能完全交给编译器

动态硬件仍有必要，因为：

- cache miss 等停顿难以在编译时准确预测；
- 分支方向运行时才知道，静态调度不能总是绕过；
- 同一 ISA 的不同实现具有不同延迟和冒险，静态最优调度未必通用。

多发射的实际收益受真实数据依赖、指针别名、有限指令窗口、存储延迟和带宽限制。调度与推测硬件还会增加面积、复杂度与功耗，可能不如多个较简单核心划算。

## 12. Cortex-A53、Core i7 与设计边界

### 12.1 讲义中的两种实现

| 指标 | ARM Cortex-A53 | Intel Core i7 920 |
|---|---:|---:|
| 目标市场 | 个人移动设备 | 服务器、云计算 |
| 热设计功耗（讲义口径） | 单核 1 GHz 约 100 mW | 130 W |
| 时钟频率 | 1.5 GHz | 2.66 GHz |
| 每芯片核心数 | 4（可配置） | 4 |
| 多发射 | 动态多发射 | 动态多发射 |
| 峰值 IPC | 2 | 4 |
| 流水线级数 | 8 | 14 |
| 调度方式 | 静态、顺序流水线调度 | 动态乱序并推测执行 |
| 分支预测 | Hybrid | 2-level |
| 每核 L1 | 16–64 KiB I + 16–64 KiB D | 32 KiB I + 32 KiB D |
| 每核 L2 | 128–2048 KiB | 256 KiB |
| 共享 L3 | 取决于平台 | 2–8 MiB |

A53 的“多发射由硬件动态决定每周期能否发出”与“按程序顺序调度”并不矛盾；i7 则进一步允许乱序执行与推测。两者展示的是同一 ISA/性能目标下不同的功耗、面积和 ILP 取舍，而不是“级数越多必然越快”。

### 12.2 功耗墙与设计演化

讲义的历史例子显示，从单发射到多发射，再到深流水、乱序与推测，性能提高伴随功耗显著增加。高复杂度并不总是最佳：多个简单核心有时比单个极复杂核心更节能。

理解这些表格应抓住：

- 发射宽度决定峰值，不决定实际 IPC；
- 更深流水线可能缩短周期，却增加寄存器开销和分支惩罚；
- 乱序窗口、保留站、ROB、预测器都消耗硬件资源与能量；
- 存储系统能否供数，决定复杂核心能否持续满载。

### 12.3 矩阵乘法例的意义

讲义最后用展开并向量化的矩阵乘法展示软件如何配合硬件：使用向量寄存器、加载多个元素、广播一个操作数、并行乘加，再通过循环展开提供可调度指令。

这里不要求背整段 x86 汇编，重点是理解：**编译器、指令集与微架构共同决定实际 ILP**；仅有 4 发射硬件，并不能自动把任意程序变成 IPC=4。

### 12.4 常见谬误与陷阱

> [!warning] 三个常见误区
> 1. **“流水线很容易。”**基本重叠思想容易，冒险检测、前递优先级、控制恢复和精确状态才是难点。
> 2. **“流水线与技术无关。”**更多晶体管让复杂调度与预测可行，但功耗又限制过度复杂化。
> 3. **“ISA 与流水线无关。”**复杂寻址、隐式副作用、变长指令都会影响流水实现；特定流水线设计也会反过来影响 ISA 选择。

## 13. 异常简述

异常或中断可能要求处理器在某条指令处暂停正常控制流、保存原因与位置，并转入处理程序。在简单顺序流水线中，需要关注：

- 哪条指令被视为发生异常；
- 异常之前的指令是否已完成；
- 异常指令及更年轻指令的副作用是否已取消；
- PC 与流水线寄存器如何恢复。

在乱序或推测执行中，错误路径上的 load 可能产生异常，但它最终根本不应提交。动态实现可暂存异常，直到该指令成为最老、准备提交时再处理；若预测被撤销，异常也随之丢弃。静态推测则可能需要 ISA 提供延迟异常等支持。

这引出**精确异常**：处理时能够给出与某种顺序执行一致的清晰机器状态，避免年轻或错误路径指令留下不应有的体系结构副作用。ROB 的按序提交与推测结果的暂存，正是支持这一性质的重要机制。

详见 [[06 异常、中断与特权级]]；本篇只建立它与流水线 flush、ROB 和推测执行的联系。

## 14. 我的理解与思考

> [!note] 个人归纳
> 本节是我基于讲义整理的解释框架与辨析，不是讲义逐字结论。它用于帮助记忆和迁移，具体数值仍以题目给定的微架构为准。

### 14.1 周期、CPI、IC 是同一个三角形的三条边

我习惯把所有优化先放到

$$T=IC\times CPI\times T_c$$

里定位：流水线主要压低 $T_c$ 并提高吞吐，停顿和预测失败抬高 CPI；循环展开常降低循环控制的动态 IC，却可能增加代码大小并影响取指；VLIW 把调度和 nop 显式编码，可能改善 CPI，也可能增大程序体积。

真正困难之处在于三项会互相牵制。加深流水线看似降低 $T_c$，却可能增加分支误判损失，从而抬高 CPI；激进预取或推测若让程序执行更多无用工作，也会增加实际能耗。任何“只缩短周期”“只降低 CPI”的论述都不是完整性能证明。

### 14.2 Forwarding 是数据可用时间的前移

我把寄存器写回看成一个值最晚、最标准的可见时刻，把 ALU 输出、EX/MEM、MEM/WB 看作这个值在数据通路中更早的副本。前递是在消费者需要它之前，选择**已经存在且足够新的副本**。

所以前递有两个自然边界：

1. 结果尚未产生时无法前递，load-use 就是典型例子；
2. 多个副本同时匹配时必须选最新生产者，所以 EX/MEM 优先于 MEM/WB。

这也解释了为什么前递条件同时需要编号匹配、RegWrite、非 `x0` 和源字段有效：它们共同回答“这条线送来的值，是否真的是消费者按 ISA 应该看到的值”。

### 14.3 Stall 与 Flush 对应“等待”和“撤销”

Stall 不改变控制流的正确性，只推迟年轻指令，因此 PC/IF/ID 保持、ID/EX 控制清零必须配合。Flush 则撤销本不应执行的年轻指令，必须阻止它们所有后续副作用，并修复 PC。

我由此把 hazard handling 理解成两种时间操作：**stall 推迟时间，flush 撤销历史，forwarding 提前提供值。**三者不能互相替代。

### 14.4 精确异常与推测执行通过“提交点”联系起来

推测允许处理器先执行，但体系结构状态不能在猜测未证实时就永久改变。ROB 等结构把“已经算出结果”和“允许程序观察到结果”分开：前者可乱序、可推测，后者按程序顺序提交。

这个提交点也天然服务精确异常。若异常在按序提交时才被确认，就能保证更老指令已提交、年轻与错误路径指令未提交；若异常来自被取消的推测路径，则根本不应触发可见处理。于是，乱序带来的性能与顺序 ISA 的语义并不冲突，关键在于把执行顺序和提交顺序分开。

### 14.5 多发射的瓶颈从“每周期一条”转向“窗口里有多少可用工作”

单发射五级流水线的理想上限是 IPC=1，多发射只是把上限提高。真正限制变成：指令窗口是否足够大、依赖能否被重命名消除、分支能否准确预测、存储器能否及时供数。

这也说明编译器与硬件不是替代关系：编译器负责把独立工作暴露出来，硬件利用运行时信息抓住编译期看不到的机会；二者都需要，但都要付出成本。

## 15. 考点速查

1. **性能公式**：$T=IC\times CPI\times T_c$；IC 看 ISA/编译器，CPI 与周期看实现，但三者会相互影响。
2. **单周期**：CPI=1 不等于快，周期必须容纳最慢指令；本讲 load 关键路径为 800 ps。
3. **五阶段不是五项副作用**：store 无 WB，R 型无 MEM，beq 不写数据寄存器；它们只是在统一通路中流动。
4. **基本数据通路**：PC/IM/寄存器堆/ALU/DM，加 Imm Gen、目标地址加法器与 MUX；多个来源不能直接接线。
5. **指令路径**：R 型读两寄存器并写 ALU 结果；load 算地址、读内存、写回；store 写内存无写回；beq 比较并选 PC；jal 写 `PC+4` 并跳转。
6. **立即数**：I/S/B/J 字段位置不同；B/J 偏移按半字编码，末位补 0，不可都按 I 型处理。
7. **二级控制**：opcode 经主控制生成类别信号与 ALUOp；ALUOp 再与 funct3/funct7 生成具体 ALU 操作。
8. **流水线收益**：提高吞吐，不降低单条延迟；理想 $n$ 条指令 $n+4$ 周期，平均 CPI 渐近 1。
9. **级间寄存器**：IF/ID、ID/EX、EX/MEM、MEM/WB 同时保存数据、寄存器编号和后续控制；load 的 `rd` 必须传到 WB。
10. **三类冒险**：资源争用是结构，值未就绪是数据，下一 PC 未定是控制；解决手段分别是资源/停顿、前递/停顿/调度、预测/早判决/flush。
11. **前递编码**：00 用 ID/EX，10 用 EX/MEM，01 用 MEM/WB；条件包括 RegWrite、Rd≠0、寄存器匹配及真实源字段。
12. **前递优先级**：EX/MEM 比 MEM/WB 新，双重匹配必须选 EX/MEM。
13. **Load-use**：使用者需要数据早于 load MEM 末产出，前递不够，至少 stall 1 周期；调度可填入无关工作。
14. **Stall 控制**：保持 PC 与 IF/ID，同时清 ID/EX 控制；前者保留使用者与后续取指位置，后者制造无副作用的气泡。
15. **Flush 控制**：预测错误时清除错误路径年轻指令并恢复 PC；不是让它们停顿后继续错误执行。
16. **分支惩罚**：本讲典型 MEM/EX/ID 判决对应 3/2/1 条年轻指令需处理，但须结合预测方向、目标计算与题目图示。
17. **预测器**：1 位在嵌套内层循环常见双误；2 位需连续误判才翻转预测趋势；BTB 缓存目标而非只预测方向。
18. **CPI 计算**：基础 1 + load-use 比例×停顿 + 分支比例×误判率×惩罚；例题结果 1.11，CPU 时间 0.111 s。
19. **多发射**：CPI 可小于 1，常用 IPC；4 GHz 四发射峰值 16 BIPS，但相关性和资源限制实际值。
20. **静态多发射**：编译器组包、填 nop，须了解目标延迟；双发射示例 IPC=1.25，展开后 1.75，代价是寄存器与代码体积。
21. **动态调度**：可乱序执行，但 ROB 按序提交；保留站等待操作数，寄存器重命名消除名字相关而非真相关。
22. **推测执行**：先执行、后验证、错误则回滚；分支与 load 都可推测，未确认前不能提交体系结构状态。
23. **A53 vs i7**：顺序双发射、8 级与较低功耗，对比 4 发射、14 级、乱序推测与更高功耗；峰值和级数都不等于实际性能。
24. **异常与推测**：错误路径异常不应提交；ROB 暂存结果与异常并按序提交，以支持精确异常，详见 [[06 异常、中断与特权级]]。
25. **ISA 与流水线相互影响**：定长、规整、load/store ISA 易流水；复杂 ISA 可用微操作实现，但需更多硬件；没有脱离技术条件的“最佳级数”。
